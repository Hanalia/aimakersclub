## *리볼루트가 자체 호스팅 오픈 모델로 AI 코딩 비용을 90% 절감한 방법* 핵심 요약

- 본 발표자는 리볼루트(유럽 최대 디지털 은행, 고객 8,000만 명)의 AI 운영 책임자 데이비드로, 고성능 AI 엔지니어링 및 오픈소스 기반 자체 호스팅 대형 언어 모델 사용 경험을 다룸
- 리볼루트는 2023년 1월 Gemini 기반 AI 코딩 도입 후 코드 작성 시간 20%, 기능 구현 시간 10% 단축을 달성
- 상용 클라우드 AI 서비스(예: Cloud Code, Anthropic, OpenAI)는 초기에는 혁신적이었으나, 월수천~1만 달러 단위의 높은 비용과 ROI 한계로 인해 예산을 엄격히 관리할 필요성을 느낌
- 오픈소스 LLM(GLM 51/53) 자체 호스팅 도입 후, 코드 작성 시간 60%, 기능 구현 시간 70% 단축이라는 압도적 생산성 개선 달성(2024년 4월~)
- 2,000명 엔지니어를 위해 GPU 56대(B200)만으로 800억 파라미터 모델 운영, 1회 토큰비용은 100만 개당 30센트, 비용은 상용 대비 1/10
- 동시 요구건수, 응답속도(최초 토큰 생성 1.6초), 캐시 적중률, 양자화 활용(FP4, VFP4 권장) 등 인프라 최적화로 성능 및 비용 극대화
- 엔지니어는 AI 할당량 걱정 없이 무제한 코드생성 사용, 업무 병렬화 및 개발 문화의 근본적 변화 유도
- 데이터 보안, EU 규제 준수(사람 개입 필수, 샌드박스 환경 운영), 프롬프트 인젝션, 국가별 데이터 위치, 로깅 시스템 등 운영 우려사항에 대한 기술적 대응책도 상세히 논의

## 세부 요약 - 주제별 정리

### 리볼루트는 유럽 최대 디지털 은행으로 혁신적 엔지니어 문화와 제품 다변화를 추구함

- 리볼루트는 8,000만 명 이상의 고객과 45개 시장에서 활동하며, 2023년 기준 유럽에서 가장 많은 다운로드를 기록한 금융 앱 보유
- 2023년 7월 이후 유럽 최대의 비상장 기업 위치 달성
- 신속한 제품 출시, 엔지니어링 문화와 기술 탁월성 중시
- 다양한 디지털 금융 서비스를 빠르게 실험·런칭하는 것이 기업 경쟁력의 핵심임

### AI 도입 이전의 개발 프로세스는 Stack Overflow·문서참조에 많은 시간을 소비했으며, 변화가 필요했음

- AI 도입 전, 기능 선택 후 실제 배포까지 수일~수주 소요
- 코드 작성 시간(파란색), 기능 전체 구현 및 배포 시간(녹색)으로 나눠 관리
- Stack Overflow 혹은 각종 개발 문서 검색에 긴 시간 소요
- 엔지니어 효율성 개선이 시급한 과제로 부상

### Gemini 및 Cloud Code 등 상용 AI 도입은 생산성에 도움을 줬으나, 비용·ROI 면에서 한계가 명확했음

- 2023년 1월 Gemini 도입, 자체 데이터 사용 AI 환경 구축
- 코드 작성 시간 20% ↓, 기능 구현 시간 10% ↓ 등 안정적 성과 기록
- 2023년 2월 Cloud Code 도입했으나, 초기엔 별다른 성과는 미비(실질적 속도 개선 미흡)
- 그러나 Anthropic, OpenAI, Cloud Code 사용시 엔지니어 1명당 월 1,000~만 달러 단위 비용 부담 발생
- ROI에 의문, 사용량 제한 및 예산 관리 필요성을 절감

### 오픈소스 LLM(GLM) 자체 호스팅 도입 후, 생산성은 폭발적으로 향상되고 비용은 90% 이상 절감됨

- 2024년 4월, 자체 호스팅 GLM(주로 GLM 51/53) 도입
- 코드 작성 시간 60% 절감, 기능 구현 배포 시간 70% 절감 등 괄목할만한 성과
- 엔지니어들이 코드 생성에 ‘쓸모없는 징크’ 없이 자유롭게 AI 활용 가능(토큰 제한X)
- Stack Overflow, Jira, Confluence 읽기 등 반복적 업무→AI가 처리, 병목 구간이 코드작성보다 ‘기능 전체 구현’임을 데이터로 입증

### GPU 인프라 설계·운영 최적화로 수천 명 엔지니어에게 대규모 LLM 서빙이 가능해짐

- B200 GPU 56대로 800억 파라미터 GLM 호스팅(최신 GLM 53 기준)
- 엔지니어 2,000명 대상, 최초 토큰 응답 속도 1.6초, 동시 200 TPS(초당토큰수) 지원
- GPU 사용률, 요청량, 병렬성 고려해 ‘오후 5시 이후’ GPU 사용량이 낮아지는 시간대에는 800 TPS도 가능
- 응답속도 5초 이상되면 엔지니어 불만 폭증(영향 임계선), 제품성/생산성 저하로 인식

### 연간 운영비 1/10 실현…오픈 모델 자체 호스팅의 경제성·예측 가능성이 높은 것으로 판명됨

- 오픈소스 GLM 자체 호스팅 시, 토큰 100만 개 당 0.3달러(30센트) 비용
- Anthropic·OpenAI 등 상용 서비스 대비 약 1/10
- 고정비에 가까워, 비용 예측 및 예산 통제가 가능
- 프랑스 법인 등 특별 예외 케이스 제외, 전체적으로 오픈모델 우선 전략 구사

### 성능 개선의 핵심은 양자화, 캐싱, 병렬처리, 컨텍스트 최적화 등 엔지니어링 조합에 있음

- 높은 컨텍스트 창(예: 백만 토큰)의 실제 활용성은 과대평가, 대부분 256K 토큰이면 충분
- GPU의 Q화: FP4, VFP4(노란색 칩일 경우) 양자화, FP4→FP8 전환시 40% 이상 GPU 메모리 절감
- GLM은 TP4 최적화 되어있으나, 작업 많은 경우 TP8도 적합(캐시 KV 메모리 한계 때문)
- 캐시 히트율 90% 이상 필요, 디코딩·시퀀스 프리패킹·PGD Zag 등 성능최적화 기법 다각도 적용

### 텍스트 전용 GLM의 한계(비전/이미지 미지원)는 멀티모달 프록시 or 조합모델로 해결 가능함

- GLM 자체 모델은 텍스트 생성·코딩 특화
- 이미지/비전 태스크 필요시, API 레벨에서 OpenAI Gemini·Luna 등으로 프록시 처리
- “UI 디자이너가 Gemini 5G Flash로 프론트엔드 작업부서의 생산성을 비약적으로 개선한 사례” 등 구체적 적용사례도 제시

### API 호환성 및 내부 PaaS화로 엔지니어링 진입장벽 없이 유연한 활용이 가능하도록 구축됨

- OpenAI API(특히 completion, response EndPoint)와 100% 호환 구조로 래핑
- Open Codex, Cloud Codex 등 내부 툴에서 자유롭게 호출
- 내부 배포·운영, 보안·규정충족 등 대규모 조직 내 실용적 도입 사례로 설명

### 데이터 보호, 컴플라이언스, 프롬프트 인젝션 등 보안·운영 이슈는 샌드박스·로깅 등 기술로 해결함

- EU·영국·미국·이스라엘 등 데이터 주권 국가 내에만 위치(데이터 이동 문제 없음)
- 오픈소스 중국 모델 활용시 "추론 엔드포인트가 아닌, 단순 가중치 다운로드"라 정보유출 논란 차단
- 모든 AI 코딩 작업은 ‘사람의 승인·개입’이 반드시 반영되는 구조(자율적 agent化 방지)
- 개발용 샌드박스에 승인 규칙 적용(특정 오퍼레이션 차단 like Gradle 등)
- 프롬프트 인젝션 위협은 모델 스마트화에 따라 감소, 그러나 대비책은 유지 필요
- 고성능 로깅·메트릭 시스템 구축, 장애·이상 발생시 신속한 추적 및 분석 가능

### 오픈모델, 자체 호스팅이 엔지니어링 문화와 조직 역량을 근본적으로 변화시켰음을 수치와 사례로 입증함

- AI 적극 활용으로 엔지니어가 실험·개발에 주도적으로 참여, 생산성 및 제품 출시 가속
- 무제한 AI 활용 환경 제공(토큰 비용 부담 해결) → 혁신적 업무 프로세스 설계가 가능해짐
- 단순 코드 작성뿐 아니라, 기능 전주기 개발/협업 문화 전반에 파급
- 초기 도입과정에서 상용 솔루션과 자체호스팅 각각의 장단점을 경험적으로 비교 분석
- 강도 높은 규정 준수·보안 정책 하에서도 대규모 운용이 가능함을 입증
