## *AI 에이전트가 직접 하니스 엔지니어링을 수행하도록 하는 방법* 핵심 요약

- 영상에서는 코딩용 AI 에이전트에서 성공적으로 적용한 하니스 엔지니어링 기법이 실제 비즈니스 자동화 AI 에이전트에도 효과적으로 확장된다고 설명함
- 하니스 엔지니어링이란 에이전트가 실제 서비스 환경에서 발생하는 오류와 실수를 추적하고, 그 데이터를 기반으로 규칙과 워크플로우를 점진적으로 개선하는 체계를 의미
- 최신 하니스 구조에서는 규칙, 스킬, 서브 에이전트, 가드레일, 메모리 등이 마크다운(markdown) 기반 문서로 유연하게 설계되어, 에이전트를 손쉽게 조정 및 개선 가능
- 영상에서는 Langchain 플랫폼의 Managed Deep Agents와 Langsmith의 트레이싱, 메트릭, 개선 제안 기능이 하니스 엔지니어링과 실시간 에이전트 개선에 어떻게 적용되는지 구체적으로 시연
- 과거에는 파이썬, 타입스크립트 등에서 코드로 각 기능을 일일이 구현해야 했으나, 지금은 30줄 내외의 코드와 몇 개의 문서만으로 에이전트 구조를 단순하게 정의할 수 있게 됨
- 핵심 개선 루프는 생산 환경에서 에이전트가 실시간으로 교훈을 학습하는 "메모리 루프"와, 운영 데이터(트레이스)를 바탕으로 워크플로우와 지침(instructions)을 업데이트하는 "하니스 개선 루프"로 구성
- 실제 고객 질문 사례(14건)에서, 처음에는 4건만 정확히 답변하던 에이전트가 위 두 개선 루프를 거치며 13/14건까지 정확도를 끌어올림
- 최종적으로, 에이전트의 자율적인 하니스 엔지니어링이 가능하되, 관리자가 변경 사항을 승인하는 “인간-에이전트 협업” 구조가 중요함을 강조

## 세부 요약 - 주제별 정리

### 신경망 기반 AI 에이전트의 생산환경 적용에는 코딩 에이전트와 동일한 하니스 전략이 효과적임

- 발표자는 올 한 해 동안 주로 코딩 에이전트에 집중했으나, 동일한 하니스 엔지니어링 전략이 비즈니스 자동화, 프로덕션 에이전트에도 효과적임을 강조
- "하니스 엔지니어링" 개념은 단순히 모델 자체가 아니라, 모델을 둘러싼 규칙, 워크플로우 등이 장기적으로 발전하는 과정을 포괄함
- 코딩 에이전트와 프로덕션 AI 에이전트 모두에서, 에이전트가 실제 사용 중 발생한 실수(에러, 실패)를 사후적으로 분석해 근본 규칙 및 기능을 보강하는 피드백 루프가 중요

### 최신 하니스 구조는 마크다운 기반 설계를 통해 코드 중심 방식에 비해 압도적으로 유연해짐

- 이전에는 각종 연동 도구, 시스템 프롬프트, 가드레일 등을 파이썬이나 타입스크립트 코드로 구현해야 했음
- 현재는 규칙(system prompt), 스킬(workflow), 서브에이전트(멀티에이전트 위임), 도구, 가드레일 등 모두 마크다운 문서(mmd 등)로 정의 가능
- 에이전트 정의는 30줄의 agent.py와 몇 개의 문서만으로 완성 가능
- instructions.mmd, skills 폴더 등으로 디렉토리 구조가 간소화되어 유지보수가 용이
- 코드와 마크다운이 결합해 일부 "배관(plumbing)" 작업만 남고, 주 구성요소는 자동으로 감지/연동됨

### Langchain Managed Deep Agents와 Langmith의 트레이스, 메트릭이 하니스 엔지니어링의 핵심 지원 도구로 등장

- Langchain Managed Deep Agents 플랫폼은 AI 에이전트의 배포, 하니스 구성, 관리에 핵심 역할
- Langmith는 실시간 트레이싱, 대화 이벤트 기록, 성능 평가 및 자동 개선 제안 기능 제공
- 트레이스 데이터와 개선 제안(프로퍼즈드 픽스)이 하니스 주기적 개선의 기반이 됨
- 영상 제작자가 Langchain 플랫폼을 장기적으로 사용해 온 이유, 제품의 진화 과정 사례 언급

### 첫 번째 핵심 루프: 에이전트가 생산환경에서 실시간으로 교훈을 메모리에 축적함

- 에이전트가 실시간 고객 대화에서 확실치 않은 이슈/에러를 인식하면 관리자에게 즉시 에스컬레이션
- 관리자(또는 인간 팀)는 올바른 답변이나 수정을 제공, 에이전트는 이를 ‘레슨’ 등으로 저장
- 이러한 ‘교훈’들은 ‘컨텍스트 허브’(context hub)에 집적되며, 사용자별/글로벌 메모리로 구분 저장
- 다음 유사사례 발생 시, 에이전트가 확실한 답변을 내릴 수 있도록 기억을 활용
- 실제 예시: helpdesk용 에이전트가 Nina, Omar 등 각기 다른 사용자의 질문을 받고, 에스컬레이션-수정-학습 과정을 거쳐 점진적으로 정확도 향상
- per-user memory, core memory 등으로 에이전트의 안전성과 프라이버시 보장

### 두 번째 핵심 루프: 트레이스 데이터 기반 하니스(지침·워크플로우) 자동 개선이 가능해짐

- Langchain의 ‘Managed Deep Agents’와 ‘Langmith’ 엔진은 트레이스 데이터를 모니터링해 에러, 실패, 사용자 혼란 등을 포착
- 각 실패 케이스의 구체적 증거, 대화 흐름을 분석해 시스템 문서(instructions.mmd 등)의 수정 제안을 자동 생성
- 관리자는 제안된 수정(프로포즈드 픽스)을 대시보드에서 클릭 한 번으로 승인/적용할 수 있음(자동화+통제)
- 모든 수정/학습 이력은 커밋 단위로 관리되어, 필요 시 롤백 및 버전 관리를 유연하게 할 수 있음
- 제품 배포와 동일한 방식으로 슬랙(Slack) 등 외부 환경에도 손쉽게 연동 가능

### 실제 사례를 통한 자가개선 하니스의 효과 입증

- 영상 내 모의 데이터셋: 14개 질문을 가진 helpdesk 에이전트 평가
- 초기 상태: 14문제 중 4문항만 정답
- 하니스 엔지니어링 루프 적용 후: 13/14문항에 대해 올바른 답변 제공
- 모델(Langchain/Langsmith 기반 LLM)은 완전무결하진 않으나, 반복 개선을 통해 실제 현업 수준 정확도까지 도달 가능함을 시연

### 하니스 엔지니어링의 지속성, 통제 및 협업 구조가 실전 운영에서 특히 중요함

- 하니스 엔지니어링은 1회성 작업이 아니라, 운영 단계에서 지속적으로 이루어져야 함
- 관리자는 에이전트의 개선 제안·적용 과정을 최종 승인하며 전체 운용 방향을 통제
- 수정 이력 관리, 롤백, 버전 관리 등 SW 개발의 '풀 리퀘스트'와 유사한 협업 프로세스가 필수
- 아무리 자동화가 진행돼도, 최종 의사결정과 검증은 전문가(인간)가 개입해야 안전하고, 방향성을 잃지 않음

### 중요한 설정 및 활용 팁: 플랫폼 자율구축과 상용플랫폼 사용의 선택지

- 사용자는 직접 하니스 파이프라인/플랫폼을 구축하거나, Langchain Managed Deep Agents 등 상용 플랫폼을 활용할 수 있음
- 상용 플랫폼은 배포, 개선, 트레이스, 승인 대시보드 등을 체계적으로 제공해 실무상의 부담 크게 경감

### 소프트웨어 진화 방식의 코드 에이전트 전략을 프로덕션 AI에도 성공적으로 적용함

- 코딩 에이전트의 하니스 개선 루프(시스템 에볼루션) 구조가 비즈니스 자동화 AI 에이전트에서도 그대로 확장 운용 가능함을 실증
- 실제 프롬프트/문서/스킬 업데이트, 승인-적용 프로세스 등은 IT 개발 현장의 워크플로우와 유사

### 에이전트의 기억 및 교훈은 사용자별, 전역별로 관리되며 개인정보 보호 및 맥락 적합성을 확보함

- 모든 학습된 기억(lesson)은 per-user와 글로벌 메모리로 엄격히 구분되어 안전하게 보관
- 각 사용자는 타인 케이스에 대해 접근 불가, guardrail(접근제어 규칙)로 프라이버시와 데이터 보안을 강화
- 상황맥락 정보가 개인화되어, 한 사용자의 고유 이슈와 기억이 정확히 반영

### 영상 제작자는 Langchain, Langsmith와의 경험·협업을 통해 완성도 높은 데모와 실전 적용 노하우를 제공함

- 영상 말미에서 Langchain, Langmith의 파트너십, 크레딧(Code: colem) 등 구체적 참여 정보 언급
- 본 영상 포함 과거 첫 영상(2년 전)부터 일관되게 Langchain 플랫폼을 사용해 실전성과, 커뮤니티 피드백을 모두 경험
- 에이전트 운용의 성공사례와 실질적인 플랫폼 활용 노하우를 제공

### 결론적으로, 하니스 엔지니어링은 운영 과정에서 인간과 AI 에이전트가 협업하며 실시간 자기개선을 실현하는 핵심 기술임

- 에이전트의 자가 학습, 운영 환경 트레이스 자료의 실시간 적용, 관리자의 승인-통제 환경 모두 결합
- 하니스 엔지니어링의 보편적 전략과 상용도구 번들링 방식이 오늘날 AI 에이전트 배포의 표준임을 강조
