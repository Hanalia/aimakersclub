## *2.7배 인력으로 40배 더 많은 머지 PR을 달성한 방법 — Cognition의 내부 AI 활용 전략* 핵심 요약

- Cognition은 지난 1년간 엔지니어 수 2.7배 증가에 불과했으나, 머지된 PR(풀리퀘스트) 수는 무려 40배로 급성장함
- 개발자 생산성은 기존 대비 10배 이상 상승했으며, 코드 품질 또한 동일하거나 향상되었다고 강하게 주장함
- 핵심 원동력은 자체 개발 AI 에이전트 Devin을 활용한 ‘소프트웨어 팩토리’ 구조의 도입임
- Devin이 버그 리포트부터 PR생성·머지·검증·모니터링까지 전 개발 프로세스를 자동화
- 개발 조직 구조도 팀을 소형화(2~3명 단위)하고, 구성원마다 고객 피드백 수집·QA·PM 등 수직적 책임을 부여
- Slack 기반 워크플로우를 구체적으로 도입하여, 버그 리포트와 패치 결과를 영상 포함해 유저와 실시간으로 공유·검증
- 코드베이스는 완전히 로컬/모의 환경(Docker Compose, Mock Service, VM)으로 재구성, 클라우드 에이전트가 안전하게 테스트 자동화
- 반복적 자기개선(Recursive Self-improvement) 루프를 구축해, Devin이 자체적으로 CI 최적화∙버그 선제 탐지 등 지속적 개선을 제안
- 에이전트에게 단순 태스크가 아닌 ‘목표(Goal)’를 부여, 성능지표 추적~자동 개선 반복 등 장기 임무 방식으로 개발 패러다임 전환 시도를 강조함
- 실제 예시로는 Nvidia Vera Rubin GPU 최적화, iOS-Android 애플리케이션 동기화 자동화 등 고난이도 개발 작업도 에이전트가 주도
- 궁극적으로 인간은 지시 최소화, 대부분 Slack 피드백 및 검증 수준만으로 더 많은 결과를 창출할 수 있음을 사례로 입증함

## 세부 요약 - 주제별 정리

### Cognition의 엔지니어링 생산성은 1년 만에 40배 성장하며 AI 주도 자동화의 효과를 입증함

- Cognition에서 최근 1년간 머지된 PR(풀리퀘스트) 수는 40배 증가
- 같은 기간 엔지니어 인력은 2.7배(약 세 배 내외) 늘었을 뿐임
- 결과적으로, 엔지니어 1인당 생산성은 10배 이상 향상됨
- 이 PR은 단순량 뿐 아니라 코드 품질 면에서도 전년과 동등 이상임을 내부적으로 자신함
- 주요 질문: 어떻게 40배의 엔지니어링 생산성을 달성했는가? 어떤 구체적 시도와 변화가 있었는가?

### Devin을 활용한 소프트웨어 팩토리 도입으로 전체 개발 라이프사이클을 자동화함

- ‘소프트웨어 팩토리’란 개발 전 과정을 기본적으로 자율적으로 자동화하는 방식을 의미
- Cognition에서는 Devin(코딩 에이전트)이 버그 리포트~PR 생성~머지~모니터링·유지보수까지 휴먼 개입 없이 처리
- 코드 변경 요청(예: 버그 리포트)이 생성되면, Devin이 직접 코드를 고치고 PR을 발생시킴
- 특별한 판단이 필요한 경우에만 사람이 에스컬레이션하여 개입
- 기본적으로 모든 개발 티켓과 태스크가 Devin을 통해 자동 처리되기에, 개발자 업무 패턴에도 근본 변화가 발생

### 개발자의 역할과 조직구조는 AI 기반 프로세스에 맞춰 다시 설계되어 수직적 책임과 효율성을 동시에 강화함

- 2024년 3월경부터 큰 팀을 소규모(2~3명) ‘팟(Pod)’으로 분할
- 각 팟은 소속 엔지니어가 단순 코드 작성 뿐 아니라 고객 버그 리포트 확인, QA 테스트, PM 역할까지 수직적으로 담당
- 엔지니어별로 각자 고유 티켓(Linear Board 등)을 관리하며, 실행은 에이전트에 전달해 자동화
- 이는 규모의 경제 대신 각 엔지니어가 전 과정에 주도적으로 개입하며, AI 지원으로 기존 대비 압도적 생산력을 달성하는 구조임
- Cognition은 타 대형 조직에도 이런 소형 팟 및 수직 책임 모델을 전파중임

### Slack 기반의 원격 자동화 개발 체계가 피드백과 코드 검증 모두를 극적으로 간소화함

- 버그 리포트, 증빙 영상 등을 Slack으로 수신 및 관리
- 개발자는 Slack에서 바로 Devin을 태그해 이슈 수정 요청 가능
- Devin은 코드 수정, PR 생성, 완성 영상 피드백까지 Slack에 직접 전달
- IDE, GitHub, 로컬 환경 등을 별도로 열지 않아도, 대부분의 협업·피드백·검증 업무가 Slack에서 바로 이뤄짐
- 최종적으로 외부 고객에게도 패치 결과와 증빙 영상 등을 자동 전달 가능

### 로컬 및 모의 환경으로 완전히 구축된 테스트 인프라가 에이전트 주도 개발의 핵심 기반이 됨

- 기존에는 클라우드 스테이징 환경+DB·서버에 수동으로 접속하는 방식 사용
- 대전환: 모든 서비스가 Docker Compose 등으로 로컬에서 구동 가능하도록 개편
- 외부 서드파티 서비스도 모의(Mock) 버전 도입, 단일 VM 내에서 완전 구동 가능
- 모든 에이전트는 실서버 접근 없이 안전하게 로컬 환경에서 코드 변경과 테스트를 수행
- VM 이미지는 1시간마다 최신 코드 기반으로 재빌드, 변화에 신속 대응
- VM 빌드 실패시 Devin이 즉시 원인 분석~자동 수정, 자체 유지보수 루프를 운영
- 코드베이스/테스트 방법 자체도 에이전트가 계속 “자기학습”-자동 갱신하여 변화에 따라 빠르게 적응
- 결과적으로 엔지니어들은 노트북 대신 iPad 만으로 모든 개발 및 검증을 수행할 수 있게 됨

### 보안성이 VM·클라우드 중심으로 대폭 향상되고, 실질적 개발 안정성이 구축됨

- 개인 개발자 PC·노트북 대신, 중앙 관리되는 VM 및 클라우드에서 작업
- DevOps, 키 유출, 비밀정보 노출 등의 위험이 현저히 감소
- 환경 초기화·통제 덕분에 내부 보안 사고 예방과 신속한 문제 복구 가능
- 실제 Cognition 내 일부 엔지니어는 이미 iPad를 메인 개발 환경으로 활용 시작

### 복잡한 멀티플레이어 테스트도 완전 자동화하여, 에이전트의 고도 활용성이 입증됨

- 예시: Devin의 음성, Zoom 콜 기능 개발 및 QA
- Devin이 여러 계정을 생성, 하나의 VM 내에서 동시에 Zoom 콜에 접속 후 VOICE 메모 교환 등 고난도 시나리오를 자동화 테스트
- 이런 복잡한 환경 케이스도 클라우드 VM을 통해 실제로 재현 가능함을 입증

### 자기개선 루프 구축으로 에이전트가 스스로 개발 프로세스를 분석하고 최적화함

- 모든 코드 라인, PR, 결정/판단 과정 등이 완전 추적 가능
- Cognition은 Devin이 자체적으로 코드베이스 및 개발 프로세스를 분석하여, 효율 저하·불필요한 반복·테스트 커버리지 미흡 포인트 등 개선 방안 제언
- Devin이 Slack 채널에 매일 “Node 구조를 변경하여 CI 속도를 1분 단축 가능”, “lint 스크립트를 바꿔 20% 더 많은 버그 사전 포착” 등 구체적 제안을 자동 공유
- 개발팀은 이런 제안 중 바로 실현 가능한 부분을 즉시 반영, 지속적 품질 개선 루프 형성

### ‘업무 단위 분할→목표 중심’으로 에이전트 활용 방식을 전환하며, 인간-에이전트 협업 패러다임을 혁신함

- AI 에이전트에게 단순 개별 태스크(구현 요청 등)를 넘기는 수준을 뛰어넘고자 함
- 사례: 백엔드 P99 레이턴시 개선 업무를 Devin에게 “성능 목표”로 부여
- Devin은 실시간 측정, DataDog 연동, 알림/보고/리포트 자동화, 원인 분석 등 전체 개선 여정 주도를 맡음
- 엔지니어는 사실상 목표(지표)만 할당하고, 세부 수행계획, 실행, 개선은 Devin이 긴 루프 내에서 자체 분할/수행/보고 위주로 처리
- 모든 조직 지표(온보딩 리텐션, UI 변화, 트래픽 등) 역시 수치화-계량화하여 장기 목표로 관리할 것을 강조
- 예시: 클릭 속도, 레이아웃 변경 빈도 등까지 측정·최적화 작업을 에이전트가 ‘임무’로 수행

### 하드웨어 도입 및 신기술 확장에도 AI 주도 개발 방식이 실질적 효과를 증명함

- Nvidia의 Vera Rubin GPU 신제품 초기 테스트에서 기존 커널 미존재 상태
- Devin에게 ‘최고 추론 속도 달성’이라는 목표를 부여하고, 여러 전략적 접근/성능 테스트 수행
- 약 1주일간 에이전트가 테스트와 개선을 반복, 최적 전략을 추출
- 최종 전략만 인간 엔지니어가 검토/승인, Rubin GPU의 추론 tpm(Throughput per Minute) 성능을 신규 GB 300 대비 월등 우수하게 향상
- 전체 과정에서 에이전트가 전 과정을 주도하여 신속·효율적 문제 해결 과정을 실현

### 앱 크로스플랫폼(안드로이드-iOS) 개발 자동화로 인간 개입 최소화 및 생산력 극대화를 달성함

- 소규모 인원에도 불구하고, Devin에게 “iOS 앱의 기능과 UI 완전 동기화 기반으로 Android 앱 전체 관리”라는 장기 목표를 부여
- Devin은 코드베이스에 상시 후킹·모니터링, 고객 피드백 Slack 채널 수집, QA 자동화, 라이브 테스팅까지 주도
- 인간은 고위급 의사결정 시에만 개입, 일상적 피드백은 Devin 영상/Slack 메시지로 즉시 확인
- 44일 내 실제 배포 가능한 안드로이드 앱 완성, 과정 중 대다수 PR(일 40~50건 이상)이 인간 개입 없이 자동 병합됨
- 인간과 에이전트의 협업이 실제 업무에서 “명령→실행” 단계를 넘어, 목표만 부여하는 진정한 공동 작업 방식으로 전환됨

### 올바른 루프 설계와 목표 중심 문화가 에이전트-인간 엔지니어링의 극한 생산력과 발전을 실현함

- 영상을 통해 실제 내부 개발 환경의 변화, 구체적 툴·조직·실행 방식, 자동화 및 최적화 과정까지 단계별로 사례 중심 소개
- 궁극적으로 “루프를 올바르게 설계하면, 거의 야인적 생산성과 품질 향상 실현 가능”함을 수치·과정 모두로 입증
- 제한은 조직의 ‘야망’일 뿐, AI와 인간 협업 루프의 최적화를 통해 더욱 큰 성과와 빠른 혁신이 가능함을 주장하며 발표를 마무리함
