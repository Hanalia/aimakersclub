## *이벤트 소싱 시스템에 AI 에이전트 통합하기* 핵심 요약

- 본 영상은 기존 이벤트 소싱(Event-Sourced) 또는 이벤트 기반(Event-Driven) 시스템에 AI 에이전트를 통합하는 구체적 방법과 실제 아키텍처 적용 예시(실시간 결제 사기 탐지)를 단계별로 소개함
- 발표자는 본인의 3,500달러 노트북 구매 경험을 예로 들며, 현재의 사기 탐지 엔진(룰 기반 또는 ML 기반)이 ‘이유 설명 불가’ 및 ‘불확실성 처리 미흡’ 문제를 가지고 있음을 지적함
- 기존 룰 기반 시스템은 유지 보수 난이도, 변화하는 사기 수법에 대한 신속한 대응 한계가 있으며, ML 시스템은 대부분 경계값 기반 판단으로 “그레이 존” (불확실한 구역) 처리가 미흡함
- 해결책으로 두 계층(Tier 1: 기존 룰/ML, Tier 2: AI 에이전트 기반 판단) 조합 구조 제시. 그레이 존에서는 AI 에이전트가 추가로 개입함
- 내부 도메인은 트랜잭션, 계정, 디바이스, 결제 등 여러 바운디드 컨텍스트(bounded context)로 나뉘며, 각 컨텍스트 데이터의 비동기적 통합·전달을 위해 오케스트레이터 레이어와 메시지 브로커, CDC(change data capture) 메커니즘을 활용
- 트랜잭션 컨텍스트는 이벤트 소싱 구조 + Cosmos DB(NoSQL 이벤트 스토어), 여러 리드 모델(read model)로 쿼리 성능을 확보하고, 정보는 메시지 브로커로 다른 컨텍스트와 연동됨
- AI 에이전트는 언어모델, 툴(tool), 메모리(쉼 메모리) 구조로 동작하며, 빠른 응답(SLA 500ms 이내)을 위해 단기 인메모리 기반
- Tier 2(에이전트 레이어)는 리스크 분석, 행동 분석 등 전문 에이전트 두 개와 이 결과를 통합(합의)하는 세 번째 에이전트로 구성되어 있음 (fan-out 패턴)
- 각 에이전트는 시맨틱 레이어(통합 분석 전용 DB)에서 정보를 가져오고, 자체 툴로 트랜잭션 정보, 디바이스 신뢰도, 계정 상태, 결제 기록 등 종합 활용하여 판단
- 발표자는 POC(Proof of Concept) 데모로 전체 이벤트·에이전트 처리 흐름을 실제 시스템 시뮬레이션으로 보여주며 구조적 적용 방안을 설명함

## 세부 요약 - 주제별 정리

### “기존 사기 탐지 시스템은 이유 설명 불가와 불확실성에 취약함”

- 발표자는 3,500달러 노트북 온라인 구매 시, 결제가 네트워크 문제도 아닌데 반복적으로 거절된 경험을 소개
- 고객센터는 ‘왜 차단됐는지’ 명확한 이유를 설명하지 못했음
- 현재 시스템들은 룰 기반(고정 임계값, 과거 이력 단순 집계 등) 혹은 ML 기반(데이터-피처 제공, 임계값 기반 리스크 스코어)의 한계로, 그레이 존(불확실 영역) 판단이 어렵고, 설명력(explainability)이 낮음
- 반복되는 사기 패턴 변화, 수많은 예외상황에 대한 규칙 수작업 업데이트 한계도 지적

### “AI 에이전트가 추가로 개입해 그레이 존에서 실시간 결제 사기 판별 정확도를 높임”

- 기존 룰/ML 시스템은 효과적이지만, 불확실(회색지대) 상황에서는 AI 에이전트가 추가로 판단에 개입함
- 기존 시스템 유지 및 확장 구조(절대 대체가 아님)로, 에이전트는 선택적으로 '그레이 존' 거래에서만 실행되어 실효성/효율성을 함께 추구
- 이를 위해 두 계층(Tier 1: 룰/ML, Tier 2: 에이전트) 구조 사용

### “복합 도메인(트랜잭션·계정·디바이스·결제) 구조에서는 데이터 통합·전달이 핵심 과제임”

- 각 컨텍스트(트랜잭션, 계정, 디바이스, 결제)는 독립적으로 관리되고, DDD(도메인 주도 설계)에서 말하는 바운디드 컨텍스트로 데이터 직접 공유 없이 비동기 이벤트로 소통
- 트랜잭션 컨텍스트: 거래, 가맹점, 금액 등의 모든 거래정보 보유. 계정 컨텍스트: 계정임(고객 상세정보, KYC, 고객상태 등). 디바이스 컨텍스트: 디바이스/브라우저/OS지문 등. 결제 컨텍스트: 충전, 결제, 차지백 등
- 데이터 공유/연동은 오케스트레이터 계층 및 메시지 브로커, CDC(change data capture) 방식으로 구현

### “오케스트레이션 레이어(중앙 통제 계층)가 AI와 마이크로서비스 연동의 중추 역할을 맡음”

- 모든 도메인 이벤트와 서비스 커뮤니케이션은 오케스트레이터 레이어를 통해 제어됨 (saga 오케스트레이션 방식)
- 오케스트레이터 내부에 AI 에이전트가 포함되며, 각 도메인 컨텍스트와 비동기적으로 메시지 브로커를 통해 소통
- 메시지 브로커는 컨텍스트 간 느슨한 결합 및 이벤트 구동 마이크로서비스 통합의 핵심

### “이벤트 소싱+프로젝션(시맨틱 레이어) 구조로 AI 전용 집계 정보를 효율적으로 제공함”

- 거래 데이터는 Cosmos DB 등 NoSQL 이벤트 스토어에 저장되고 이벤트 소싱(event sourcing) 방식 사용
- 쿼리 최적화를 위해 CDC(또는 change feed)로 다양한 read model(타임라인, 고객정보 보기, 사기지표 등)로 projection/denormalize 처리
- 각 컨텍스트의 프로젝션 데이터는 종합되어 ‘시맨틱 레이어’(materialized view)로 구축·집계, AI가 실시간 활용
- 외부 컨텍스트가 이벤트 소싱을 꼭 쓸 수 없는 환경에선, 메시지 브로커를 통해 워커 프로세스가 projection 구축 담당

### “AI 에이전트는 언어모델, 도구, 메모리 구조로 동작하며 빠른 응답 처리에 최적화됨”

- 에이전트 구성 요소는 언어모델(필수적으로 LLM일 필요 없음, SLM 및 오픈소스 모델도 사용 가능), 외부 데이터 연동 툴, 일정 범위 메모리임
- 거래 건별로 500ms 이내(서비스수준SLA) 응답 필요성 때문에, 인메모리 단기(short memory)로 운용(장기 메모리 채택 불가)
- 에이전트는 문제가 분해될 수 있는 경우 루프 내에서 분할처리(스텝별 추론)하나, 무한루프 방지를 위한 분기 조건(메트릭스 등) 필수

### “에이전트 레이어는 '리스크 분석'과 '행동 분석' 전문 에이전트, 그리고 결과 통합 에이전트로 구성됨”

- Tier 2(에이전트 계층)에선 이벤트가 도달하면, 이를 Fan-out 방식으로 2개 에이전트(리스크, 행동)에 분배
- 리스크 분석 에이전트: 사기 이력, 디바이스 신뢰도, 사업 규칙 등 여러 툴로 분석
- 행동 분석 에이전트: 거래 패턴, 행동 일관성 검증, 별도 플러그인 도입
- 두 에이전트가 독립 결론 도출 → 세 번째 통합(합의) 에이전트가 이를 최종 판정(판정 기준은 if 조건, 메트릭, 별도 룰 등 다양하게 설계)

### “AI가 사용하는 시맨틱 레이어는 각 도메인 컨텍스트의 핵심 정보를 집계해 제공함”

- 트랜잭션 컨텍스트: 거래 건 수, 평균/최근 거래금액, 거래이력 등
- 디바이스 컨텍스트: 디바이스 신뢰점수, 위치 이력, IP 정보 등
- 계정 컨텍스트: KYC(본인확인) 결과, 계정 생성 시기, 지속 고객 여부 등
- 결제 컨텍스트: 최근 결제, 차지백 등 결제 이력
- 모든 정보는 Projection 레이어(시맨틱 레이어)로 집계 후 에이전트 툴이 실시간 읽어 활용

### “전체 아키텍처는 다계층(이벤트 소스/시맨틱/에이전트/오케스트레이션) 구조로 유연하게 설계됨”

- 각 서비스 컨텍스트는 자체 DB(관계형/NoSQL 등) + Projection + 메시지 브로커 통신 구조로 설계
- 오케스트레이터 내부에 에이전트 계층 및 판정툴-단기메모리 존재
- 전체 결과는 saga orchestration 패턴을 따라, 다시 연쇄적으로 이벤트로 확산

### “POC(개념검증) 데모를 통해 실제 이벤트 흐름·에이전트 판단·결과 발행 과정을 시뮬레이션으로 검증함”

- 트랜잭션, 계정, 디바이스 컨텍스트 → Projection/CDC 메커니즘으로 시맨틱 레이어에 데이터 집계
- 시뮬레이션 이벤트가 다양한 체계를 거치며, AI 에이전트 판단 흐름을 실제로 화면에 출력
- Tier 1(룰/ML)과 Tier 2(에이전트)가 연속적 혹은 병렬적으로 판단, 최종 판정은 이벤트로 다시 브로커에 발행
- 전체 흐름이 실시간으로 시각화되며, 실제 아키텍처 내 적용 가능성을 데모에서 입증

### “실시간 결제 사기 탐지 시스템에서 AI 에이전트 통합은 기존 시스템 보완·효율성·설명 가능한 대응력을 크게 높임”

- 기존 시스템의 단점(설명력 미흡, 회색지대 취약, 반복 규칙 업데이트) 보완
- 데이터 통합/오케스트레이션, Fan-out 멀티에이전트, 시맨틱 레이어 등 다양한 복합기술을 통합해 실제 서비스가 동작
- 응답 속도와 실시간 분석을 양립하며, 그레이 존 거래의 검증력을 향상
