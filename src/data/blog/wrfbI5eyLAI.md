## *1,000명의 Claude 에이전트가 페르마의 마지막 정리를 공식화하다* 핵심 요약

- Anthropic의 Lance Martin이 Claude의 두 가지 최첨단 활용 사례—대규모 다중 에이전트 협업과 에이전트 메모리 및 "드리밍(dreaming)" 기능—를 심층적으로 설명함
- 첫 사례에서는 1,000개의 Claude 에이전트가 협업하여 수 세기 동안 난제로 유명한 '페르마의 마지막 정리'의 증명을 Lean 언어로 공식화하는 프로젝트에 성공함
- 초기에는 도메인 특화 허니스(harness)와 연구자의 지속적인 개입 하에 12명의 에이전트로 작업했으나, 이번에는 도메인 특화 허니스와 인간 개입 없이 단순한 도구(Git, SQL DB)만 제공함
- 각 에이전트는 제한된 네트워크 환경(샌드박스)에서 Git과 DB에만 접근하며, 실시간 및 오프라인 모니터링으로 안전성을 확보함
- 에이전트들은 자율적으로 테이블을 설계, 역할을 분담하고 Lean 코드를 작성하며, 복잡한 과업을 효율적으로 분할·할당함
- 30시간 이상 작업하여 60개 수학적 명제를 공식화함으로써, 단순 프리미티브만으로도 난이도 높은 장기 프로젝트를 자율적으로 완수할 수 있음을 입증함
- 에이전트의 자체 메모리 사용 능력도 빠르게 진화하고 있으며, 최근 CL Bench와 포켓몬 게임 등에서도 성능이 뚜렷이 향상되는 모습을 보임
- 성능이 우수한 모델일수록 메모리를 전략적으로 활용, 압축적이고 의미 있는 정보만 저장하고, 치명적 실수를 드리밍(dreaming)으로 교정하는 능력을 보임
- 드리밍 기능은 메모리 자체를 재구성하고, 실수를 바로잡고, wiki와 같은 지식 구조를 점진적으로 구성하는 데 효과적으로 활용될 수 있음
- 종합적으로 Claude는 점점 더 적은 지시와 구조로도 복잡한 문제를 자율적으로 해결하고, 장기적 맥락을 효과적으로 관리할 수 있는 에이전트로 진화하고 있음을 시연함

## 세부 요약 - 주제별 정리

### 수백 년 동안 미해결이었던 페르마의 마지막 정리가 다중 에이전트 협업으로 공식화됨

- 페르마의 마지막 정리는 350년 넘게 미증명 상태였던 유명 수학 명제로, 'a^n + b^n = c^n'이 n > 2에서 자연수 해를 가지지 않음을 주장함
- 1990년대 중반, Andrew Wiles에 의해 손수 증명되었으나 증명 과정이 극도로 복잡·고통스러웠음
- 수년간 수학계에서는 해당 증명의 논리적 정확성을 컴퓨터로 검산(공식화)하는 노력이 이어짐
- Lean과 같은 시스템을 활용해 증명 과정을 단일 논리 사슬로 만들어 컴퓨터가 단계별로 검증함

### 12개 소규모 에이전트와 도메인 특화 도구로 공식화 작업을 처음 시도함

- 최초 시도(블로그 발표분)는 약 12명의 Claude 에이전트를 구성, 'Prove to Me'라는 도메인 특화 오케스트레이션 플랫폼과 Lean harness를 활용
- 연구자(인간)의 활발한 지원과 세부적인 구조화(스크래폴딩)가 필요했음
- 모든 증명 단계를 컴퓨터 상에서 관리·분할하여 실행함

### 도메인 특화 도구와 인간 개입 없이 1,000명 에이전트로 스케일업하여 재도전함

- 두 번째 시도(Anthropic Fable 5.2 당시 보고)는 인간 개입·도메인 특화 harness 없이 1,000명의 Claude 에이전트에 단순 도구(Git, SQL DB)만 제공
- 모든 에이전트는 샌드박스 환경에서 독립적으로 실행됨(Git와 DB만 접근 가능, 네트워크 제한)
- 실시간 모니터링(각 툴 사용 감시)과 오프라인 모니터링(10분 단위 전체 로그 수집)으로 보안·안전 문제도 철저히 통제함

### 에이전트들이 스스로 조직 구조와 작업 분배 방식을 설계하여 난제 해결에 성공함

- 1,000명 중 1명이 리드 에이전트, 999명은 헬퍼 에이전트로 간단한 역할 분담 시스템을 부여
- 5분 만에 리드 에이전트가 자체적으로 DB 테이블(announced, subtask, notes, land 등)을 생성하여 각종 역할·진행 상황·코드 작성 분배 체계를 구축
- 각 에이전트가 테이블을 통해 실시간 소통, 작업 배분, 코드 통합을 자율적으로 수행
- 구체적으로 30시간에 걸쳐 모든 수학적 진술(총 60개)을 차례로 공식화함
- 복잡한 부분(예시: Lagrange's tunnel)에서는 자동으로 세부 추상화·트리 구조 업무 분할·의존성 관리 등 고차원적 협업 패턴도 발현함

### 난이도 높은 장기 문제도 간단한 프리미티브만으로 자율적으로 해결 가능함이 드러남

- Git과 SQL DB라는 최소한의 프리미티브만으로, 복잡하고 장기적인 증명 공식화 작업을 사람 개입 없이 완수함
- 각 에이전트가 작업 중간중간 남긴 메모, 진행상황 노트 등을 통해 자율적 리소스 재할당·동기화·검증 접근을 구현함
- 성공적으로 작업을 마치고 리드 에이전트가 999명의 성과를 축하하는 메시지까지 남김(“magnificent work all 999 of you”)
- 종래 수년 걸릴 작업을 최소한의 구조화만으로 수십 시간 내 완료했음을 시연함

### Claude 모델의 메모리 능력은 버전 업이 될수록 전략적·효과적으로 진화하고 있음

- 두 번째 사례로 에이전트 '메모리(memory)' 활용력의 진화 소개 — CL Bench 벤치마크 및 포켓몬 게임 예시 중심
- 기존(예: Sonnet 46) 모델은 메모리 사용이 미숙(언제 어떤 정보를 저장·활용할지 인식 부족)
- Fable 5, Opus 등 상위 모델은 필요할 때만 의미 있는 정보를 전략적으로 메모리에 기록 및 조회함
- 별도 메모리 활용(prompting) 없이도 자체적으로 메모리 활용 전략을 발전시킴

### 단순한 기록이 아닌, 맥락적으로 긴 과업에서 의미 있는 메모리만 선별·활용하는 능력이 성장함

- CL Bench: 40개의 데이터베이스 질의를 매번 완전히 새로운 세션에서 수행, 필요한 경우만 메모리에 노트 작성 가능
- 낮은 성능 모델은 아무 도움 없이(메모리 無)와 별 차이 없으나, Fable 5/Opus 등은 메모리 존재 하에 정확도가 유의하게 향상됨
- 좋은 모델일수록 언제·무엇을 기록해야 할지 본질적으로 파악, 과거 예측/상태 추론에도 적극 반영

### 포켓몬 게임 예시에서 Claude의 메모리 질과 전략성 차이가 극명하게 드러남

- Claude 37은 포켓몬 게임 도중 엄청나게 많은 기억을 무분별하게 축적해 비효율적(실제 게임 성과도 저조)
- Fable 5는 필요하고 핵심적인 전략·전술만 선별 기록, 적은 양의 정보로도 뛰어난 게임 진행 및 성취 가능
- 메모리 디렉토리 크기로도 두 모델의 차이 확인 가능(작고 알짜만 남긴 Fable 5 vs 불필요 정보 범벅인 Claude 37)

### 에이전트 메모리는 인간의 단기/장기 기억과 유사하며, '드리밍'이 장기 지식 정제로 작용함

- 인용: 키르케고르(Kierkegaard) “인생은 뒤를 돌아보아야 이해되고, 앞으로 살아내야 한다” → 에이전트가 경험하며 기록하는 기억과, 나중의 일괄 정제(드리밍) 개념 연결
- 사람도 daily(해마)→long-term(신피질) 기억 정제 과정이 있는데, 에이전트도 임시·단기 메모에서 드리밍을 통한 장기 지식 재구성이 효과적임
- 드리밍: 과거 대화(transcript), 노트, 파일 등을 재가공하여 중복 제거, 오류 수정, wiki화, 미래 세션에 사전 주입 등 다양한 지식 구조로 진화시킴

### 드리밍 기능은 실수 교정, 틈새 정보 보완, 지식 구조화(wiki) 등 다목적으로 강력하게 쓰임

- 포켓몬 예시: 잘못된 정보(장소 오류)로 인한 루프에 빠진 Claude도 드리밍 단계를 거치면 직접 오류를 찾고 교정하며 게임 진행이 가능해짐
- dreaming을 통한 기억 정제로 '독(毒) 메모리'에 의한 장기적 실행 쇠퇴를 막을 수 있음
- 회사 내부 위키 구축 사례(Stainless사 문서+슬랙+이메일 25개 질의): 단순 검색(정답률 53%)보다, Claude가 전체 corpus를 wiki로 재구성할 때 드리밍 컴퓨팅을 추가할수록 검색력 정밀도가 비약적으로 상승
- wiki와 검색을 결합 시 효율이 추가적으로 높아짐(대표적 드리밍 응용 예시)

### 드리밍은 미완성 wiki 페이지 자동 완성, 누락 정보 보완 등 고도의 자가 학습/정제 능력을 보여줌

- dreaming 이전과 dreaming 이후 Claude가 구축한 wiki 비교: 초안엔 누락, placeholders 등이 다수 존재하지만, dreaming 단계를 거치면 빈틈없는 인덱스+콘텐츠가 자율적으로 완성됨
- 주요 역할: 과오 정정, 누락 정보 채움, 구조화된 knowledge representation(예: wiki 생성), 미래 맥락 사전 주입 등 다양
- 결론적으로 Claude와 같은 LLM 기반 에이전트는 '드리밍'을 통해 메모리, 지식 체계, 전략성, 자기 교정 능력을 비약적으로 끌어올릴 수 있음을 실험적으로 시연함
