## *에이전트가 작성하고 병합한 225,000줄의 테스트 코드 - 듀오링고 사례* 핵심 요약

- 듀오링고는 AI 에이전트를 활용해 약 8개월 만에 iOS 코드베이스에 22만 5천 줄의 유닛 테스트를 추가, 테스트 커버리지를 11%에서 24%(MVVM 레이어는 9%에서 59%)까지 대폭 향상시켰음
- iOS 저장소는 2019년 20만 줄에서 현재 약 200만 줄로 증가, AI 코드 도구 덕분에 비 iOS 개발자(백엔드, Android, PM, 디자이너 등)도 활발히 코드에 기여 중
- MVVM 패턴 도입 후 유닛 테스트가 쉬운 코드(신규 구조)에 집중, 프로젝트 초기 기준 해당 영역의 테스트 커버리지는 9% 수준에 불과
- 테스트 자동화 파이프라인 구축으로, 파일 식별-에이전트 테스트 작성-품질 검증/CI 통과-엔지니어 승인-지속적 피드백 순환 루프를 확립
- Temporal(워크플로 관리), Cloud code(코딩 에이전트), S3(공유 상태 저장), GitHub(PR·라벨 관리), DataDog(관찰성/파이프라인 모니터링) 등 인프라 활용
- 4단계 마일스톤: ①로컬 실험, ②스케줄 기반 백필, ③PR 라이프사이클 자동화, ④엔지니어가 직접 신코드 테스트 생성 요청 가능
- 테스트 대상 파일 선정은 파일 유형(MVVM 관련 가중치 부여), 크기, 레거시 코드 여부 등 신뢰 점수로 결정되며 UI 코드는 제외
- 품질 문제(린트, 테스트 불안정성, PR 관리 난이도)는 사례별로 프로세스·규칙·도구 개선, 에이전트 머신 환경 변경(리눅스→맥), 다층적 품질관리(Bot 리뷰, LLM판단 등)로 극복
- 전체 테스트 PR 중 700여건(22만 5천 줄)이 병합되었고, 인간 엔지니어의 검토·승인을 반드시 거침
- 최근에는 본 파이프라인의 순환 패턴을 iOS UI 마이그레이션, 안드로이드 코루틴 이관, 스냅샷 테스트 자동화 등 다른 영역에도 적용 중

## 세부 요약 - 주제별 정리

### 듀오링고 모바일 코드베이스의 규모와 변화로 AI 도구 도입이 가속됨

- 듀오링고의 모바일 앱(iOS/Android)은 10년 이상 운영되어온 성숙한 코드베이스를 보유
- 2019년 iOS 저장소는 약 20만 줄, 2023년 기준 200만 줄에 육박
- AI 코딩 도구(Copilot, Cloud Code 등) 도입 후 코드량 증가 곡선이 눈에 띄게 가팔라짐
- 연간 코드 기여자 수는 200명(이전)→250명(올해) 이상으로 증가, 비(iOS) 개발자, 백엔드 개발자, Android 개발자, PM, 디자이너 모두 기여
- 다양한 배경의 기여가 가능해진 배경에는 AI 보조 도구 활용이 결정적
- 코드베이스의 절반은 최신 MVVM 패턴, 나머지는 레거시 구조로 이원화되어 이행 작업이 진행 중

### AI와 인간이 빠르게 코드를 생성함에 따라 "코드 검증"이 새로운 병목이 됨

- 듀오링고는 매주 앱스토어 배포 및 600개 이상의 라이브 A/B 테스트를 진행하는 실험 중심 회사
- 코드 생산 속도가 빨라지면서, "작성"이 아닌 "검증(verify)"이 개발 파이프라인의 주요 병목이 됨
- Pull Request(PR) 단계에서 코드의 안전성 보장이 점점 더 중요해져 유닛 테스트의 역할이 커짐
- 유닛 테스트는 작성과 실행 비용이 낮고, 코드 설명 및 에이전트의 즉각적인 피드백 자원으로도 작동

### AI 에이전트 기반 자동화로 iOS 코드 유닛 테스트 커버리지가 크게 상승함

- 2023년 3월 기준 전체 테스트 커버리지 11%, MVVM 영역은 9~11%(레포 11%, 뷰모델 9%, 데이터소스 5%)
- 8개월 후(2023년 11월 기준) 전체 테스트 커버리지는 24%, MVVM 영역은 59%(레포 72%, 뷰모델 58%, 데이터소스 41%)로 약 6배 상승
- 프로젝트 범위가 전체 코드가 아닌 테스트가 용이한 MVVM 관련 신규 코드에 집중되었음

### 자동화 파이프라인은 5단계 루프(식별-생성-검증-병합-피드백)로 설계됨

- ①테스트 대상 파일 식별 → ②AI 에이전트가 테스트 코드 작성 → ③품질·CI 검증 → ④엔지니어가 리뷰 및 병합 → ⑤피드백 데이터로 계속 성능 개선
- 인프라 구성요소: Temporal(워크플로/오케스트레이션), Cloud Code(에이전트), S3(공유 상태 저장), GitHub Actions/Labels(PR 이력 및 자동화), DataDog(모니터링)

### 실험 및 점진적 확장: 4단계 마일스톤으로 체계적으로 검증하며 구축

- **1단계(로컬 검증):** 간단한 클라우드 코드 오케스트레이터와 Xcode 커버리지 리포트로 파일 선택, 두 개의 서브에이전트가 테스트 작성/PR 오픈 역할 분담
    - 1차 17 PR(8 merge), 2차 40 PR(19 merge) 등 50% 내외 병합률
    - 목표는 대량 병합이 아닌, 에이전트의 실패 케이스들을 학습해 정책 수립에 활용
    - XCtest와 SwiftTest 혼용, 싱글턴 객체 과도 사용 등에서 실패 빈발, 대규모 리팩터링(싱글턴→프로토콜화), 테스트 규칙·린트 추가 등 개선
- **2단계(스케줄 백필):** 매 PR 병합 시점마다 Xcode 커버리지 리포트 생성 및 S3 업로드, 테스트 우선순위 셀렉터 스크립트로 파일별 신뢰도 계산
    - MVVM 유닛(뷰모델, 레포 등)은 2.5배 가중치, 대형/레거시 파일은 제외, UI코드는 미포함(스냅샷 테스트와 분리)
    - 모든 테스트 병렬 생성, Cloud Code 기반 에이전트가 테스트 작성/모킹/PR 생성 처리
- **3단계(PR 라이프사이클 자동화):** 수십~수백개 병렬 PR 관리를 위한 워크플로, 상태머신화하여 주기적으로 PR 상황 분석 후 단일 액션 수행
    - 병합 충돌/3주 이상 오픈 PR은 자동 종료
    - CI 통과+리뷰어 없음: git blame으로 소스 파일 최대 기여자 자동 할당, AutoMerge 설정
    - CI 실패: 사전정의 액션(Pre-commit은 GitHub Action이 자동 수정, 테스트 에러는 에이전트가 수정·최대 5회 시도)
    - 식별→생성→검증→해결 루프가 자동화되어 반복
- **4단계(신규 코드 지원):** 엔지니어가 신코드 PR에 `[write test]` 라벨 추가 시 자동화 파이프라인 실행, 특정 파일 지정을 통한 즉시 테스트 생성·자동 PR 리턴

### 린트, 테스트 불안정, PR 품질 등 실전 과제는 다층적 규칙 접근법으로 해결함

- 최초엔 리눅스 머신에서 에이전트 실행, Xcode/Swift 미설치로 20~30분 후 CI에서 린트 에러 빈발(13.6% PR 실패, 그중 62%가 2개 린트 규칙에서 집중 발생)
    - 개선: 명확한 예시/피트폴 제공, 자동 린트 픽스(GitHub Action), 무의미한 린트 규칙 제거, 최종적으로 Mac Runner로 이관하여 실행 환경 일치 확보
- PR 품질 보장 위해 3중 체크:
    1. 테스트, 목, 페이크, 스텁 외 파일 수정 시 PR 즉시 종료
    2. Claude, Codex 등으로 AI PR 코드리뷰 수행, 심각(P0) 코멘트는 별도 에이전트 해결 후 인간 검토
    3. LLM Reviewer(판사) 도입: 프로덕션 코드/기존 테스트 수정 PR, 테스트 삭제/비활성화, 과도 대기 삽입 등 감지→자동 거부(2,200 PR 중 73개 거부). 모든 거부 사유 피드백은 프롬프트/스킬 개선에 반영

### 에이전트 파이프라인 도입 성과는 수치로도 명확함

- 2023년 3월부터 8개월간 파이프라인으로 병합된 테스트 PR 700건 이상, 테스트 코드 22만 5천 줄 추가
- 엔지니어 검토·승인 필수로 품질 관리
- 백필된 테스트의 비중은 신규 파일 기준 34%, 신규 테스트 케이스의 44% 차지. 전체 swift 라인 중 10%가 파이프라인 통해 추가
- 최근에는 엔지니어 직접 작성 비율 증가: 파이프라인의 성공적 "습관 굳히기" 효과 발생

### 자동화 루프 패턴은 테스팅 이외 다양한 엔지니어링 워크플로로 확장 가능함

- "식별-생성-검증-병합-피드백 반복" 패턴은 테스트 코드 생성 외에도 모든 반복적 엔지니어링 작업에 적용 가능
- 실제로 iOS 화면 MVVM/SWIFT UI 마이그레이션, 안드로이드 코루틴 이관, 스냅샷 테스트 자동화 등에도 동일 루프 적용 중
- 미래에는 PR 라이프사이클 의사결정(상태→액션 매핑) 트리에 LLM 기반 초고속 분류(classifier) 모델 도입 가능성도 제시

### 듀오링고의 인프라 구현 경험과 개선 사례는 엔지니어링 블로그에서 더 자세히 공유됨

- 팀원 Jesse, Gordalup, Hunter, Jiho 등 여러 엔지니어가 플랫폼 아키텍처/코드 리뷰 등 핵심 역할 수행
- 실전 경험 및 코드를 듀오링고 엔지니어링 블로그에 추가로 공개
- 유사 자동화·AI 인프라를 구축하는 타 개발자들과의 교류도 권장
