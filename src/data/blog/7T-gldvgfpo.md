## **에이전트에게 '방법'이 아닌 '무엇'을 말해야 한다 — OpenProse 소개** 핵심 요약

- 영상은 Dan Barrett(창립자), Raymond Weitekamp, Jose Montes de Oca가 참여해 OpenProse의 철학과 구조, 실제 사례, 데모를 상세히 설명함
- OpenProse는 복잡한 멀티에이전트 AI 워크플로우를 "마크다운 텍스트"로 선언적으로 기술할 수 있도록 설계된 오픈소스 프레임워크/언어임
- 핵심 주장: 에이전트에게 "어떻게(how)"가 아니라 "무엇(what)"을 명확하고 선언적으로 전달하라. 실제 세부 실행(방법)은 AI가 결정하게 하라는 패러다임 전환을 제안
- OpenProse는 단순한 챗봇이 아닌, 이벤트 기반(Event-driven) 멀티에이전트 시스템 패턴을 지향하며, 텍스트(마크다운)만으로 복잡한 워크플로우를 구성 및 관리 가능
- 기존 프롬프트 기술 발전사(프롬프트→컨텍스트 엔지니어링→하니스→자기수정형 토폴로지) 대비, 이제는 '목표 선언'과 '계약 기반 워크플로우 설계'로 초점이 이동
- 핀(고정) 기능을 통해 초기엔 느슨하게 "무엇"을 선언하고, 이후 우수 실행 사례(trace)를 "방법(how)"로 고정해 실행 비용과 신뢰성을 동시에 확보 가능
- 실 데모에선 Github PR 리뷰 자동화, 크론·웹훅 기반 트리거, 작업 선언형 조립, 규제산업(퀀트 모델 문서화) 도입 사례 등을 구체적으로 시연
- 모든 마크다운 워크플로우는 버전 관리, 합성·조합, 조직 내부 배포, 모델/스택/하니스 독립적으로 활용 가능
- 계약 기반의 워크플로우 평가와 decision model(Jev 등) 연결, RL(강화학습) 적용 가능성, 서드파티 하니스 통합까지 기술적 확장성 매우 뛰어남
- 반복적·신뢰성·감사성 필요한 복합 업무에 최적화되어 있으며, 단발성 및 탐색형 작업에는 기존 챗봇이 여전히 적합함을 명확히 구분 제안

## 세부 요약 - 주제별 정리

### AI 프롬프트 기술에서 선언형 워크플로우 설계로 패러다임이 변화함

- 5년 전(2021년)엔 '프롬프팅(prompter)' 역량이 커뮤니티에서 매우 중시됐으나, AI 기술 발전으로 실질적 프롬프트 스킬 수명이 짧아짐(2~3년)
- 프롬프트 → 수작업 컨텍스트 엔지니어링 → 하니스(자동 컨텍스트 관리) → 자기수정형 토폴로지(Anthropic 등 최신 흐름) 순으로 기술 발전
- 이제 진짜 중요한 것은 "원하는 목표나 상태를 명확하게 선언하는 것", 즉 클리어하게 output/outcome을 지정하는 계약(Contract) 작성 기술
- 실제로, 최신 모델/하니스에도 '내가 원하는 의도'를 AI에게 잘 전달하는 문제는 해결되지 않음
- 소프트웨어 전통의 '합성(Composition)', '선언형(declarative)', '계약 기반 설계' 개념을 도입해, 차세대 AI와의 인터페이스로 제시

### OpenProse는 순수 마크다운 기반으로 멀티에이전트 시스템을 기술함

- OpenProse 언어/프레임워크의 본질은 '모든 것이 텍스트', 즉 마크다운만으로 복잡한 시스템을 구성
- 실제 프로그래밍 언어이지만, 읽기는 사람·작성은 에이전트/AI가 하도록 설계되어 진입장벽 최소화
- 이벤트 기반(event-driven) 시스템이 핵심이며, "챗" 방식과 달리 트리거(크론, 웹훅 등)에 따라 자동 동작
- 오픈소스 방식(npx skills add open pros pros로 로컬 실행 가능) 뿐 아니라, 호스팅(beta.run.pro.md)으로도 접근 가능
- IT/조직 내 별도 스택·모델·인프라 제약 없이 사용자가 원하는 저장소, 모델, 가드레일, 하니스와 조합 사용 가능

### 다양한 수준의 사용자(엔지니어, 비코더, 전문가) 모두를 위한 설계가 적용됨

- 금융 등 규제산업: 마크다운으로 모든 설계가 이뤄지기 때문에 별도 IT/구매 절차 없이 도입 가능; 기존 인프라, 보안 정책 준수
- 비개발자도 논리적 영어만 읽을 수 있으면, 에이전트가 주도적으로 프로그램(워크플로우) 생성 → 필요시 가볍게 수정하는 구조
- 개발자는 개발자의 툴(코딩 에이전트, 도구 등)과 연계, 자신만의 하니스/플러그인 환경에 연결 활용 가능
- 프레임워크의 컴파일러/런타임 역시 거대 프롬프트(70~80K 토큰)로 구성 — 매우 유연한 구조

### '무엇(What)'과 '어떻게(How)'의 분리 선언 및 최적화 전략이 적용된다

- 우수한 모델에선 "목표만 명확히" 설정하면 경로/방법/도구 선택은 AI가 최적화시킴
- 비용, 신뢰성 문제 해결을 위해 핀(Pin) 기능 등 제공: 처음에는 여유롭게 "무엇"만 선언 → 실제 실행흔적(trace) 또는 성공경로를 'how'로 고정
- 이를 통해 고비용 대형모델로 우수한 실행사례를 만든 뒤, 이후 작은(저렴한) 모델로 재사용·최적화 가능
- 고정된 프로시저블(Procedural) 방식과 선언형(Declarative) 방식을 상황 별로 혼합 활용 가능

### 마크다운 '계약'을 통한 멀티 에이전트 조합 및 워크플로우 재사용이 가능함

- 에이전트, 서브에이전트, 도구(예: Exa 검색 등), 입력/출력 조건 등 개별적 요소를 선언적 마크다운 '계약'으로 구성
- 프로그램(계약)이 필요한 의존성/스킬/도구를 모두 명시 — 존재하지 않으면 실행(컴파일) 거부
- 복잡한 워크플로우도 100줄 미만의 마크다운으로 관리 가능; git으로 버전 관리, 팀 내 공유, 외부 배포 등 유연성 높음
- 선언된 계약을 여러 개 합성하는 방식으로 대규모 업무 분해·합성(Composition)이 자연스럽게 지원됨

### 트리거 및 이벤트 기반의 반복/대량 업무 자동화가 매우 강력함

- 크론(scheduled), 웹훅(Github, Slack, Stripe 등), 임의 트리거 등으로 워크플로우 자동화 가능
- 데모에서는 Github issue/PR 발생 시, 자동적으로 리뷰/수정/커밋까지 이어지는 워크플로우 구현 과정을 시연
- 실무(데모)에서 수십~수백 번의 PR 리뷰 자동화, 반복적 피드백/수정 절차 구현; 리뷰 자체가 계약(마크다운) 기반 평가 기준에 따른 검증 패턴 적용
- 모든 실행 결과(workflow)는 선언적 계약과 비교되어 평가·수정됨

### 계약 기반 평가 및 최신 모델(Decision Model, Jev 등)과의 연계가 논의됨

- 매 실행/세션에서 결과물은 "계약"으로 명확하게 정의된 이상적 상태(ideal state)와 비교되어 통과/합격 여부 결정
- 제3의 decision model(예시: Jev 등의 원샷 판별기)와 연계해 검증 효율 더 증대 가능
- 추후 Router(자동 태스크 분배기) 추가 가능성, 짧은 토큰 프리픽스/효율적 긴 컨텍스트 관리(RL 등)도 확장 가능성 시사

### 조직 내 인하우스/온프레미스와 오픈 하니스/모델 조합으로 독립적 도입이 쉬움

- 전체 구조가 오픈소스(Open Core, Permissive License)로 배포 — 조직 내 도입 시 서버 내에서 독립적으로 실행(데이터 외부 반출 X)
- 사용자 조직의 하니스·모델·인프라 스택을 그대로 조합 활용하여, 고유한 노하우(운영 매뉴얼, SOP 등)를 보안 상 안전하게 전달
- 실제 대형 금융사(연 4,000여개 모델 문서 필요)가 도입, 연 1,000만~5,000만 달러 비용 절감 효과 창출
- 정량적 개선: 인적 자원·시간 집약적 모델 문서화 업무, 반복성·감사성·준법성 요구 모두 만족

### 우수 사례: 퀀트 모델 규제 문서화, 반복 리뷰 자동화 등 실전 적용이 입증됨

- 실제 금융사 예시: 퀀트 모델별 규제 문서화, 감사·준법·업스트림 참조 등 상세 요구 조건을 계약으로 선언 → 실제 문서 자동 생성
- 공공 모델(sofer curve) 데모, 연간 필수 문서화(4,000개 모델, 매해 반복)비용/시간 대폭 절감
- 반복 피드백(최대 14번 리뷰 후 통과), 데모에서 실제 개발·운영에 직접 적용해 신뢰성 검증
- 내장 Agent/초음도우스 보완, 베스트프랙티스(좋은 계약 샘플) 및 안티패턴을 커널에 내장

### 선언형 워크플로우의 지향점과 한계도 명확하게 구분 제안함

- 반복적, 신뢰성·감사성 요구가 큰 대량 업무(예: PR 리뷰, 문서화)에는 OpenProse가 우위
- 탐색·일회성·형상 미정의(무엇을 원하는지조차 모르는) 상황은 챗봇형 인터페이스가 오히려 적합
- 완전히 엄격한 명세 기반(DSP)과는 달리, OpenProse는 일부 자유도·자동화 허용 → 실무 유연성 보장
- 고비용(모델, 컴퓨팅) 문제 완화와 효율성까지 충족하는 다양하고 진화가능한 생태계 구축 방향

### 계약 조립(Composition) 중심의 프레임워크로 '지식 공유·워크플로우 관리' 혁신을 도모함

- 여러 개의 계약을 하나의 런에 조립 → 다중 결과 충족을 요구하는 복복합 업무까지 자연스럽게 확장
- 이벤트 기반 의존성 추적 시, 효율적 상태 변화 감지와 downstream 작업 트리거를 저비용 모델(예: Jev)을 활용해 최적화 가능
- 전통 템플릿(템플릿화)과 달리, 전체 멀티에이전트 워크플로우를 선언적으로 기술 및 재활용 가능 — 기사작성, 연구, 카피에디터 등 복합 예시 설명
- 실질적으로 git/notion/jira 등과 연계 — Version control, 조직적 지식 축적/확산에 유리

### 실무 적용 및 베스트 프랙티스는 실제 개발 경험과 경험적 검증에 기반함

- 커널, 워크플로우, 베스트 프랙티스 등은 다년간의 엔지니어링·고객 프로젝트·내부 진화 알고리즘 실험 결과로 축적됨
- 소프트웨어 개발, 운영, 제품관리, quant documentation 등 다양한 분야에서 실제 사용 사례 축적 중
- 스펙 기반 개발(spec driven development) 계약 작성, 100+ PR 리뷰 실사용, 다양한 서브에이전트·스킬 조합 등 실무 노하우 다수 확보
- 코드 및 non-code(문서, 운영 등) 업무 모두에 동등하게 적용 가능 — non-엔지니어 적극 활용 사례 늘어남
