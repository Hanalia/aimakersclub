## *스케일의 복잡한 현실: 합성 데이터와 프리트레이닝* 핵심 요약

- 영상 제목: **스케일의 복잡한 현실: 합성 데이터와 프리트레이닝**
- Poolside의 Marah Abdin과 Robert McHardy가 자사의 모델 스케일링 과정에서 직면한 데이터, 합성 데이터, 프리트레이닝의 실제적인 난제, 해결법, 그리고 모델 공개 현황을 공유함
- 최근 엔터프라이즈 기업만을 위한 모델에서 공개 모델(오픈 웨이트) 전략으로 전환, Hugging Face에 Laguna M과 Laguna XS 공개, 그 과정에서 데이터 믹스와 프로세스에 많은 변화가 있었음
- 데이터 측면에서는 오토 믹서(자동 데이터 믹스 평가), 웹 데이터 샘플링 방식 개선, 합성 데이터 적극 활용의 3가지를 중점적으로 시도함
- 합성 데이터는 기존 자연(organic) 데이터의 암묵적 구조와 학습 힌트를 보완하며, 토큰 표현 및 모델 학습 방식의 다양성과 규칙성을 동시에 향상
- 효과적인 합성 데이터 파이프라인 구축을 위해 6가지 핵심 모듈(시드, 입력, 메타데이터 등)과 다양한 곡선상의 복잡성(저비용 대규모~고비용 고품질 파이프라인)을 활용
- Hive라는 유연한 에이전트 큐/오케스트레이터 기반 합성 데이터 생성 인프라로, 다양한 생성 및 평가, 감독을 손쉽게 관리
- 프리트레이닝에서는 데이터 품질과 구현 정확성, 분산훈련 환경 모두 통합적으로 관리하며, 대규모 환경에서만 드러나는 이슈(불량 GPU, 수치 정밀도, 그레이디언트 폭주 등)를 직접 겪으며 검증 및 개선
- Laguna S(118B 파라미터, 30조 토큰, 4,000 GPU 등)까지 확대한 실험에서 발견된 FP8 커널 기반 오류, 레이스 컨디션, 해시 검증 기법의 한계 등을 사례 중심으로 상세히 설명함
- 기존 모델 대비 합성데이터 다양성, 데이터 반복 감소, 수치적 개선 등을 레시피화해 차세대 모델 XGen-2, Laguna S 등으로 반영, 코드 중심 에이전틱 퍼포먼스에서 최신 경쟁 모델들과의 비교 결과도 투명하게 제시함
- 향후 더욱 확장된 모델과 오픈 웨이트 제공을 예고하며, 공개 채용 및 소셜 미디어 안내로 마무리

## 세부 요약 - 주제별 정리

### 엔터프라이즈 집중에서 전사용 공개 모델 전략으로 과감하게 전환함

- Poolside는 이전까지 엔터프라이즈(기업 고객) 전용 모델만 배포했으나 최근 오픈 웨이트(Open Weight) 모델을 공개하기 시작함
- Hugging Face에 Laguna M, Laguna XS 두 개의 공개 모델을 올림 (각각 Laguna M 0.1, XS 0.2)
- 이 두 모델 간 큰 구조적 변화가 있었고, 공개 이후 추가적인 버전업과 개선 작업도 지속 중
- 상세한 아키텍처, 데이터 구성, 실험 결과 등은 별도의 기술 보고서에 수록

### 합성 데이터는 자연 데이터의 한계를 보완하는 효과적 전략임을 입증함

- Poolside에서는 합성 데이터가 기존 자연 데이터(organic data)를 대체하기보다는 보완적·정규화 수단임을 강조
- 이유: 자연 데이터는 내재적(implicit) 정보와 구조, 추론 과정을 명시적으로 드러내지 않고, 학습 효율이 완벽하지 않기 때문
- 합성 데이터를 활용해 모델이 직접적으로 암시적 추론, 계획, 구조적 의미 등 "감춰진 힌트"를 명백히 경험하도록 만듦
- 토큰 구성뿐 아니라 "모델이 배우는 방식"까지 정규화·다양화할 수 있음
- 예시로 Laguna XS pre-training에서 전체 데이터 믹스의 13%를 합성 데이터로 구성 (post-training 전)
- 6조(trillion) 토큰 넘는 대규모 데이터 코퍼스를 생성하고, 추가 방향으로도 지속 확장 중

### 데이터 스케일 아웃 과정에서 반복(repetition)과 토큰 다양성 문제가 실제로 발생함

- 초기 소규모 실험에서는 "품질위주(quality over quantity)" 전략이 오히려 스케일 확장 시 반복적인 고품질 데이터 과적합으로 이어짐
- 더 많은 예산·규모로 데이터와 파라미터 수를 늘릴 때, 희소한 고급 데이터 반복 사용으로 모델 포화현상이 발생
- 이 문제 해결을 위해 가장 널리 사용되는 합성 데이터 방식: "리프레이징(재서술, rephrasing)" 파이프라인 도입
- 실험(ablations)에서 리프레이징 적용 시(기존 씨드 데이터 대비) 반복 감소 및 성능 향상 확인
- Poolside는 표준 리프레이징 파이프라인 외에, 코드·텍스트 간 변환 또는 STEM(science, tech, eng, math) 문서 특화 등 추가 맞춤형 파이프라인도 직접 설계 구현

### 6단계 모듈 기반의 합성 데이터 파이프라인을 체계적으로 구축함

- 모든 합성 데이터 파이프라인은 다음 6가지 구성요소로 모듈화 가능함:
  - seed(씨드, 원본 or 예시), primary input(주 입력), metadata(메타데이터), secondary input(보조입력), generator function(모델 및 프롬프트/에이전트), supplementary function(필터·검증기 등)
- 이 구조로 저비용, 대용량 리프레이징 파이프라인(씨드 비중 높음)부터, 복잡한 다중 에이전트·고도화된 검증 라인 혼합의 고품질 품질 파이프라인까지 자유롭게 설계
- 예: 교육 데이터, 수학 문제 생성, 코드 변환 등 높은 가치를 가진 경우 복잡성/품질을 높임

### 다단계·도메인 이동·다중 롤플레이 등 다양한 합성 데이터 생성 전략을 구체적으로 실험함

- 단일 단계(리프레이징) 외에, 다단계(multi-stage) 워크플로에서 각 생성 단계를 분리·적층하는 방식을 채택
- 예: 소설 생성 시 한 번에 전체 챕터가 아닌 "주인공/설정/줄거리/비틀기" 순 생성→이어 챕터별 생성 방식으로 품질 극대화
- 크로스 도메인 포팅(cross-domain porting): 수학문제를 코드로 변환하거나 코드 포맷을 전환하는 등 영역간 이동도 실험
- 다중 롤(agents)이 연속적(turns)으로 상호작용하는 에이전트 챗, 평가자-주작자 간 task evolution 등을 통해 더욱 다양하고 리얼한 합성 데이터 확장

### Hive 인프라를 통한 에이전트 큐와 오케스트레이션 구조로 유연성과 확장성을 실현함

- Hive는 합성 데이터 생성, 평가, 관리 전체를 큐(queue) 기반의 에이전트 체계로 구현한 인프라임
- 각 에이전트별로 프롬프트, 입력/출력, 모델 타입, 진입 조건, 반복주기 등을 세밀하게 맞춤 설정
- 오케스트레이터(중앙관리자)가 각 에이전트 동선과 우선순위, 상호작용(hierarchy, policy enforcement, creativity 등)을 동적으로 조정
- 수퍼바이저 역할은 오케스트레이터 전체를 감시하며, 글로벌 view로 전반적 품질 통제 가능

### 프리트레이닝에서는 데이터 품질·분산훈련·아키텍처 모두를 병행·총체적으로 관리함

- “데이터”만이 아니라 “훈련 코드베이스”, “아키텍처”, “분산 환경”, 모든 요소를 개별적이 아닌 통합적(holistic)으로 봐야 함
- 데이터나 코드베이스 둘 중 어느 하나라도 조악하다면 단단한 모델 생성 불가
- 대규모 모델(수십~수백억 파라미터, 수천대 GPU)에서만 드러나는 수많은 예기치 못한 실패 케이스를 경험함

### 대규모 프리트레이닝에서 발생하는 실제적 버그와 검증 전략을 구체적으로 사례로 제시함

- 분산 훈련 환경에서 모델 가중치 동기화/일치성을 해시(hash) 기반으로 실시간 검증
- 이 해시 방식으로 다음과 같은 대규모 스케일에서만 발생하는 버그를 잡음:
  - 불량 GPU 사용: 학습 곡선이 비정상(스파이크), 그레이디언트 노름 급등. 동일 환경인데도 데이터 손상 발생→해시 불일치로 적발
  - 그레이디언트 폭주/수치 정밀도 문제: BF16, FP16과 같은 저정밀 누적 연산 도입 시 활성값 오버플로우로 학습 중단→FP32로 누적 연산 전환·회복
- 이슈 재현 시 체크포인트 이어받아 수치 설정만 바꿔 진행, 성능 정상화 사례 공유

### 합성 데이터 다양성, 데이터 반복 최소화, 수치적 안정성 등 최적화를 차세대 모델에 반영함

- Laguna M 1→XGen-2로 진화하며, 데이터 다양성, 반복 데이터 비중 감소, 수치적 안정성, 전체적인 옵저버빌리티 개선
- XGen-2: 오픈 웨이트로 공개, 같은 크기(33B 파라미터)의 경쟁 모델 대비 코딩 분야에서 강력한 성능을 보임 (특히 Agentic coding, 에이전트 기반 자동화에 특화)
- Laguna S로 확장: 118B 파라미터(총), 8B 활성 파라미터, 30조 토큰, 4,000 GPU에서 훈련→대규모 환경에서 수치/데이터 개선점 실타래를 실제로 검증함

### FP8 커널 통합 및 커뮤니티 코드베이스 적용시 확산되는 새로운 에러 및 대응 전략을 탐색함

- Deep Chem FP8 커널 도입 과정에서 race condition, 메모리 접근 위반, gradient NaN 등 새로운 이슈 직면
- 심지어 일부 케이스에서는 전체 그레이디언트의 0.5%가 무작위로 손상되지만, 기존의 해시 체크(분산 환경에서 여러 replica 비교)로 검출 불가
- 해결책: PR로 Deep Chem에 패치 제안 및 커뮤니티 공유, blind spot(꾸준한 신규 버그 탐색과 validation) 강조
- 해시 방식의 한계(실제 학습 환경에서는 redundancy 부족) 극복을 위한 새로운 검증 로직 실험

### 차세대 모델(AI코딩/Agentic Coding) 결과를 다양한 최신 오픈 모델들과 정밀 비교하여 투명하게 공개함

- Laguna S 및 새로 개발 모델을 코드 벤치마크(Multiple Eval Code Bench, Big Code Bench 등)에서 GLM 4.5 Air, Intern 360, DeepSeek V4 Flash Max 등 다양한 최신 오픈 모델과 비교
- Laguna S가 이전 자사 모델(XS 2와 M 1) 대비 확실히 우수, 외부 대형 모델과도 대등하거나 우위인 결과 도출
- 특히 SweepBench(멀티링구얼 에이전트 프락시 벤치마크)에서 가장 탁월한 성능 시현
- 일반 상식(MMLU pro) 벤치마크에선 Nema Tron, DeepSeek 등에 밀리지만, 회사 목표인 agentic coding(코딩 중심 에이전트)에 특화 집중
- 데이터 커버리지 차 등이 주요 요인임을 설명, 데이터 확장으로 향후 채움 가능
- 새 모델도 조만간 오픈 웨이트로 공개 예정, 누구나 무료로 다운로드/이용 가능

### Poolside는 지속적 확장, 열린 협력 및 채용을 통해 에코시스템 확대에 집중할 계획임

- 발표 마지막에 회사 채용 페이지, 트위터 등 안내
- 향후 새로운 오픈 웨이트 모델 출시, 커뮤니티 협업, 지속적 기술 레시피 확장 약속
- 강연을 마치며 청중 및 참석자에게 감사의 말로 마무리
