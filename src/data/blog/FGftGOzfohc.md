## *Claude 관리형 에이전트로 연구 에이전트 구축하기 (2부/4부)* 핵심 요약

- 이 영상은 Anthropic의 Claude Managed Agents를 활용해 다양한 연구 에이전트를 단계적으로 구축하는 실제 워크숍으로 구성되어 있음
- 첫 번째와 두 번째 세션의 설계 변경점은 저장소 메커니즘을 더 추상화·컴포넌트화하여 확장성과 느슨한 결합을 실현한 것에 있음
- Claude 관리 콘솔에서 "주제별 농담 에이전트"를 직접 생성·설정·배포하는 실습을 진행하며, 생성된 에이전트는 클라우드 상에 자동 배포됨
- 실습 워크플로우는 리포지토리 클론, 종속성 설치, 환경 변수 구성, API 키 및 개인 정보 입력 등 단계별로 구성됨
- 기본 채팅형 에이전트에 이어, SEC 웹사이트에서 기업공시 분석이 가능한 스킬과, 비동기적 장기 작업을 수행할 수 있는 멀티 에이전트 구조로 확장하는 과정을 데모함
- "outcome" 이벤트와 셀프-슈퍼비전을 활용하여 사용자가 정의한 작업 평가 루브릭에 따라 에이전트가 결과를 검증 및 반복 수행하도록 구성함
- 다수의 티커(종목)에 대해 멀티세션을 동시에 운용 후 결과를 집계하는 "map-reduce" 방식 구축 과정을 실습함
- 엔터프라이즈 활용을 위한 환경 권한 관리, 비밀키(credential) 관리(vault), 외부 데이터 접근(MCP/CLI), 집단 메모리(공유 메모리 스토어) 등 실무적인 확장 방법 설명
- 세션 관찰 및 개입, 롤백·포크(세션 포킹), 예산·토큰 제한, 장기 학습(드리밍) 등 실사용 질문에 대한 구체적 Q&A가 병행됨
- 개발자 및 엔지니어들이 직접 활용 및 커스터마이즈 할 수 있는 API 기반 구조와, 주요 기능별 구현 예시를 다룸

## 세부 요약 - 주제별 정리

### 첫 번째와 두 번째 세션 설계 변화는 저장소 추상화 및 컴포넌트화를 통해 확장성과 유연성을 확보함

- 1차·2차 세션에서 가장 큰 변화는 이벤트 저장소 구조를 별도의 컴포넌트로 분리 및 추상화하여 새로운 저장 메커니즘 추가가 용이하도록 설계된 점임
- 이로써 특정 세션 로직에 저장소가 밀접결합되지 않고, 이벤트 계층까지 인터페이스 기반으로 분리됨
- 미래에 다른 유형의 이벤트나 데이터를 추가로 저장하려 할 때 구조적 확장이 쉬워짐

### Claude 콘솔에서 클릭 몇 번으로 주제별 농담 생성 에이전트를 직접 만들고 운영할 수 있음을 실습으로 보여줌

- Claude 콘솔의 UI에서 "주제별 농담 생성" 에이전트를 생성하는 데모부터 시작
- 시스템 프롬프트, 에이전트명, 설명, 모델(LLM 종류), 도구(toolset) 연결을 자동으로 설정함
- "Create Agent" 버튼 클릭 시 v1 agents endpoint 호출을 통해 실제 에이전트를 생성하고 클라우드에 배포함
- 환경(template for sandbox)도 생성하며, 데모에서는 unrestricted(무제한) 액세스 설정
- 원하는 패키지(python 등) 설치, 액세스 제어(특정 도메인 제한) 및 실제 세션을 생성해 chat을 시연
- "고양이 농담" 등의 프롬프트에 바로 응답하는 실습을 통해 에이전트 배포·상호작용이 극히 간단함을 강조

### 실습 환경 준비는 Git 리포지토리 클론, 종속성 설치, API 키 등 환경 변수 입력 등 단계로 구성됨

- 참가자는 QR코드로 리포지토리(clone), 디렉토리 이동(cd), npm install(혹은 bunai 설치) 등 환경 준비를 안내받음
- .env.local 파일에 API 키와 SEC API를 위한 이름, 이메일 삽입 등 환경 변수 준비 진행
- 네트워크(WiFi) 이슈를 고려해, 워크숍 스킬을 리포지토리 항목에 미리 포함했고, 인터넷 환경에서 누구나 단계별로 재실행 가능하도록 설계함

### Claude Managed Agents의 기본 채팅형 에이전트 인터페이스 구현 과정을 데모함

- bun run rundev 명령으로 서버 실행 후 웹사이트(frontend)에서 setup 화면 진입
- cloud code로 “workshop start” 실행 시, 6개의 단계로 워크숍 스킬이 자동 진행
- 각 단계마다 Claude가 필요한 파일 복사(.env.example → .env.local), API 키 확인, 필수 입력값 점검 등 중요한 사전작업을 안내함
- 사용자 입력란에서 채팅 메시지를 보내면 백엔드에서 SSE(event stream)를 통해 이벤트 발생 및 수신 구조로 동작
- Chat UI에서 “Say hi to our agent” 등 실제 상호작용이 가능함

### 에이전트에 SEC 분석 스킬과 멀티 에이전트 구조를 추가해 장기·비동기 분석 에이전트로 발전시킴

- 에이전트에 SEC(미 증권거래위원회) 웹사이트에서 특정 티커의 공시서류를 불러오고 분석하는 스킬 추가
- “dispatch analysis”라는 커스텀 도구(tool) 정의 및 이를 통해 서브에이전트로 작업 분배가 가능하게 함
- 하나의 헤드 연구에이전트가 필요한 만큼 서브 에이전트(예: 재무 분석, 위험 평가 등)로 분기하여 병렬작업 수행
- 메모리 스토어(long-running memory)를 통해 세션 간 정보 공유 및 팀 기반 집단지성 시나리오 시연

### "Outcome" 이벤트와 셀프 슈퍼비전 루브릭을 통해 사용자 정의 기준에 따라 결과를 자동 평가 및 반복함

- outcome 이벤트는 “Nvidia의 최신 SEC 분기 보고서 분석”과 같이 사용자가 목표와 평가 루브릭, 반복 횟수 등 세부 요구조건을 지정 가능
- Claude는 각 서브에이전트에게 실제 분석 작업을 분배하고, 결과물을 취합한 뒤, 정의된 outcome에 의해 셀프 평가 에이전트를 자동 실행함
- 평가(rubric) 기준을 만족하면 완료로 간주, 미달 시 재작업 반복
- 실제 예시로 메모리 업데이트, scorecard 파일 생성, JSON 포맷 지정 등 다양한 deliverable을 구조적으로 관리
- 결과물은 콘솔에서 쓰레드(서브에이전트별)로 상세히 추적 가능하며, scorecard는 파일 또는 데이터베이스에 저장

### 여러 종목에 대해 대규모 병렬 분석을 수행하는 map-reduce식 오케스트레이션 구조를 간단히 구축할 수 있음

- 직접 chat을 통해 “10개 티커에 대해 각기 세션을 분기하고, 결과를 집계하는 커스텀 하네스(Orchestration Harness)”를 생성
- 커스텀 도구(Dispatch analysis)를 활용해 메인 에이전트가 다중 세션을 격리 실행, 완료 후 결과를 자동 집계
- 개발자는 이러한 구조를 별도 구현 없이 Claude의 커스텀 하네스(CMA 기반) 및 API를 통해 쉽게 구성 가능

### 실무 적용을 위한 환경 권한(Access Control), 비밀키(Vault), 외부 데이터 연동(MCP/CLI) 방법을 구체적으로 안내함

- 보안 및 외부 연동을 위해 vault(비밀 자격증명 관리 시스템)로 환경변수 대신 placeholder를 사용, 실제 호출 시 지정 도메인에서만 진짜 값을 주입
- 예: SEC API 활용 시 이메일과 이름은 prompt에 삽입, 실제 production 환경에서는 vault로 보안 강화
- 외부 시스템 연동(MCP): CLI 혹은 API 호출용 MCP(Managed Compute Providers)와, 필요시 self-hosted sandbox(mcp tunnel 등)로 폐쇄망/사내 네트워크 대응 지원
- 종속성(Dependencies)은 npm/pip/cargo 등 외에도 파일 업로드, github repo 방식 등 다양한 설치 지원

### 세션 관찰·개입, 롤백·포크, 토큰·예산 제어, 장기 학습 등 현업의 니즈와 Roadmap을 솔직하게 공유함

- 실시간 SSE 스트리밍 콘솔로 모든 매니저 및 서브에이전트의 로그·이벤트 현황을 풀 오브저버빌리티로 모니터링 가능
- 신규 이벤트(메시지) 삽입을 통한 런타임 개입 가능, 하지만 현재는 세션 롤백/포크는 미지원(로드맵상 추가 예정)
- 세션 단위의 토큰/비용 제한(예산 컨트롤)은 현재 부재, 추후 계획 중
- map-reduce, outcome 기반 시설은 모두 API 호출 기반으로 구조화됨

### 집단 메모리(Shared Memory Store)를 통한 장기·공유 학습 및 드리밍 기능을 통해 에이전트 성능이 향상될 수 있음

- 집단 메모리 스토어를 통해 여러 세션, 여러 사용자 또는 조직 단위로 데이터를 누적·공유 가능
- dreaming(드리밍) 기능: 여러 세션의 transcript 및 memory를 주기적으로 분석, 좋은 사례나 edge case를 학습해 미래 에이전트의 지식에 반영
- 메모리는 개별 사용자 수준 및 조직 레벨로도 여러 개 동시 적용 가능하며, 추출 및 외부 시스템 연동이 자유로움

### Agent SDK와 Managed Agents의 차이점 및 호환성, 오케스트레이션의 유연성을 명확히 설명함

- Agent SDK는 headless cloud code 역할을 하는 바이너리 패키지로, 직접 환경에 구현·운영할 수 있음
- Managed Agents(CMA)는 fully hosted 솔루션으로, 별도의 실행 환경/하네스를 갖추고 있는 점이 차별화됨
- 양쪽 구조 모두 서로의 베스트 프랙티스와 개선점을 교환하며 발전 중
- 멀티프로바이더, 오픈API 구조이므로 벤더 락인은 최소화되어 있음

### Q&A를 통해 실사용/운영 환경의 보안, 배포, 성능, 집단기억, 개입, 롤백, 토큰 제한, 기억 업데이트에 대한 실전 노하우를 공유함

- 예: SEC 데이터 접근시 credential 필요 여부 및 vault 적용 방법
- 에이전트 오케스트레이션시 무한 루프, 토큰 폭주 위험에 대한 질문 및 예산 제한 관련 향후 계획 공유
- 작업 흐름에서 실수/역사 복구에 대한 세션 포킹 니즈와 로드맵 항목 언급
- 기억 학습 및 dreaming 확장 범위(현 단계는 메모리, 향후 skill·프롬프트까지 확대 가능)에 대한 답변
- 실습 환경 준비와 워크숍 진행상 WiFi 이슈 등 현실적인 부분까지 배려하며 설명
