## *에이전트는 모든 결정을 내릴 때 LLM이 필요하지 않다* 핵심 요약

- 영상은 Raymond Weitekamp이 최근 주목받는 ‘System 1’(의사결정/판단) 모델과 이를 활용한 재귀적 의사결정 모델(RDM; Recursive Decision Model)에 대해 설명함
- ‘System 1’의 명칭은 Kahneman의 ‘Thinking, Fast and Slow’에서 유래, 빠르고 직관적인 판단을 소프트웨어로 구현한 것으로, TypeSafe의 Jev 모델이 대표적임
- Generative AI(생성형 AI)와 대조적으로, ‘System 1’ 모델은 텍스트를 생성하지 않고 후보 옵션 중에서 빠르게 선택·분류하는 역할에 특화됨
- Jev와 같은 결정 모델을 재귀적으로 구성할 수 있음(즉, ‘결정이 또 다른 결정을 호출’하는 구조). 이는 작은 빠른 판단의 연쇄로 복잡한 작업을 수행할 수 있다는 점에서 주목받음
- 대표 사례로, Jev를 사용해 Doom이나 Factorio 같은 게임을 빠르고 효율적으로 조작하는 에이전트가 구현되어, 복잡해 보이는 작업도 많은 미소(微小) 결정의 조합만으로 해결 가능함을 증명
- 이러한 구조의 한계로는 ‘생성’의 부재와 프로그램적으로 미리 모든 옵션을 정의해야 한다는 점이 있지만, ‘생성형 모델’(LLM)과 결합 시 양쪽의 강점을 융합 가능
- 실제로 스마트홈, 문서 탐색, 영상/이미지 분류 등 다양한 예시로 RDM이 빠르고 효율적으로 문제를 해결하는 모습을 보여줌
- RDM의 효과적 병렬 실행과 충돌 방지를 위해 ‘arbiter’(중재자) 모듈이 고안됨: 여러 판단이 병렬로 이루어지더라도 최종 행위 결정만 하나로 통제함
- 이러한 혁신 모델을 실제 컴퓨터 접점으로 확장시키는 시도로, Weitekamp 본인은 마우스/키보드 없이 음성 등의 물리적 인터페이스만으로 컴퓨터를 제어하는 OSO(Operating System One) 프로젝트 개발 중임
- 발표자는 DSPI, Rust 패키지 등에서 RDM 구현체를 직접 공개, 코드와 데모 영상에서 실제 사용 예시를 제공함

## 세부 요약 - 주제별 정리

### *‘System 1’ 개념은 칼만의 이론에서 비롯되어 Jev 등 소프트웨어로 구현됨*

- Daniel Kahneman의 『Thinking, Fast and Slow』에서 ‘System 1’(빠르고 직관적인 결정)과 ‘System 2’(느리고 논리적 추론) 개념이 등장
- TypeSafe에서 Jev라는 시스템을 내놓으며 ‘System 1’이라는 소프트웨어 명칭이 널리 쓰이기 시작
- Jev 모델은 빠르고 직관적인 판별·분류·의사결정(“judgment” or “decision”)을 소프트웨어로 실현
- 커뮤니티 내에서는 Zero-shot classifier, 판별모델 등 용어 혼용이 있으나, 결국 ‘의사결정’ 능력에 초점
- Generative AI(Large Language Model)와 대비되는, ‘선택’ 특화 모델로 소개

### *의사결정 모델과 생성형 모델(LLM)은 역할 분담 및 상호보완의 관계에 있음*

- System 1 모델은 결과를 생성하지 않고, 미리 주어진 옵션들 중에 빠르게 최적의 답을 선택
- 생성형 AI(예:Llama, GPT 등)는 무한히 새로운 텍스트를 생성하는 ‘발산적’(divergent) 속성이 강점이지만, ‘수렴’(convergence)에는 약함
- 실제 시스템에서는 결국 어떤 판단이 생산 결과(코드, 문장, 행동 등)의 채택 여부를 결정해야 함
- Jev 같은 결정모델의 강점: 정확히 한 가지 행동이나 출력을 확실히 정할 수 있음(yin/yang 비유)
- 많은 에이전트/오토메이션 시스템에서 “분류/선택(Decision)”과 “생성(Generation)”이 효과적으로 조합됨

### *재귀(Recursive) 구조를 지닌 의사결정 모델(RDM)이 복잡한 작업을 단순 결정의 반복으로 해결함*

- Recursive Decision Model(RDM): “결정이 또 다른 결정을 호출할 수 있음”이 핵심 원리
- MIT의 “Recursive Language Model”(RLM)에서 영감을 받아, 의사결정 구조에 접목
- 실제로는 루트(최상위) 모델이 필요시 하위 결정모델, LLM, 혹은 도구 호출 등을 선택·호출
- 각 층마다 ‘의사결정’만으로 연결된 트리 구조/그래프로 시스템을 설계
- RLM, Coding agent 등 여러 분야에서 유사 방식(재귀적 에이전트 구조)을 적용 가능

### *Jev 기반 게임 에이전트(Doom, Factorio) 사례에서 미소결정 조합의 위력을 보임*

- Doom 플레이 예시: FPS(1인칭 시점)와 맵(지도) 두 가지 ‘조합형 의사결정 프리미티브’(composition of AI primitives) 에이전트를 결합
- 단 2개의 Jev 기반 의사결정 모델 만으로 복잡한 Doom 미션을 완료함
- Factorio 게임 사례: 에이전트가 공장 내 생산 라인 문제(인서터 고장 등)를 탐지·판단하고 행동. 여러 결정모델을 행렬/그래프 구조로 배열해 자동화
- 두 사례 모두 LLM/추론/생성 등 무거운 로직 없이 초고속 판단만으로 복잡한 환경을 효과적으로 제어하는 점을 강조
- “복잡한 추론이 필요한 것처럼 보이는 작업도, 미소결정의 조합만으로 해결 가능”이란 테이크어웨이 제시

### *재귀적 구조에서 적용되는 3대 규칙이 RDM의 설계 원칙임*

- 규칙1: ‘컨텍스트’(외부 환경)는 모델 바깥에 두고, 코드가 이를 슬라이스/분할해서 제공
    - 예: Doom 게임의 전체 상태는 시스템 바깥, 하위 결정모델은 필요한 정보만 처리
- 규칙2: ‘결정은 또 다른 결정을 호출할 수 있다’. 재귀적 트리를 허용하되, 최대 깊이(max depth)를 제한
- 규칙3: ‘생성형 모델 없이도 동작해야 한다’
    - LLM, 생성모델을 포함하지 않고도 의사결정만으로 시스템 설계 가능해야 함
    - 다만, LLM·에이전트 등과 결합 구성도 허용(혼합형 모듈 지향)

### *다차원 분류/탐색(골튼보드, Shopify 분류 등) 예시로 재귀 의사결정의 적용 범위를 설명함*

- 골튼보드(핀볼)의 예: 각 단계별로 “좌/우” 등 미소결정을 반복하여 분류, 다차원 컬러 및 번호 분류도 재귀적으로 구현
- Shopify의 12,000개 대규모 카테고리 분류에서, Jev를 활용한 재귀적 빔-서치로 효율적인 분류 진행
    - 각 레이어마다 하위 카테고리에 대한 판단을 반복, 탐색량을 현실적으로 관리
- 이미지 내 객체 탐색(예: 딱정벌레 위치 식별)도 비슷한 구조('히트맵' 형태의 재귀 탐색, 피드백 루프 적용)를 활용
- 평가: 이러한 예시들은 경우에 따라 1회 분류로도 가능하겠으나, 재귀 결정 구조임을 시각적으로 이해하도록 설계됨

### *의사결정 모델만으로 컴퓨터·브라우저 내 행동 제어가 가능함을 실증함*

- Jev 기반의 재귀 결정만으로 브라우저 웹사이트(페이지 이동, 영상 재생 등) 제어하는 예시 시연
- 일반 사용자가 사용할 수 있는 모든 액션(마우스 클릭, 핫키 등) 역시 전부 집합적으로 열거되어, 결정모델 내에서 재귀적으로 탐색/선택 가능
- 일부 유명 코딩 에이전트(Claude, Codeium, CodeWhisperer 등)와 유사하게, 실제 사용자 작업도 ‘명확한 결정의 연쇄’로 환원 가능함을 시사
- 실제 컴퓨터에서 얼마나 많은 동작 가능 액션이 있는지 세어보고, 이론적 한계를 검증

### *생성형 LLM과 조합 시, 더 복잡하고 동적인 상호작용·자동화가 가능해짐*

- 결정모델만으로는 ‘가능한 결정지’의 사전열거·설계에 한계(트리 구조의 대칭성, 프리디파인드 구조) 발생
- LLM(생성형 모델)을 결합시 동적으로 결정 후보 생성 가능, 더 유기적이고 비정형적 문제에 대응 가능
- 스마트홈 제어 예시에서, 일반화된 map(공유 인터페이스)을 기반으로 결정모델·LLM이 상호 작용
    - ex) "Cinema 모드, 취침 모드" → 하위 세부 주문 자동 구성
- map의 구조(예: TV-On, 램프-OFF 등)에 대해 결정모델이 ‘선택’, LLM이 새로운 조합·명령 추가·수정
- type-safe, 의미 기반 임베딩 등과 결합 가능성 등 map의 확장 활용 언급

### *병렬 실행 및 충돌 방지를 위한 ‘arbiter’(중재자) 설계로 실시간성 및 안전성을 확보함*

- 결정모델은 빠르고 저렴(로컬 CPU, 구형 노트북 등에서 동작)
- 여러 판단을 동시에 내려도 모두 시스템 상태를 바꾼다면 충돌(case clash, race condition) 발생
- CPU의 read/write 락(lock) 개념을 차용, ‘arbiter’ 모듈이 여러 병렬 결정 중 최종 1개만 실제 행동으로 허락
- Alex Zang(MIT) 등에서 제안한 speculative tool calling(예측적 도구 호출)를 의사결정 구조에 도입
- 음성 제어 예시에서 여러 채널의 판단결과를 arbiter가 집계해 최종 결정, 오디오·실시간 분류와 연결함

### *실제 구현(DSPI, Rust 등)과 코드/데모들이 오픈 및 운영됨*

- RDM의 첫 공개 구현은 DSPI(오픈소스 에이전트 프레임워크) 모듈로 배포
    - Compound AI 등에서 Jev system 1 API 지원
    - DSPI는 강력한 구조화 패러다임으로, RDM 아키텍처 실험에 최적화
- Rust 기반 Standalone RDM 패키지도 출시, 경량·이식성/포터블 조건에서 빠른 실행 가능
- 실제 수십개 예시 코드, 다양한 실험 예시(게임, 스마트홈, 웹, 오디오) 영상 등 공개
- 주요 리포지터리, 유튜브, 웹사이트 등에서 접근 가능(설명 중 직전 발표 링크 안내)

### *기존 컴퓨터 인터페이스 한계를 뛰어넘는 ‘Radical Human Computer Interfacing’ 방향성을 제시함*

- 발표자는 마우스/키보드 사용에 따른 신체적/정신적 스트레스(tech neck, repetitive stress 등) 경험을 토로
- 근본적으로 ‘물리적 신체와 기기의 결합’에서 오는 고질적 한계를 해소하고자 음성, 제스처 등 대체 인터페이스 탐색
- 프린스턴 랩톱 오케스트라(PlOrk)에서의 음악/컴퓨터 인터페이스 연구 경험 언급 (트랙패드, 키보드, 노트북 가속도로 만든 드럼 등)
- 실시간 머신러닝(오디오 신호 40-100ms 단위 분류)로 음성 등 물리 신호를 빠르게 분류-제어하는 실험 진행 (예시: Earshot)
- 철학: “컴퓨터를 만지지 않고, 혹은 보지 않고도 자유롭게 제어할 수 있는 시스템” 추구
- OSO(Operating System One; oso.computer) 프로젝트로 확장: 음성 기반 에이전트, 알비터 및 RDM 구조 포함, 실제 컴퓨터 사용 자동화·개인화 도전

### *OSO 프로젝트(Operating System One)는 RDM을 실시간 인터페이스 혁신과 결합함*

- OSO: RDM 기반 컴퓨터 제어 에이전트, 키보드/마우스 없이 음성만으로 컴퓨터 사용 실현 목표
- 초반 음성 입력 중심, 점차 사용패턴·선호도 기반으로 ‘자기개선’·적응하는 시스템 지향
- ‘Earshot’ 데모: 필립 글래스 음악 활용, 음성 단어 입력에 실시간으로 컴퓨터 명령 실행(딜레이 수십 ms 이하)
- Agnet/에이전트 플러그인 확장성, 일반적인 코딩 에이전트(Claude, Codex 등)와 연동/분업 가능
- OSO 시스템은 기본적으로 ‘결정 우선(Decision-First)’ 로직으로, 신뢰도 기반(arbiter 활용)으로 가장 빠른/경량 모델 선호…진화/성장하는 구조
- OSO 사이트에서 대기자 명단(wait list) 운영 중

### *초소형 인베딩/분류모델의 부흥과 타 분야 접목 시도도 함께 조명함*

- Hunch(마트 마스트라이): Gemma 2 임베딩을 WebGPU로 브라우저에서 초고속(150ms 내외) pictionary 클래스 분류 수행
- 초소형, 초경량 오디오/비주얼 인베딩·분류모델들이 부상함을 소개
- 이들 모델과 RDM, LLM 등을 유기적으로 결합하면 다양한 문맥과 입력(음성, 그림, 제스처 등) 기반 에이전트 자동화 가능성 높음

### *정리: RDM, System 1, 음성 등 인터페이스 결합으로 미래적 인간-컴퓨터 상호작용을 주도할 비전을 제시함*
