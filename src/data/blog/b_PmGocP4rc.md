## *비디오 생성물 평가(Evaling Video Slop) — Maor Bril, Character.ai* 핵심 요약

- Character.ai의 Maor Bril은 비디오 생성 AI 기술이 빠르게 발전했으나, 생성된 비디오의 품질 평가(evaluation)는 여전히 뒤처져 있다고 지적
- 기존 평가 방식(clip score, LPIPS 등)은 개별 프레임 일치 및 프롬프트 일치, 프레임 간 일관성을 측정하나, 전체 스토리 전달력이나 물리적 자연스러움 등은 평가하지 못함
- 고품질 비디오 생성을 위해서는 여전히 인간의 평가가 중요하며, 인간 평가를 바탕으로 LLM(대형 언어모델) 심판을 만들고 지속적으로 피드백을 주입하여 정렬 작업이 필요함
- 기존 LLM 심판 방식은 느리고 비용이 많이 들기 때문에, 실제 비디오 생성 프로세스와 더욱 밀접하고 빠른 평가 모델(소형 VLM, Vision-Language Model)로 전환
- 비디오 품질 평가에서 "절대 평점(1~10점)" 대신, "상대 비교(A vs B)"가 훨씬 더 신뢰성 있고 일반화에 효과적이라는 것을 실험적으로 확인함
- 학습 데이터셋 구축 시, 인간 비디오와 AI 비디오가 각각 ‘좋고 나쁨’이라는 딥러닝 편향이 생기지 않도록 동일한 방식으로 인코딩·평가(annotate)하여 AI 감지기가 아닌 진정한 비디오 평가자가 되도록 설계
- 고도화된 평가 파이프라인은 유저가 만든 다양한 캐릭터·음성·이미지의 독특한 스토리를 평가할 수 있도록 agent(에이전트) 기반 워크플로우로 변화
- 비디오 평가 시 핵심 축(스토리텔링, 페이싱, 물리엔진, 오디오 싱크 등)을 따로 점수화해야 하며, 이 과정이 생성 루프 내에 최대한 가깝게 들어와야 고품질 비디오 대량 생성이 가능
- 오디오 일치 평가는 Atmos 적용 및 특정 프레임의 사운드 스파이크 매칭 방식으로 수행, 리핑싱크(입모양 음성 싱크)는 아직 미해결 과제임
- 실제 모델 서빙(scale)·속도·비용 등 여러 현실적 제한 요인도 설명하며, 소규모 서비스에서도 개선효과와 난점을 짚음

## 세부 요약 - 주제별 정리

### AI 비디오 생성 기술은 급속히 발전했으나, 품질 판단 기준은 미흡한 수준에 머물러 있음

- 최근 등장한 Kling, SeaDance, VEO, Sora 등 AI 기반 비디오 생성기는 스튜디오 제작 대비 비용을 거의 0에 가깝게 낮추고 품질도 비약적으로 상승 중
- 트위터 등 소셜 미디어에는 다양한 비디오 생성 가이드와 팁이 공유되며, 누구나 쉽게 영상을 만들 수 있음
- 하지만 생성물이 실제로 ‘얼마나 좋은가’를 평가하는 일에는 기존의 주관적 판단이나 프레임 단위의 정량적 수치에 의존하고 있음
- 대다수의 자동 생성 비디오는 “슬롭(slop, 질이 낮은 데이터)” 상태로 출시되며, 이중 상당수는 불연속적인 물리현상(예: 추가된 사지, 동시 문 열기/닫기, 공중부양, 물리 오작동) 등 치명적 결함을 가짐

### 기존 평가 시스템은 프레임 단위 일치나 연관성만 검사하여, 전체적 스토리 전달력 등은 놓침

- Clip score 등 이미지·텍스트 모형 기반 평가는 한 장면이 프롬프트와 일치하는지, 장면 간 일관성이 있는지만 분석
- LPIPS 등은 프레임 간 장면 변동(drift) 감지를 지원하지만, 스토리 내러티브의 흐름이나 맥락적 일치성, 전체적 표현성 등은 반영하지 못함
- 예를 들어, 계단을 내려오는이라는 프롬프트가 있으면 실제 캐릭터가 걷는지, 떠 있는지까지는 기존 툴로 평가 어렵고, 오디오 싱크(문 닫힐 때 소리 등)도 감지가 안 됨
- 실제로 긴 비디오 생성을 시도할 때도, 여러 개의 짧은 영상 클립+편집 과정을 거치며, 이 과정의 품질 제어 역시 페인포인트임

### LLM을 이용한 '자동 평가자' 구축은 느리고 일관성 문제 및 프롬프트 의존성이 높음

- 최근 대형언어모델(LLM, 예: GPT 등)을 비디오 평가에 활용하는 시도가 증가
- 장점: 수많은 멀티모달(영상+프롬프트) 사례를 바탕으로 “스토리 전달력”, “물리적 자연스러움” 등 평가 가능
- 한계: 속도가 느리고, 프롬프트 설계에 따라 동일 모델이 매우 다른 결과를 내기도 함(프롬프트 민감도)
- 사람마다 프롬프트 사용 방식이 달라 “이 비디오가 좋은가?”라는 단순 문제에도 모델의 답이 일관되지 않을 수 있음

### 인간 평가(feedback)의 ‘정렬’이 필수이며, LLM 평가자 프롬프트와 결과에 반복적으로 주입해야 정합도 상승

- LLM에 인간 평가 데이터를 지속적으로 반영하여, 실제 사람들이 생각하는 품질 기준에 맞춰 동기화(align)하는 과정이 필요
- 비디오 평가용 ‘하니스(harness)’ 시스템에서는, 매번 인간 주석자가 비디오를 여러 기준으로 표기·채점 → 이 데이터로 LLM 프롬프트 튜닝 및 리워드피드백 진행
- 그러나 이런 방식은 평가 속도가 느리며, 대량 영상 생성(특히 실시간 제작 루프)에 적용하기 어렵다는 한계가 존재

### 평가 루프는 영상 생성과정(Loop) ‘앞단’으로 배치해, 저비용·신속한 오류 탐지 및 수정이 가능함

- 생성된 길이가 긴 비디오도 사실상 단편 클립의 조합이기에, 각 시작 프레임별 오류(캐릭터 드리프트 등)를 최대한 초기에 검출하여 바로잡으면, 전체 재생성 비용 감소
- 예를 들어, 6초짜리 짧은 클립 생성물에서 빨리 이상점을 확인·수정하면, 수분 단위의 롱폼 영상 전체 오류 수정 대비 비용 및 시간 절약
- 이런 사전 점검 과정이 있어야 대규모 영상 생성 파이프라인, 사용자 직접 생성 툴 등에 바로 연결할 수 있음

### ’절대적 평점’ 대신 ‘상대 비교(A와 B 중 더 나은 쪽 고르기)’ 학습이 평가 신뢰성 및 일반화에 효과적임을 입증

- 여러 사람이 “이 비디오의 스토리텔링을 1~10점으로 평가”하면 점수 기준이 제각각(예: 6/5/4/8 등)임
- 반면, “A와 B 중 어느 쪽이 스토리텔링이 더 좋나”라는 식의 쌍(pair) 비교를 반복하면 대다수의 합의가 도출되고, 평가 일관성 향상
- 실제 모델 학습 데이터셋을 A/B 비교 형식으로 구축하여 이 방식의 효과를 증명

### 진짜 품질 평가지(평가 모델) 구축 과정에서 데이터 오염 및 AI 감지기로 전락하는 편향을 방지함

- 인터넷에는 고품질 비디오(사람이 만든)가 풍부하므로, 인위적으로 나쁜 비디오(슬롭)는 좋은 비디오의 변형 또는 무작위 생성으로 제작 가능
- 데이터셋 구성 시 “인간이 만든=좋음, AI가 만든=나쁨”이라는 이분법 시 과적합되어 결국 AI 감지기(누가 만들었는지 판단)에 머무를 우려
- 이를 방지하기 위해, 실제 비디오와 AI 비디오 모두 동일 인코딩 방식·동일 평가 기준으로 어노테이트 함 → 모든 축(스토리, 물리 등) 동일하게 평가하여 진짜 품질 평가자 역할
- 이 과정을 거쳐 1차 버전에서 발생한 ‘정확히 잘못됨(예: 정지화면 카메라워크 9.2점)’ 현상도 개선

### 평가 파이프라인은 agent 기반 방식(자동 품질 검사 도구 통합)으로 변화하여 유연성과 적응성 향상

- 단일 데이터 파이프라인(특정 요구사항만 커버) 대신, 유저가 각자 독특한 캐릭터·스토리·음성을 쓰는 상황에서도 품질 평가·수정 가능하도록 ‘agentic workflow’로 전환
- 에이전트는 생성물(비디오)에 내장된 평가 도구를 통해 스스로 결과를 판단하고, 오류 즉각 수정 가능
- 이런 유연성이 서비스 대중화 및 다양한 사용자 창작물을 평가하는 데 핵심 역할

### 오디오 평가 및 리핑싱크 등 멀티모달 축 점수화는 여전히 난제이나, Atmos 등 활용해 프레임·사운드 동기화 측정

- 오디오의 음질, 선명도 평가는 Atmos 등 툴을 이용
- 비디오+프롬프트 기반 모델 입력 활용 시, 예를 들어 “문 닫힐 때 소리”라는 프롬프트가 있으면 해당 프레임 타임스탬프와 사운드 스파이크 일치 여부로 점검
- 리핑싱크(입모양–음성 일치)는 아직 미해결 과제로서, 단순 애니메이션 캐릭터 기준엔 측정이 불가능함을 인정

### 인간 평가(테이스트, 수용성 등)는 ‘Judge Judy’ 프로세스를 반복적으로 운영해 AI 평가와 정렬을 유지

- “무엇이 좋은 비디오인가?”라는 테이스트(취향) 문제는 완전히 자동화하기 어렵고, 사람마다 천차만별
- 실제 Character.ai에서 10~15분짜리 어노테이션(랜덤 축, 1인 1기준 표기)을 주기적으로 실시하고, 이 데이터를 AI 심판(LLM) 튜닝에 지속 반영
- 이 과정을 수차례 되풀이하며 점차 품질 판단 기준이 보정·진화됨을 언급

### 모델 선택, 서빙(Scale), 비용·속도 균형 등 현업 적용 시 현실적 고려 필요

- Character.ai 기준, ‘Kuan’ 소형 VLM 모델을 선택(타 사례 활용 경험, 속도·효율성 이유)하며, 더 큰 모델은 품질은 올랐으나 속도와 비용이 크게 증가
- 실제 사용 규모(수백~수천~수만개 영상)와 예산, 처리속도에 따라 가장 효율적인 경로는 달라짐
- 소규모 사용자라면 전문가 집단의 수동 평가도 현실적이고, 대규모 운영자라면 신속·저비용의 소형 모델 활용이 더 합리적 선택임

### 오픈소스 평가 시스템(하니스)은 다양한 에이전트·LLM 연동 가능하며, 사용자 피드백에 따라 기능 확장 예정

- 발표 시스템(하니스)은 에이전트나 LLM 연결이 자유롭고, 내부적으로는 API 서비스화된 agentic harness로 운영
- 사용자의 기능 요청(예: 평가 히스토리(trace) 외부 노출 등)에 따라 향후 확장 가능함을 약속
- 전체적으로는 비디오 생성–평가 자동화 루프를 좀 더 가깝고, 신속하며, 정밀하게 구축하는 것이 장기 비전임
