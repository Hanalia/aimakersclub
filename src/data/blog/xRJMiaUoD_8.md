## *쓴 교훈의 달콤한 면* 핵심 요약

- 이 영상은 Thariq Shihipar가 Anthropic 퇴사 후 1년 동안 AI와 소프트웨어 개발, 창작, 그리고 자신의 오판에 대해 고찰하며 발표한 내용임
- Thariq는 최근 1년간 자신이 맞게 예측한 AI의 동향(모델의 영상 편집/생성 능력, HTML 사용 능력, 미지 탐색·계획·학습 지원 등)과, 본인이 잘못 판단했던 사례(“Bash만 있으면 된다”, “React만 있으면 된다”, “생성형 예술이 모든 예술 형식을 위협한다” 등)를 솔직하게 소개함
- Bash나 CLI 인터페이스, React만이 정답일 것이라는 우려와 달리, AI 모델들이 다양한 언어·툴을 자유롭게, 유연하게 지원하는 방향으로 나아가고 있다고 설명
- AI가 미지의 형식이나 방식으로만 일처리를 강제하는 “불안”, 즉 ‘Shoggoth’(이질적 지능)의 우려와 달리, 인간 중심적 방식 유지 가능성에 주목함
- 올해(2023~2024)를 ‘소프트웨어의 산업혁명’과 ‘창작 르네상스’가 병존하는 시기로 정의하고, 소프트웨어가 대량생산화되면서도 창의적 품질·경제적 가치가 점점 중요해지고 있음을 분석
- AI의 발전은 “능력의 들쭉날쭉한 경계(boundary)”와 “내부의 매끄러운 연계”라는 두 가지 특성을 가진다고 지적, 점차 모든 코드와 툴을 다룰 수 있는 ‘유연성’ 중심으로 변화함을 강조
- 사례로, 본인이 만드는 2D 격투 게임 작업을 설명하며, 엔진 코드와 ‘명세(specs, 인간 가독 코드)’를 분리해 구성하는 전략을 도입함
- 최종적으로, AI의 발전은 새로운 언어·데이터베이스·운영체제 연동, 그리고 HCI(인간-컴퓨터 상호작용)의 미학적 변화 등으로 이어질 것이며, 본질적으로 “르네상스를 직접 설계해야 할 때”임을 역설함

## 세부 요약 - 주제별 정리

### Anthropic 퇴사 이후 자신이 경험한 AI의 변화와 올바른 예측

- Thariq Shihipar는 Anthropic을 퇴사하고 지난 1년간 경험한 AI와 개발 업계 변화를 반추
- 본인이 맞게 예측한 주요 동향을 솔직하게 밝힘
    - “AI 모델이 영상 편집/생성을 할 수 있을 것”이라는 예측이 실제로 구현됨 (2023년 6월부터 주장)
    - AI가 HTML 쓰기를 이해하고 활용하는 능력이 널리 확산됨
    - AI 모델이 인간에게 미지의 영역을 이해·탐색·계획하고 배울 수 있도록 돕는 일이 현실화됨
- 이러한 기술 진보가 현실이 되어감에 자부심을 느끼며, 업계의 많은 사람들이 이를 실제 업무에 적극 도입하는 점을 강조
- 자신이 맞았던 판단 외, 본인이 잘못 믿었던 부분도 있다고 고백


### Bash, CLI, React 등 특정 기술만이 “미래”일 것이라는 오판의 극복

- 한때 “Bash만 있으면 된다”, “AI는 CLI 위주로 확장된다”는 생각이 만연
    - Claude Code 등 여러 유명 툴도 Bash를 중심으로 설계
    - CLI와 Bash·터미널 기반 툴이 주류가 될 것이라는 기대감이 돌았음
- 하지만 실제로는, Bash 사용은 AI의 특정 훈련 방식에서 비롯된 과도기적 산물에 지나지 않았음
- 현재 Thariq는 CLI 대신 MCP 프로토콜, ‘코드 모드’, 점진적 기능 공개 등 다양한 방법이 더 잘 맞는다고 판단
- “React만 있으면 된다”는 오해도 비슷하게 잘못된 것으로 판명
    - 한동안 AI가 React 코드 작성을 잘해, 모든 AI 기반 앱은 React·React Native·웹이 되어야 한다는 흐름
    - 현재는 AI가 HTML, React, Swift, Figma용 JSON 등 다양한 언어와 포맷을 거의 동일하게 처리 가능
    - 특정 기술/언어에 종속된 개발 패러다임에서, 다양한 선택지를 지원하는 방향으로 기술이 진화하고 있음을 강조


### 생성을 통한 예술의 통제 상실 우려와 그 반전

- Thariq는 AI가 예술 분야를 잠식할 것이라는 ‘걱정’도 과거에 가졌었다고 언급
    - 생성형 모델이 예술적 출력물을 너무 자유롭게 만들어서 인간의 통제권을 상실할 것이라는 공포
- 실제로는, LLM(대규모 언어 모델)이 코딩을 통해 Blender, Photoshop, Figma 등의 도구를 직접 사용할 수 있고, 사용자가 원하는 통제 가능한 방식의 ‘프로그래밍적 예술’ 창작을 가능케 함
- “Shoggoth(외계적/낯선 AI)”이라는 AI에 대한 불안 개념이 업계 내에서 널리 쓰였으나, 결과적으로 인간이 자신만의 방식으로 AI를 활용·통제할 수 있음을 보여줌
- ‘AI가 자기 방식만을 강제하는 세상’이 될 것이라는 우려는 맞지 않았다고 결론


### 소프트웨어 산업혁명과 창조적 르네상스가 동시에 일어나고 있음

- 소프트웨어 산업에서 현재 일어나고 있는 2가지 대전환을 설명
    - 첫째, ‘소프트웨어의 산업혁명’: 반복 작업의 자동화, ‘소프트웨어 공장’ 개념의 확산으로 소프트웨어가 저비용·고신뢰로 대량생산되는 흐름
    - 둘째, ‘창작 르네상스’: 소프트웨어에 담긴 창의성, 품질, 인간적 가치를 높이려는 노력과 경제적 가치 창출이 동시적으로 부각
- 이 두 흐름은 서로 긴장관계에 있지만, 병행적으로 진행
- 소프트웨어 엔지니어가 AI 활용 도입의 최전선에 있으며, 이러한 변화가 다른 지식 노동 및 경제 영역에도 확산될 것이라고 진단
- ‘품질 저하 방지’, ‘콘텐츠 가치 상승’ 등 새로운 사회적 역할이 요청됨을 언급


### AI 모델 발전의 “경계”와 “내부 연계”에 대한 통찰

- AI 발전 논의에서는 흔히 “경계의 들쭉날쭉함”(zigzagging boundaries)이 언급됨
    - 옛날에는 AI에 단순한 기능(할 일 목록, Slack 클론 등)만 요구했지만, 최근엔 복잡한 게임(Mario Kart 전체 빌드, 포팅 등)까지 요청하게 됨
- 이와 달리, “내부의 매끄러운 연결”(smooth interior) 개념을 강조
    - 모델이 한 기술을 익히면 관련 포맷·언어 모두 자연스럽게 소화
    - React 코드를 쓸 줄 알면 Figma, JSON 등도 자동으로 처리 가능
- 이런 “내부의 유연성”이 AI 진화의 실질적 핵심이라고 지적
- 중요한 것은 결국 “우리가 원하는 품질의 소프트웨어를 만들 수 있느냐”임을 강조
    - 사용자가 원하는 다양한 포맷(HTML, React, Figma 등)으로 자유롭게 결과를 뽑아낼 수 있음에 만족의 뜻을 표함


### AI “품질 검수자” 역할에서 “직접 제시자”로 변하는 미래

- 과거에는 AI 사용자가 QA(품질검수), 코드 리뷰어 역할에 머무를 것이라는 예측이 많음
- 실제로는, 모델의 능력치가 높아지며 사용자는 직접 사양/목표만 정리하면 AI가 완벽한 결과물을 산출하는 흐름
- 이상적인 모델은 스스로 “완료”를 선언하고, 사용자는 단순 검증만으로 원하는 코드 및 소프트웨어를 얻게 됨
    - Opus 4.6, Opus 5.5 등 모델 발전 단계 예시와, “위도·경도 입력시 해당 좌표가 육지/해양인지 판별해 전지구 지도 재구성” 예시로, AI의 일반 상식·지식 성장이 실제 어느 수준에 이르렀는지 설명
- 이제는 “AI 활용법 설계·목표 설정”이 점점 더 중요해지는 시점임


### 실전 예시: 2D 격투 게임 개발에서 명세 기반 소스코드 구조화 실험

- Thariq는 현재 자신의 경험을 바탕으로 2D 등각 투쟁 게임(Avatar, Smash Bros 등 영감)의 개발 사례를 공유
- 개발 과정에서 AI의 창의적 개입과 사용자의 통제 사이에서 발생하는 불확실성을 토로
    - 캐릭터의 행동(돌던지기 등)의 로직 세부 사항이나 결과물이 예측 불가한 점에 당혹감을 느낌
    - AI가 너무 많은 선택지를 주도적으로 결정하거나, 사용자가 작업 몰입도가 떨어지는 등의 이슈 존재
- 해결책으로 코드베이스를 “엔진 로직”과 “명세(specs 혹은 human 폴더)”의 2부분으로 구분
    - 인간이 읽고 쉽게 편집할 수 있는, 영어로 작성된 명세 문서를 따로 관리
    - 각 캐릭터별 동작(돌 던지기, 벽 소환 등), 파라미터(크기 등)를 구분해, 이해와 수정이 쉬운 코드 구조를 실험
    - 직접 값(예: 돌 크기 1.5 등)을 조정하고, 결과를 즉각적으로 게임에 반영하며, 창작적 통제력을 높임
- Cursor 등의 실시간 코드 오토컴플리션 도구와 AI Tab 활용으로 편의성 향상
    - “중앙에 벽 소환” 등 행동을 명세에 추가 시 코드 자동 완성 및 반영
- 엔진/핵심 코드와 명세층을 분리하여 유지보수성과 가시성을 개선하는 신개념 접근법 시도


### 창작 품질 향상과 프로그래밍 방식의 다양화 필요성

- 현재, AI가 선호하는 언어나 툴에 ‘예속’될 필요 없이, “최고 품질의 소프트웨어” 구현에 초점을 두게 됨
- 앞으로는 새로운 프로그래밍 언어, 고성능 데이터베이스, 모듈화·핫스왑 가능한 시스템 그리고 이해하기 쉬운 코드 구성이 중요하다고 설명
- Rust와 같은 성능 중심 언어, 즉각적/직접적 수정 가능 언어 등에 대한 니즈 명확함
- 새로운 데이터베이스, 서버, OS와의 신개념 인터랙션 등도 연구 필요
- 개인적 실험(본인의 OS 시스템 수준까지 개입하는 소규모 자동화 등)을 통해, 미래 HCI·UI 미학 등 “소프트웨어의 미적 패러다임” 자체도 변화할 것이라고 전망


### 미래의 소프트웨어와 AI 활용, 그리고 “르네상스”를 위한 비전 제시

- 업계 내부의 공통적 논의(대담한 도전 필요, 새로운 언어와 구조 탐색, 창의성·품질 동시에 갖춘 소프트웨어 등)가 재확인됨
- 진짜 중요한 것은 “우리가 미래 경험을 주도적으로 설계하는 일”임을 강조
    - AI는 제한적 혹은 이질적인 외부 지능이 아니라, 사용자가 원하는 모든 것을 실현할 수 있는 범용 도구가 됨
    - AI와 함께 인간 중심의 “역동적 창작 르네상스” 시대를 맞이해야 함을 역설하며 발표를 마무리함
