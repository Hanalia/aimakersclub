## *음성 에이전트가 중간에 끊어져도 무너지지 않도록 만드는 방법* 핵심 요약

- 대부분의 AI 에이전트는 백그라운드 작업에 활용되지만, 실시간 음성 에이전트(콜센터, 예약 서비스 등)는 즉각적이고 인간적인 상호작용을 요구함
- 사용자들은 자연스럽게 에이전트의 말을 끊거나 혼동을 주는데, 현재 대부분의 음성 AI는 이러한 상황에서 대화가 어색해지고 실패함
- 진정으로 인간 같은 음성 에이전트를 만들려면 가장 중요한 요소는 낮은 지연 시간(레이턴시)과 자연스러운 대화 흐름임
- 음성 AI 시스템은 여러 모델(음성 인식, LLM, 음성 합성)의 파이프라인으로 구성되며, 각각의 성능이 전체 대화 품질에 영향을 줌
- 단순히 리더보드 상위권 모델을 조합하는 것은 실시간 대화 구성에는 적합하지 않으며, 실제 사용 환경에서의 에이전트 전체 성능이 더 중요함
- 모델 선택 시 'time to first audio(첫 소리까지의 시간)'와 'time to first sentence(첫 문장까지의 시간)'을 측정해야 하며, 이는 기존 리더보드의 평가와 다름
- 에이전트는 백엔드 연동 속도가 느릴 때 인간처럼 "잠시만 기다려주세요" 등으로 대화를 자연스럽게 이어가야 하며, 동시에 멀티태스킹으로 흐름을 유지해야 함
- LiveKit은 오픈소스 실시간 음성 AI 인프라로, 효율적인 턴 감지(turn detection), 모델 아키텍처 최적화, 실제 사용자 시뮬레이션 기반 벤치마킹 도구를 제공함
- 실제 시나리오(호텔 예약 데모 등)에서 시뮬레이션과 반복 테스트를 통해 자신만의 벤치마크를 구축하고, 최적의 모델 조합을 찾아야 함
- 결론적으로 "음성 에이전트는 단순한 챗봇이 아니며", 실제 대화를 기반으로 한 총체적인 성능 평가와 지속적 개선이 성공의 핵심임

## 세부 요약 - 주제별 정리

### 음성 에이전트에서 인간다움이 가장 중요한 문제임을 주장함

- 대부분의 일상 AI 에이전트는 코드 작성·리서치 등 비실시간 작업을 함
- 사용자는 결과를 즉시 기대하지 않기 때문에 지연 시간이 커도 문제없음
- 그러나 콜센터, 약국, 항공사, 자동차딜러 등 실시간 대화 에이전트는 즉각적 소통이 필수
- 사용자가 말을 끊거나 혼동을 주었을 때 에이전트가 대화를 흐트러트리고, 결국 사람 상담원 요청(Operator)으로 이어짐
- 이런 어색하고 비자연스러운 상호작용의 문제를 해결해야 함
- 특히 금융 분야(예: 결제 날짜 변경 중간 요청)에서는 정확성과 신뢰성이 더욱 중요함

### 실시간 음성 에이전트는 ‘지연 시간’ 외에도 인간 같은 대화 흐름이 요구됨

- 많은 사람들이 좋은 음성 에이전트 제작의 가장 중요한 요소로 '지연 시간(latency)'만을 강조함
- 실제로는 낮은 지연 뿐 아니라, 상대방을 자연스럽게 이해하고 대응하는 ‘human-like’ 특성이 관건임
- OpenAI의 ChatGPT 고급 음성 모드는 LiveKit을 활용함
- LiveKit은 오픈소스 실시간 프레임워크로, 음성·비디오·데이터스트림·로봇 등 여러 모달리티 지원하나, 본 발표는 음성에 집중함
- 음성은 가장 본능적이고 자연스러운 인간-컴퓨터 인터페이스로 평가됨(예: “우리는 읽기보다 먼저 말하기를 배운다” 인용)

### 기존 음성 에이전트 파이프라인 구조와 최신 모델 변화 설명

- 전통적인 음성 에이전트는 세 가지 모델 파이프라인(음성-텍스트 변환, LLM, 텍스트-음성 변환)이 협동하여 작동함
- 최근에는 음성-음성(speech-to-speech) 실시간 모델이 도입되고 있으나, 모든 용례에 적합하지 않고 성숙 단계가 아님
- 수백 개의 모델·수십 개의 제공업체 선택지가 생기며 복잡성 증가
- 많은 개발자는 리더보드 상위 모델만 조합하여 선택하지만, 실제 대화 흐름에서는 한계가 있음

### 리더보드 기반 모델 선택이 실시간 대화에는 적합하지 않음을 사례로 설명함

- 음성 인식 모델이 “3rd(3일)”을 “30th(30일)”로 오인식할 경우, LLM은 오탐 결과만을 받아 이후 모든 처리가 잘못됨
- 리더보드는 개별 모델의 정확도만을 비교할 뿐, 전체 대화 흐름 및 종단 간(stacked) 상호작용 품질은 반영하지 못함
- 대부분의 리더보드는 깨끗한 음성 데이터 기반으로 평가하지만, 실제 고객은 교통 소음·어린이 등 다양한 환경에서 통화
- 결론적으로 실제 사용 환경 및 시나리오 기반 종합적 벤치마킹 필요

### 실제 서비스에서 측정해야 할 지연 시간 지표를 구분하여 제시함

- 텍스트-음성 변환(TTS) 제공자의 ‘time to first byte’(첫 바이트 전송 시간)는 실제 오디오 시작과 무관
- 일부 인기 TTS에서 초반 0.75초까지 무음이 발생하기도 함 → 사용자는 무음 구간을 직접 경험함
- 측정해야 할 것은 실제로 고객 귀에 소리가 들리기까지의 ‘time to first audio’
- 언어 모델(LLM)은 ‘첫 토큰 추출 시간’을 제공하지만, TTS는 문장 전체를 받아야 음성 합성이 시작됨
- 따라서 LLM의 성능 평가 지표도 ‘첫 문장 추출 시간’(time to first sentence)이 되어야 실제 퍼포먼스를 가늠할 수 있음

### 백엔드 처리 지연 시 인간처럼 자연스럽게 대화를 유지하는 멀티태스킹의 중요성 강조

- 에이전트는 백엔드 작업(결제 확인, 거래 조회 등) 시 최소 수십~수천 ms의 대기시간이 발생
- 인간 상담원은 “잠시만요”, “확인 중입니다” 등으로 대기 시간 중에도 대화를 잇거나 멀티태스킹 수행
- 기존 많은 에이전트는 작업 완료까지 침묵함 → 사용자 불안, 부자연스러움 유발
- 코드를 통해 백엔드-음성 대화 흐름을 분리(Async/Await 등)하여, 대기 중에도 자연스럽게 다음 질문 진행 가능
- 툴콜 결과 실패 시에도 상황을 즉시 설명하거나, 상황에 따라 사람 상담원에게 연결하는 흐름도 가능

### 턴 감지(turn detection) 성능이 인간 유사성에 결정적임을 수치 및 예시로 증명함

- LiveKit은 발화 스크립트뿐만 아니라 오디오 리듬, 피치, 억양까지 고려하는 고성능 턴 감지 기능 제공
- 대표적 경쟁 시스템은 사용자 발화를 9.9%에서 중도에 끊어버리는 반면, LiveKit은 4.5%로 절반 이하로 개선(실제 호텔 예약 에이전트 시나리오 기준)
- 턴 감지 오류 예시: “$555.23을 결제하고 싶어요” 요청에서, 500에서 멈춘 후 2초 정적이 발생하면 잘라버림; LiveKit은 화자의 억양을 감지해 끝까지 기다림
- 턴 감지 회로도, 이벨(e-vals) 및 오픈소스 도구로 직접 데이터셋별 측정 가능

### 대기-응답 구간(지연 시간 예산) 내에서 가장 인간적인 에이전트를 만드는 전략이 필요함

- 콜러의 마지막 음절~에이전트 첫 오디오 응답 사이 ‘고정된 윈도’(latency window)가 존재
- 이 구간이 1.5초를 넘어서면 대화가 어색하게 느껴지고, 500~600ms에 근접해질수록 인간처럼 자연스러움
- 각 모델 구성요소(음성인식, LLM, TTS, 툴콜 등) 지연이 누적되어 예산을 소모
- 단순히 ‘빠를수록 좋다’가 아니라, 정해진 예산 안에 얼마나 인간다운 대화를 만들 수 있는지가 핵심

### 실제 사용자 시나리오 기반 종합 벤치마크로 음성 에이전트의 품질을 판단하고 최적 조합을 찾음

- 실제 '동작하는 에이전트'를 두고, 시뮬레이션 사용자(목표 추적, 중간에 마음 변경, 말 중단, 잡음 추가 등)로 반복적으로 테스트
- 텍스트 기반 시뮬레이션(비즈니스 로직 검증), 오디오 기반 시뮬레이션(음성 인식·턴테이킹 전체 파이프라인) 모두 수행
- 벤치마크 예시: 호텔 예약 시 정확한 DB 반영 여부·팩트 기반 결과 도출, 금융 시 올바른 금액 청구 등
- 단순 완성률뿐 아니라, 과정의 정당성(불필요 호출, 도중 기능 생략, 허위 호출 등)까지 평가 필요
- 동일한 에이전트, 동일한 입력값 하에서 모델 조합(스택)만 교체하여 반복 평가 → 각 워크플로별 '개인화 벤치마크' 구축

### 벤치마크 결과에서 리더보드와 실제 최적 모델이 일치하지 않음을 밝힘

- 발표 사례(호텔 예약 봇)에서 LLM(Gemma 4 31B, LiveKit Inference)이 최고 성능. 동일 모델이어도 제공업체가 다를 때 속도 차이 발생
- LiveKit은 음성 에이전트 목적에 맞게 추론을 최적화함
- LiveKit은 모델 아그노스틱(agnostic) 구조로 개별 상황·고객 요구에 따라 어떤 모델 조합이든 연결 가능

### 총체적인 체크리스트와 반복 개선 루틴을 통해 에이전트 품질을 높임

- 호출자가 체감하는 레이턴시 예산(침묵 구간) 측정
- ‘첫 오디오’ 및 ‘첫 문장’ 시간 측정
- 금융․개인정보 등 중요 상태는 별도 확인 프로토콜 도입
- 신원 확인 필수
- 느린 툴콜 동작 중에도 경청·대화 이어가기(멀티태스킹)
- 전 과정에 대해 완전한 대화 시나리오 반복 시뮬레이션
- 완료 결과, 프라이버시 보호, 불필요 도구 호출, 턴테이킹 등 검증 사항 점검
- 실패 케이스 발견 시 각각을 ‘회귀 시나리오’로 등록하여 반복적 자동화 테스트

### "음성 에이전트는 챗봇+스피커가 아니라", 훨씬 복잡한 실시간·인간다운 대화 시스템임을 강조하며 마무리함

- 사용자와 자연스럽고 인간적인 대화를 실시간으로 계속 이어가는 데 초점을 맞춰야 함
- 벤치마크·시뮬레이션을 통해 스스로의 서비스에 맞는 최적 모델 조합, 아키텍처, 솔루션을 찾아가야 함
- 각 회사·서비스마다 고유의 워크플로 등 수많은 개인화 벤치마크가 필요함
- “이제 여러분이 직접 이런 미래형 음성 에이전트를 만들어야 한다”는 선포로 강연을 마침
