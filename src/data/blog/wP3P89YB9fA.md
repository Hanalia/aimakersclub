## *코드 리뷰에서 놓치는 버그를 잡는 방법 – Sonar Guitar 실습 워크숍* 핵심 요약

- 이 영상은 Sonar의 개발자들이 Git Guardian(새로운 이름은 Guitar)라는 도구를 직접 실습하며, AI 코드 리뷰의 한계를 극복하고 버그를 사전에 찾아내는 방법을 설명함
- Guitar는 Pull Request(PR) 단위로 코드 변경 사항을 분석, 적합한 분석을 통한 버그, 의도와 실제 구현 불일치, 비즈니스 규칙 위반 등을 자동 탐지함
- 기타는 높은 신호 대 잡음비(signal-to-noise ratio)를 유지하여 거짓 긍정(false positive)을 대폭 줄임으로써, 실질적인 수정과 비용 절감 효과를 제공함
- CI(Continuous Integration) 실패 원인을 자동으로 진단하여 실제 코드를 깨뜨리는 오류와 불안정한 인프라 잡음을 구분함
- PR의 통과 여부 및 리뷰·수정 과정을 자동화할 수 있어, 반복되는 수동 작업의 부담을 줄임
- 각 Repository별로 검증 규칙, 비즈니스 룰, 문서화된 컨텍스트, 외부 협업 내용(Slack대화, Jira 티켓 등)을 추가적으로 연결해 Guitar가 리뷰 판단에 반영할 수 있음
- 실습은 3가지 단계(일반 검증, 비즈니스 규칙 반영, 완전 자동화 & 머지)로 진행되며, 모든 샘플은 깃허브에서 실시간 체험 가능
- Advanced Feature로는 기능 검증(Jira, Slack 연동), Cross-Repo 및 Cross-PR 분석, Reviewer 피드백 학습 등 엔터프라이즈 환경에 최적화된 추가 기능도 소개됨
- 실습 참여자는 워크숍용 깃허브 레포지토리를 복제, Guitar를 연결하고, 실제 PR 리뷰 및 자동수정 과정을 단계별로 경험함
- 제시된 사례와 데모를 통해 기타가 AI코드, 사람 리뷰 한계를 보완하며, 대규모 개발 조직에서 품질 및 속도를 동시에 높일 도구임을 강조함

## 세부 요약 - 주제별 정리

### AI 코드 리뷰 한계로 인해 검증 미흡과 프로덕션 사고가 증가하고 있음

- 최근 개발팀들이 코드 생성 AI(에이전트) 덕분에 코드 생산량과 속도가 대폭 증가하는 중임
- 하지만 AI가 빠르고 대량의 코드를 만들면서, 그 코드의 검증 주체가 모호해졌고, 실제 의도와 다른 코드가 섞여 들어갈 위험이 커짐
- 첫 번째 문제는 코드 리뷰 병목: 팀원 수는 고정인데 코드 PR은 AI 덕분에 폭증, 리뷰 대기열이 길어지고 병목 현상이 반복됨
- 두 번째 문제는 프로덕션 장애 증가: 코드가 기존 아키텍처나 팀 룰, 표준을 무시하고 의도하지 않은 변화로 프로덕션에서 문제가 잦아짐
- 이러한 이유로 기존의 사람이 직접 하는 리뷰 방식은 AI 생성 코드의 속도를 따라가지 못함
- 새로운 검증 방식이 필요하며, 그 해법으로 Guitar를 제안

### Guitar는 PR 생성시점에 폭넓은 맥락을 바탕으로 자동 코드를 분석하고 수정 제안을 함

- Guitar는 Pull Request가 생성되면, 관련된 코드 변경사항, PR세부정보, 코멘트, CI 로그, 저장소별 검증 규칙 등 다양한 컨텍스트를 동시 참조
- 기존의 SonarQube처럼 정적 분석, 시큐리티 이슈(예: SQL Injection) 뿐 아니라, PR에 담긴 개발의도와 실제 구현의 적합성까지 검증
- 리포의 리뷰 및 PR 내역과 연관, 비정형적 비즈니스 규칙까지 반영할 수 있음
- 분석 결과를 PR 내에 코멘트와 함께 바로 피드백, ‘Apply fix’를 클릭 또는 ‘guitar fix’ 댓글 하나로 자동 수정 커밋을 생성
- 사용자는 자동화 수준을 세밀하게 조정할 수 있으며, 자동화된 반복 리뷰/수정/머지가 가능

### 워크숍을 위한 환경 준비 및 깃허브 저장소 구성 과정이 상세히 안내됨

- 참가자 모두 기본적으로 Guitar 14일 무료 Pro 체험을 신청하고, GitHub 계정으로 대시보드 및 앱 설치를 완료해야 함
- 데모용 레포지토리(github.com/sonarsamples/aie-new-york-workshop-guitar)를 자신의 계정 또는 조직으로 반드시 여러 Exercise 브랜치를 유지한 채 Fork함
- Fork 완료 후 GitHub Actions(워크플로우 자동 실행)를 별도로 켜야 자동 리뷰 및 머지 기능이 정상 동작
- 기타 대시보드 > 설정 > 저장소에서 Fork된 저장소가 정상 인식되는지 확인

### 첫 번째 실습에서는 기능 신규 추가 PR에 대한 Guitar 기본 리뷰 동작을 확인함

- 샘플 프로젝트(Box Office)는 소규모 콘서트 티켓팅 API(Python) 예시로 주문 및 체크인 기능 가짐
- stage-1 브랜치 PR: 티켓 주문 후 친구에게 양도 기능을 새로 추가, 기본적 유효성 검증과 간단한 테스트 케이스 포함
- 해당 PR에서 모든 CI 테스트 통과, 별 문제 없어 보이나, Guitar는 "티켓을 양도한 뒤에도 구매자가 환불/무효화가 가능"한 예외 케이스를 자동 탐지
- 일반 리뷰어로선 이전 기능(환불 처리)의 동작을 다 파악하지 못하고 놓쳤을 부분까지 Guitar가 비즈니스 로직 관점에서 잡아냄
- 발견 즉시 Guitar의 'Apply fix' 또는 'guitar fix' 댓글 작성시 자동 커밋/추가 테스트까지 반복 진행, 워크플로우가 green될 때까지 자동 검증·수정함

### 두 번째 실습에서는 조직/제품의 특수한 비즈니스 룰을 코드 리뷰에 반영하는 방법을 다룸

- stage-2 브랜치 PR: 티켓당 $3.50 서비스 수수료가 별도 추가되는 로직을 구현, 테스트케이스 추가됨
- 해당 회사는 '모든 가격은 수수료 포함한 최종금액만 표기'라는 비즈니스 룰을 내재, 사용자 경험을 위해 매우 중요한 가치임
- 이러한 룰이 코드에 명시되지 않았더라도, .gitar/reviewdirectory(비즈니스 맥락) 혹은 .gitar/rulesdirectory(자동검증규칙)에 추가 문서와 규칙을 자유롭게 입력 가능
- 예시로, '가격 필드가 수정될 경우, 고객에게 노출되는 가격이 올인(수수료 포함)인지 검사'하는 룰 작성
- 친숙하고 강력한 기능: Slack 링크가 PR 설명에 들어가면 Slack 대화 맥락까지 코드 리뷰에 자동 연결 가능
- 결과적으로 Guitar가 해당 PR에서 올바른 가격 표기/비즈니스 룰 미준수를 탐지, 훨씬 정밀한 리뷰 프로세스를 구축할 수 있음

### 세 번째 실습에서는 풀 오토메이션을 활용해 자동 PR 통과·머지까지 구현함

- stage-3 브랜치 PR: 티켓 스캔 로직 리팩토링, 티켓별 웹 URL 참조방식 변경
- 자동화 규칙 설정: GitHub > 환경설정에서 allow auto merge 활성화, 새로운 branch rule set으로 ‘status check(테스트)’가 통과해야만 머지되도록 설정
- 리팩토링 후 테스트 실패 발생(“티켓을 두 번 스캔할 수 없음” 로직 누락) → Guitar가 자동으로 CI 로그를 분석, 실패 원인을 정확히 짚고 자동 수정 PR을 반복 적용
- 별도의 UI 클릭 없이 ‘guitar auto apply on’, ‘guitar auto merge on’ 댓글만으로 휴먼 개입없이 문제를 수정, 검증, 최종 자동 머지까지 처리
- 실제 CI 파이프라인 반복과정(수정→테스트→머지)에서 발생하는 시간·비용·사람 의존도를 최소화함

### Guitar는 전통적 정적분석+비즈니스 컨텍스트 결합으로 완성도 높은 코드 검증을 실현함

- SonarQube 같이 전통적 정적분석도구는 시큐리티 위협 및 코드양/논리 흐름 분석에 탁월
- Guitar는 PR의 제목/설명, 코드 변경내역, 테스트, 커밋 등 맥락을 분석해, '의도'와 '현실'의 불일치, 비즈니스 상 커버되어야 할 논리 부재 등 추가 위반사항 검출 가능
- 두 솔루션을 함께 활용하면, 보안+비즈니스 양면에서 완전히 검증된 코드 품질 확보 가능함

### Guitar의 리뷰/머지 자동화 설정은 저장소별, 브랜치별로 자유롭게 적용할 수 있음

- Guitar 대시보드에서 저장소별 자동 승인, 자동 머지 등 설정을 개별적으로 ON/OFF 가능
- 복잡한 파이프라인 환경(수많은 테스트와 가드레일 구축된 엔터프라이즈 레포)에서도, 기타를 더해 완전 자동화 체계를 구현
- 실습에서는 자동 기능을 직접 옵션별로 불·활성화하며, 워크플로우의 유연성 사례를 다룸

### Guitar의 고급 기능으로 Jira, Slack, Cross-Repo/PR 검증 등 엔터프라이즈 수준의 협업이 가능함

- 기능 검증 : Guitar는 Jira 이슈 혹은 Slack 대화와 PR을 연결, 비즈니스/기능 요구사항 커버 여부도 자동 검증 가능 (현재 Jira, Linear, Slack 연동 지원)
- Knowledge 기능: 리뷰 피드백(거절, 수용) 이력을 학습해 false positive를 줄이고, Senior 리뷰어의 의견을 자동 반영하여 더 정확한 판단
- Cross-Repo 분석: 여러 저장소(무제한)의 PR을 동시에 분석, 독립 통과된 두 PR이 함께 머지되면 프로덕션 오류가 날 수 있는 위험을 사전 예측
- Cross-PR 분석: 진행중인 여러 PR끼리의 상호 영향성까지 자동 비교, 각 개별 PR에서는 통과해도 합쳐지면 오류나는 상황을 사전에 탐지·경고

### Guitar의 직접 리뷰 결과물은 코드 위치, 문제 사유, 수정 제안 등 구체적으로 안내되어 있음

- PR의 어느 라인에서, 어떤 이유로(버그/논리오류/비즈니스 규칙 위반 등) 문제가 있는지 Guitar가 코멘트 형태로 명확히 표시
- 단순 수정안 제시뿐 아니라, 왜 이 문제가 중요한지/어떤 기준으로 잡힌 것인지도 함께 설명
- 리뷰 대시보드에서 전 과정 내역, 수정 내역, PR 히스토리, 컨텍스트(리뷰 이유, 적용된 룰 등) 일목요연하게 확인 가능

### Guitar와 기타 연동기능 및 컨텍스트/Knowledge 피드백 활용 방안이 소개됨

- MCP(외부 맥락 관리 플랫폼) 등의 맥락도 ingestion 가능, 코드 외 다양한 도메인 정보/규칙을 리뷰에 포함
- Knowledge 탭 및 컨텍스트 기능을 함께 활용하면, 조직 내 아키텍처 가이드라인, 규칙, 관행 등을 코드 리뷰에 직접 접목 가능
- Guitar에 피드백(특정 fix 방식 선호 등을 댓글이나 Knowledge에 입력) 시 향후 리뷰시에도 일관되게 반영됨

### 실습 이후 추가 학습 및 활용을 위한 가이드와 유의점이 제공됨

- 연습용 레포 README에는 ‘Take it further’ 섹션(심화활동)이 따로 준비돼 있음. 참가자가 워크숍 후 자율적으로 실습하며 고급 기능까지 경험 가능
- 14일 무료 Pro 체험 라이선스를 활용해 본인 레포에도 자유롭게 적용·실험 가능함
- 참가자 질의응답에서 연동, Knowledge 학습, 컨텍스트 ingestion 방법 등 심도깊은 사용법 논의

### Guitar는 대규모 AI/에이전트 개발 환경의 PR 리뷰 및 코드품질 자동화의 새로운 표준임을 실습을 통해 입증함

- AI가 양산하는 대량 코드를 검증, 유지보수, 품질보증까지 커버하려면 기타같은 자동화된 컨텍스트 기반 도구가 필수임을 반복 강조
- 수동 코멘트, 단순 정적 분석을 넘어서, 실제 비즈니스 규칙·테스트·CI 로그까지 통합하는 하이브리드 리뷰 체계 제공
- 빠른 속도, 높은 품질, 실질적 노이즈 제어, 엔터프라이즈 협업 최적화 등 다양한 조직에 적용 가능함을 데모와 실습을 통해 확인시킴
