## *프롬프트 인젝션은 AI 에이전트 보안의 시작에 불과함 (필요한 보안 대책 안내)* 핵심 요약

- 영상은 AI 에이전트(예: '두 번째 두뇌')를 업무에 활용할 때 발생하는 보안 위협, 특히 프롬프트 인젝션 문제를 상세히 소개함
- 프롬프트 인젝션이란 외부 데이터(예: 웹, 문서 등)에서 악의적인 명령이 전달되어 사용자가 의도하지 않은 행동을 AI가 수행하게 만드는 현상
- 개인적으로 AI 에이전트를 직접 구축한 제작자는 데이터 흐름 중간에 다수의 보안 점검과 접근 제한 조치를 적용함
- 에이전트 스스로가 LLM(대형언어모델)에 전달되는 모든 정보에 안전검사를 거치도록 설계했다고 언급
- 대규모 조직이나 기업에서는 수많은 에이전트가 다양한 환경(클라우드, 직원 단말기 등)에 분산되어 운영되기에 훨씬 더 복잡한 보안 체계가 요구됨
- 조직 내 IT 부서는 사용 중인 모든 에이전트의 소유자, 접근 권한, 위험 범위 등을 명확히 파악하는 것이 필수적임
- 마이크로소프트가 소개한 ‘Agent 365’ 및 ‘Project Perception’은 각 에이전트에 고유 신분, 동적 접근 권한, 위험 변화에 따른 자동 격리 기능 등 새로운 보안 대책을 적용
- 에이전트 접근 통제, Guardian 에이전트를 통한 집단 보안 관리, 동적·업무 기반 권한 설정, 위험 인지 기반 정책 적용 등 구체적 보안 기능이 설명됨
- 관리자는 추천 보호 조치를 사전 검토·시뮬레이션·점진 적용할 수 있어, 실질적 보안 통제와 유연성을 동시에 보장
- 영상은 대규모 에이전트 환경에서 발생할 최신 보안 위협과 이에 대응하는 기업용 솔루션의 구조 및 효과를 현실적으로 보여줌

## 세부 요약 - 주제별 정리

### AI 에이전트를 활용할수록 보안 이슈가 커지며 사용자 데이터 접근권한 관리가 필수적임

- 영상 제작자는 '두 번째 두뇌(Second Brain)'라는 AI 에이전트를 사용해 다양한 업무를 자동화
- AI 에이전트를 업무 프로세스에 깊이 통합하면서 상당한 양의 시스템 및 데이터 접근권한을 부여하게 됨
- 이러한 특성 때문에 보안 위협, 특히 의도하지 않은 데이터 조작이나 명령 실행 가능성을 항상 염두에 두어야 함
- 특히 외부에서 유입되는 데이터가 AI의 행동을 예상치 못하게 바꿀 수 있다는 사실을 강조함
- AI 에이전트가 점점 더 많은 필수 정보를 다루게 되면서 '무분별한 접근 권한'이 곧 보안 리스크로 전환됨

### 프롬프트 인젝션은 데이터 기반 명령 실행의 맹점에서 비롯됨

- 프롬프트 인젝션(prompt injection)이란 LLM에 입력되는 데이터에 의도하지 않은 지시문이 숨어있어, AI가 악의적 또는 부주의한 행동을 하게 만드는 현상임
- 예를 들어 외부 웹페이지, 이메일, 문서 등에서 AI가 정보를 추출할 때, 해당 데이터 내에 "이러이러한 명령을 실행하라"는 문구가 있을 수 있음
- 결과적으로 사용자가 명시적으로 요청하지 않은 작업이 AI를 통해 자동 실행되는 사태가 벌어질 수 있음
- 제작자는 항상 이러한 프롬프트 인젝션의 위험을 경계해야 한다고 언급

### 직접 구축한 에이전트에서는 단계별 보안 점검 및 최소 권한 원칙을 적용함

- 제작자는 자신이 만든 에이전트(두 번째 두뇌)에는 입력되는 모든 데이터를 LLM에 전달하기 전에 보안검사를 거치도록 설계함
- 예컨대, 데이터에 이상 신호나 위험 명령이 있는지 탐지
- 또한 에이전트에는 '정말 필요한 리소스'에만 접근을 허용하는 최소권한 정책을 적용함
- 이렇게 함으로써 에이전트 자체가 불필요한 데이터 유출이나 과도한 명령 실행의 통로가 되는 것을 방지

### 개인과 달리 기업 환경에서는 수십~수백의 에이전트가 분산 운영되어 관리가 매우 복잡해짐

- 영상은 "이 모든 것이 내가 직접 에이전트를 만들었으니 가능한 일"이라고 강조
- 하지만 일반적인 기업 환경에서는 수많은 에이전트가 클라우드와 각 직원의 단말기 등 다양한 환경에 동시에 배치됨
- IT 부서는 모든 에이전트의 종류, 소유자, 접근 권한, 네트워크 위치, 제어 범위 등을 정확히 파악해야 함
- 각 에이전트가 어디에 어떤 권한으로 연결되어 있는지 모를 경우 전체 보안에 큰 위협이 되어버림

### 마이크로소프트의 Agent 365와 프로젝트 Perception은 대규모 에이전트 보안 체계 수립에 집중함

- 마이크로소프트는 이러한 대규모 에이전트 환경의 보안 관리를 겨냥해 'Agent 365'와 '프로젝트 Perception(Perception Project)' 솔루션을 개발
- 이 솔루션은 각 에이전트에 고유한 ID를 부여해 신원을 명확히 하고, 접근 권한 및 역할을 엄격히 설정할 수 있도록 함
- 또한 과도한 권한이나 용도 외 활용을 실시간으로 제어하며, 위험도 변화에 따라 에이전트를 자동으로 격리(Containment)할 수 있음

### 프로젝트 Perception은 에이전트 보안 취약점을 시각적으로 진단하고 집단 대응을 지원함

- Perception Project에서는 '에이전트 인사이트(Agent Insights)' 기능을 통해 현재 보안 정책의 허점을 시각적으로 파악할 수 있음
- 기존 통제점이 미치는 영향 범위, 취약점 발생 지점, 권한 과다 할당 사례 등을 한눈에 볼 수 있도록 도와줌
- Guardian 에이전트라는 보안 관리 전담 에이전트를 통해 전체 조직 내 다수의 AI 에이전트를 동시에 진단·통제
- 기존에는 에이전트 1건씩 개별적으로 조사해야 했으나, 이 방식은 집단단위의 효율적 보안 관리가 가능함

### 에이전트에는 미션 단위로 동적·시간제한적 접근 권한이 자동 부여되며, 위험도에 따라 정책이 조정됨

- 동적(permission delegation) 기능을 통해 에이전트는 자신의 역할과 현재 작업에 필요한 데이터 또는 시스템에만 일시적으로 접근 가능
- 각 접근 권한은 명확히 정의된 미션 범위 내에서만 적용되며, 필요 기간에 한해 자동 해제됨
- Risk-based access control(위험 기반 접근 제어)이 적용되어, 업무 정책과 실시간 위험 평가를 결합한 보안 정책이 실행됨
- 단순한 로그인 시점 뿐만 아니라 에이전트의 행동 패턴 및 실행 명령의 맥락에 따라 접근 권한이 동적으로 변동됨

### 조직 IT 부서는 자동 추천 보안정책을 사전 검토·시뮬레이션·점진 도입할 수 있음

- 시스템이 보안 기능이나 권한 제한에 관한 추천(혹은 보호) 정책을 자동 생성함
- 관리자는 해당 정책을 실제 시스템에 적용하기 전, 보호 방안의 영향을 미리 검토(preview)하고 시뮬레이션함
- 정책의 효과, 예상 변화, 부작용 등을 검증 후 단계적으로 적용(gradual rollout) 가능
- 이를 통해 조직 내 변화관리 및 보안정책 도입의 실효성을 동시에 달성

### 한 명이 구축하던 에이전트의 보안 체계가 이제 수백 대 운영을 전제한 인프라로 확장됨

- 영상 제작자는 자신이 단일 에이전트(두 번째 두뇌)에 적용하던 보안 노하우를 대규모 에이전트 환경으로 확장해야 함을 강조
- 마이크로소프트의 솔루션은 수십~수백 개의 AI 에이전트 조직 운영에 필수적인 중앙 통제와 세분화된 권한 관리 체계를 지원함
- '개인용 툴'에서 '조직 전반 프로세스'로 AI 에이전트 관리의 초점이 이동하고 있음을 시사

### 영상은 마이크로소프트와의 협업 경험이 실제적 보안 대응 방식 설계에 반영되었음을 언급함

- 영상 마지막, 제작자는 본인의 에이전트 구축 경험 및 마이크로소프트와의 파트너십을 언급
- 에이전트 보안 문제는 개인 개발자와 글로벌 IT기업 모두에게 현실적인 과제임을 재조명
- 시청자가 더 깊은 정보를 확인할 수 있도록 관련 링크 제공(설명란 참고 요청)
