## *나는 내 AI 에이전트가 코드를 병합하도록 신뢰하지만, 바로 프로덕션에 반영하는 것은 신뢰하지 않는다* 핵심 요약

- 영상의 주장은 AI 에이전트가 코드 병합(Merge)까지는 자동화할 수 있지만, 프로덕션(실 서비스)에 직접적으로 배포하는 것은 조심해야 한다는 점을 강조함
- AI 소프트웨어 팩토리는 스테이징 환경까지만 자동화하고, 이후 실제 배포 및 검토 단계는 사람이 직접 확인함
- 이유는 현재 테스트와 리뷰가 겉으로 코드가 정상처럼 보이는지만 확인 가능하며, 진짜 효과는 실제 사용자가 접했을 때만 알 수 있기 때문임
- 문제를 최소화하기 위한 오랜 답은 '피처 플래그(Feature Flag)'를 활용해 일부 사용자에게만 코드를 먼저 제공하고, 문제가 생기면 즉시 비활성화하는 방식임
- 하지만 기존에는 엔지니어가 피처 플래그를 수동으로 추가해야 했고, 자동화된 에이전트가 대규모로 PR을 올릴 때 이 과정을 따라가기 어려움
- LaunchDarkly는 실시간 프로덕션 환경에서 피처 플래그로 코드 변경 동작을 제어하는 제품으로, 최근 'Release Autopilot' 기능 출시
- Release Autopilot은 AI 에이전트가 피처 플래그 생성, 위험도 분석, 성공 지표 설정, 카나리 릴리즈, 플래그 정리까지 전 과정을 자동화함
- PR(풀리퀘스트) 단계에 이 모든 것을 제안하며, 실 사용자에 대한 최종 배포 전에 반드시 사람이 승인해야만 실제 반영되는 안전장치 제공
- 이 과정을 통해 엔지니어의 신뢰보다 시스템적인 통제와 단계별 릴리즈, 실시간 검증이 가능해짐
- 영상은 LaunchDarkly와의 협업 하에 이루어졌으며, 관련 링크도 설명란에 제공됨

## 세부 요약 - 주제별 정리

### AI 에이전트에게 코드를 병합까지 맡기지만 프로덕션 반영은 신뢰하지 않는 이유

- 제작자는 자신의 AI 에이전트들이 밤새 코드를 병합하는 것은 신뢰한다고 밝힘
- 그러나, 그 코드가 곧바로 프로덕션 환경(실제 서비스)에 반영되는 것은 신뢰하지 않음
- AI 소프트웨어 팩토리가 자동으로 코드를 병합하더라도, 최종적으로 배포하는 것은 제작자가 직접 확인함
- 에이전트가 수행하는 테스트와 리뷰는 "코드가 겉보기엔 맞아 보인다"는 것만 확인할 수 있음
- 코드 변경의 진짜 영향은 실제 사용자가 그 변화를 경험할 때만 드러남
- 따라서, 스테이징 환경까지 자동화하되 그 다음 단계는 사람이 직접 책임지고 있음

### 코드 변경의 실제 영향은 실사용자에게서만 확인할 수 있음

- 코드의 안정성, 버그 발생 여부 등은 개발 과정에서 전부 예측 불가
- 내부 테스트, 리뷰 과정은 한계가 있어, 실사용자의 실제 반응이 있어야만 진정한 안정성 확인 가능
- "변경의 진짜 효과는 코드가 실제 사용자들 앞에 놓였을 때만 알 수 있다"는 점을 명확히 강조
- 이 때문에 단순히 코드가 통과한 것만으로는 완전한 신뢰 불가

### 피처 플래그를 통한 점진적 배포 방식이 오랜 정답임

- 수년간 해답으로 꼽혀온 방법은 기능(Feature)별 플래그를 걸어, 일부 사용자에게만 새 변경 사항을 작게 릴리즈하는 것
- 코드가 문제 생길 경우, 즉시 그 플래그만 비활성화해 서비스 전체 영향 최소화
- 점진적 배포는 실 사용자 중 일부만을 대상으로 하여 리스크를 효율적으로 관리
- 그러나 이 방법이 매번 손쉽게 적용되지 않았던 현실을 지적

### 피처 플래그 추가 과정의 수동성과 자동화 시대의 과제

- 기존에는 엔지니어가 직접 소스코드에 피처 플래그를 삽입해야만 했음
- 이로 인해 많은 팀이 점진적 배포(스위치) 방식을 완전히 도입하지 못하는 경우 많았음
- AI 에이전트가 대량으로 빠른 속도로 Pull Request를 올릴 때, 플래그 관리와 구현을 사람이 따라가기 힘듦
- 자동화된 코드 생성·변경의 규모가 커질수록 이 문제 심각해짐

### LaunchDarkly는 대규모 피처 플래그 관리와 배포 제어를 지원함

- LaunchDarkly는 코드 변경 사항이 프로덕션에서 어떻게 동작하는지 실시간으로 제어할 수 있는 피처 플래그 서비스임
- 코드를 실제 환경에 배포한 이후에도 플래그를 통해 기능의 활성/비활성을 즉각적으로 제어할 수 있음
- 기존의 수동 플래그 삽입과 달리, LaunchDarkly 시스템은 더 정교한 변동 제어를 가능하게 함

### Release Autopilot는 AI 에이전트의 플래그 작업을 자동화함

- 최근에 LaunchDarkly가 출시한 'Release Autopilot' 기능은, AI 에이전트가 플래그 작업 전체를 자동으로 처리할 수 있도록 지원함
- 에이전트가 올리는 PR 단계에서부터 플래그 래핑을 자동 삽입
- 대규모 자동화된 코드 변경에서도 놓치는 부분 없이 플래그 적용 가능

### 자동 위험도 분류와 피처 플래그 적용 범위 결정 방식

- Release Autopilot의 'Risk Classification'(위험 등급 분류) 기능은 변경사항이 위험한지 자동 분석
- 위험도가 높다고 판단되면 해당 변경은 반드시 피처 플래그로 래핑하도록 조치
- 위험 분석에는 코드 변경의 심각성, 적용 범위, 서비스 영향 등을 실시간 고려

### 성공 지표 및 카나리 릴리즈, 단계적 확장 방식 적용

- 성공 기준(Success Metrics)을 자동으로 정의, 실제 프로덕션 환경에서 어떻게 변화가 측정될지 설정
- 자동 릴리즈 플랜에 따라 먼저 일부 사용자(카나리 그룹)에 제한적으로 변경사항을 배포
- 예상 범위 내에서 문제가 없을 때만 점진적으로 전체 사용자로 확대
- Guard Rail(보호선) 내에서만 확장하며, 문제 발생 즉시 확산 중단 가능

### 실시간 피처 수준 모니터링과 플래그 정리 기능 제공

- 'Feature Level Observability'(피처 단위 관찰성): 실시간으로 각 변경사항의 서비스 내 반영 상태를 추적
- 각 피처별로 프로덕션 신호와 비교하여 이상 여부를 즉각 판별
- 'Flag Cleanup'(플래그 정리): 프로덕션에 반영된 코드에서 불필요해진 플래그를 자동 측정, 정리하여 코드베이스를 깔끔하게 유지

### 최종 반영은 반드시 사람의 승인 뒤에만 적용됨

- 완전한 자동화가 아닌, PR 단계에서 AI 에이전트가 제안한 플래그 생성 및 배포 계획이 명시적으로 표기됨
- 실제로 코드의 릴리즈(배포)는 반드시 사람이 승인해야지만 최종 반영 가능
- 이렇게 함으로써 "에이전트를 더 신뢰해야만 하는 상황"이 아니라, 프로세스와 단계별 검증으로 시스템적 안전성 확보
- 실 사용자 대상 소규모 테스트를 거쳐 전체 릴리즈가 이루어지기 때문에, 원치 않는 변경의 위험을 최소화할 수 있음
- 영상 마지막 부분에서 LaunchDarkly와의 협업을 밝히고, 자세한 내용은 설명란 링크를 통해 안내함
