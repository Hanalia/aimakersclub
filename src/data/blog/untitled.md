## *당신의 코딩 에이전트는 치명적인 블라인드 스팟을 가지고 있다 (이걸 반드시 고쳐야 한다)* 핵심 요약

- 코딩 에이전트가 실제 프로덕션 환경에서 빈번하게 예기치 않게 실패하는 사례가 존재함
- 최근 메일 초안 작성을 담당하는 에이전트를 배포했으나, 사전 평가를 모두 통과했음에도 첫 실전 운영에서 심각한 오류가 발생함
- 도구 호출 없이 미처리 메일 2개를 "처리 필요 없음"으로 잘못 판단하는 등, 명확한 에러 없이 실질적 문제를 일으킴
- 코드상에는 문제의 원인이 명확히 드러나 있지 않아, 실제 운영 중 동작을 모니터링하다가 7분 만에 문제를 발견하고 수정함
- AI 코딩 에이전트는 코드 전체를 읽을 수 있지만, 실제 실행 시 내부에서 무슨 일이 일어나는지 직접 확인하지 못하는 치명적인 한계(블라인드 스팟)를 가짐
- 이 한계를 해소하기 위해 Dinatrace MCP 서버 같은 도구를 활용하면, 운영 데이터를 IDE 내 에이전트에게 직접 제공하여 실시간으로 문제 파악과 진단이 가능해짐
- Dinatrace 예시에서는 약 89초의 응답시간을 가진 앱을 실시간 데이터 기반으로 분석하고, 과부하를 유발한 데이터베이스 메서드 TOP 5를 도출함
- 원인 메서드를 소스코드 상의 정확한 라인까지 추적하여, 단순 인덱스 추가로 애플리케이션 코드 변경 없이 문제를 해결할 수 있음을 보여줌
- 실제 코드만 보면 일반적인 검색 쿼리로 보이지만, 실측 데이터가 있어야만 고성능 저하 원인을 진단 가능함
- 코딩 에이전트가 코드 실행 시 실제 동작을 "직접 볼 수 있는" 방법을 반드시 마련해야 함
- Dinatrace 링크는 영상 설명란에 제공하며, 이 영상은 Dinatrace의 후원을 받아 제작되었음

## 세부 요약 - 주제별 정리

### 실제 프로덕션 환경에서는 코딩 에이전트가 반복적으로 예기치 못한 문제를 일으킴

- 영상 제작자는 직접 개발 및 운영 중인 AI 코딩 에이전트가 여러 차례 실패했다고 설명
- 특히 "수십 번"이나 실무 환경에서 문제가 발생했다고 밝힘
- 이러한 실패 중 일부는 "굉장히 곤란하고 창피한 방법"으로 나타났다고 고백
- 실패의 거의 대부분이 사전 예상이나 코드 분석만으로 파악하기 어려운, 에이전트의 블라인드 스팟과 관련 있음

### 사전 테스트(이벌류에이션)를 통과해도 실전에서는 예상치 못한 버그가 드러남

- 최근 새로운 버전의 '이메일 초안 작성' 에이전트를 배포함
- 이는 'AI 세컨드 브레인'의 일부로, 이메일 자동 초안을 작성하는 역할을 담당
- 이 에이전트는 사내의 모든 평가(이벌류)를 통과한 상태에서 운영에 투입됨
- 첫 실전 운영(run)에서, 미답변 이메일 2개가 있었음에도 불구하고, 도구(tool)를 전혀 호출하지 않고 "처리할 필요 없음"이라는 잘못된 판단을 내림
- 이 과정에서 충돌(crash)이나 에러(error) 메시지는 전혀 발생하지 않음
- 코드베이스 상에는 해당 문제의 단서를 찾기 어려웠고, 에이전트가 스스로 문제를 인식하지 못함

### 문제는 오직 실제 운영 상황을 직접 관찰했을 때에만 발견할 수 있었음

- 영상 제작자는 운영 중인 에이전트의 실제 동작을 "직접 관찰(watch the actual run)"하는 방식으로만 문제를 포착했음
- 코드를 분석하거나 로그만 살펴서는 문제를 발견할 수 없었음
- 문제 원인을 발견하고 나서는 실제로 "7분 만에" 신속하게 수정할 수 있었음
- 이는 "AI 코딩의 블라인드 스팟"이 실제 실행시 내부 동작을 모니터링하지 못하는 점임을 강조

### 코딩 에이전트는 코드 전체를 읽을 수 있지만 ‘실행 중 동작’을 볼 수 없다는 근본적 한계가 있음

- 현재의 코딩 에이전트는 파일/코드베이스 전체를 인식하고, 코드 로직도 파악함
- 그러나 실제 코드가 운영 환경에서 어떤 방식으로 동작하는지에 대한 정보는 제공받지 못함
- 이 한계를 영상에서는 "에이전트가 실제로 실행 중 무엇이 일어나는지 볼 수 없다"고 요약
- 이는 버그 감지, 성능 이슈 진단 등 실무적 업무에서 치명적일 수 있음

### Dinatrace MCP 서버는 운영 데이터와 소스코드 분석을 연결하는 솔루션을 제공함

- 영상에서는 Dinatrace MCP 서버의 구체적인 워크스루(사용 예시)를 소개
- Dinatrace는 운영 중 발생한 데이터를 실시간으로 IDE 속 코딩 에이전트에게 직접 전달
- 이를 통해 에이전트가 실제 운영 환경에서 무슨 일이 일어나는지 알 수 있음

### Dinatrace 예시에서는 실시간 데이터 기반으로 광범위한 성능 문제를 신속하게 진단함

- 예시 앱에서는 응답 시간이 약 89초에 달해 심각한 성능 저하 문제를 안고 있음
- Dinatrace를 통해 "어떤 메서드들이 데이터베이스에 가장 많은 부하를 주는지" 에이전트에게 질의함
- 에이전트는 실측 텔레메트리 데이터를 바탕으로, 데이터베이스 호출이 많은 상위 5개 메서드 목록을 응답하며, 부하 순위까지 분석

### 실제 문제 원인은 앱의 특정 쿼리가 모든 테이블 행을 매 호출마다 읽는 구조에서 발생함

- 에이전트는 소스 코드를 분석하여 데이터베이스 과부하의 근본적인 원인을 추적
- 가장 많은 부하의 원인은 "매 호출마다 테이블의 모든 행을 조회하는 쿼리"로 판단 
- 코드상에서는 무난한 검색 쿼리로만 보이나, 실측 데이터와 결합해야 문제점이 명확하게 드러남

### 단순 인덱스 추가만으로도 근본적인 성능 문제가 해결됨을 확인함

- Dinatrace 솔루션 기반 에이전트는 문제 라인까지 pinpoint하여 알려줌
- 근본적 해결책으로 "애플리케이션 코드 수정 없이 인덱스를 추가"하는 방법을 제시
- 불필요한 코드수정 없이 정밀 진단과 빠른 대응이 가능함을 시연

### 실시간 운영 데이터는 AI 코딩 에이전트 활용의 핵심적인 요소임을 강조함

- 아무리 정교한 코딩 에이전트라 해도, 실행 중 실제 동작을 볼 방법이 없으면 치명적 한계를 가진다고 지적
- 운영 데이터(실시간 성능, 호출 횟수, 로깅 정보 등)와 소스코드 분석이 결합되어야만 구조적 버그 및 퍼포먼스 병목을 정확하게 잡을 수 있음
- 코딩 에이전트를 더욱 효과적으로 활용하려면 "실행중인 코드의 실질 동작"을 관찰할 수단이 반드시 필요하다고 강조

### Dinatrace 관련 링크 및 영상 후원사를 영상 설명에 안내함

- Dinatrace에 대한 추가 정보 및 MCP 서버 활용 안내는 영상 설명란 링크를 통해 제공함
- 해당 영상이 Dinatrace의 협찬을 받아 제작됐음을 투명하게 안내
