## *프롬프트 인젝션은 AI 에이전트 보안의 시작에 불과하다 (당신이 필요한 것은 이것)* 핵심 요약

- 영상은 AI 에이전트를 다양한 시스템 운영과 데이터 관리에 활용할 때, 보안이 매우 중요하다는 점을 강조함
- 필자는 개인적으로 '마인드 세컨드(두 번째 두뇌)'라는 AI 에이전트를 사용하면서, 민감한 시스템 접근 권한을 부여하는 것의 위험성을 깨달음
- AI 에이전트가 외부 데이터에서 예상치 못한 지시(Prompt Injection)를 받아, 사용자가 의도하지 않은 행동을 할 수 있음
- 프롬프트 인젝션 방지를 위해, 실제 LLM(대형 언어 모델)에 연결되기 전 단계에서 내부 보안 검사와 접근 제한을 설계함
- 개인 레벨에서는 자신이 직접 만든 에이전트이기 때문에 통제가 가능하지만, 기업에서는 대규모의 에이전트들이 근무자 단말기 및 클라우드에 분산되어 있어 보안 관리가 복잡해짐
- IT 부서는 현재 에이전트의 종류, 소유자, 각 에이전트의 접근 권한을 정확히 파악해야 하는 어려움을 겪음
- 이를 해결하기 위해 마이크로소프트가 Agent 365 및 Project Perception을 통해 에이전트 신원 부여, 접근 범위 관리, 위험도 기반 접속 제어 등 기업 보안 강화 솔루션을 제공함
- Project Perception은 에이전트별 권한 및 리스크를 시각화해 보안 취약점을 알려주고, Guardian Agent가 수많은 에이전트들의 리스크 분석과 통합적 대응을 돕도록 지원함
- 동적 권한(Dynamic Permissions), 리스크 기반 접근 제어 등으로 각 에이전트가 제한적이고 일시적으로만 권한을 갖도록 제어 가능
- 모든 변경사항에 대해 팀이 직접 영향도를 검토하고, 점진적 도입 단계를 거칠 수 있도록 설계되어 엔터프라이즈 운영에서의 대규모 안전 관리를 가능케 함

## 세부 요약 - 주제별 정리

### AI 에이전트 사용은 보안 위험을 내포하며 프롬프트 인젝션이 주요 위협으로 대두됨

- 영상 제작자는 자신의 '마인드 세컨드'라는 AI 기반 업무 관리 도구로 다양한 시스템과 데이터를 관리함
- 에이전트에게 주요 시스템 및 민감 데이터에 대한 접근 권한을 부여하면 편리하지만, 동시에 잠재적 보안 위협이 수반됨
- 외부 데이터나 정보가 해당 에이전트에게 전달될 경우, 예상하지 못한 명령(프롬프트 인젝션)을 통해 사용자가 요청하지 않은 동작이 실행될 소지가 있음
- "프롬프트 인젝션"은 AI 시스템 보안상의 새로운 공격 벡터로 부상 중임

### 개인 에이전트 보안은 직접적인 제어와 사전 방어 조치가 가능함

- 필자는 자신의 에이전트에 대해 다양한 보안 검증 절차를 설계해 적용함
- 외부 입력이 LLM(대형 언어 모델)로 도달하기 전, 모든 요청을 점검하는 보안 필터를 구축함
- 또한, 필수적인 시스템이나 데이터에 한해서만 에이전트가 접근하도록 강하게 제한함
- 이런 조치는 개인 수준에서는 자율적으로 관리 및 적용 가능함

### 기업 환경에서는 수많은 에이전트와 분산된 기기의 관리가 어렵고 복잡함

- 기업 내에는 수백, 수천 개의 다양한 AI 에이전트가 존재할 수 있음
- 이들 에이전트는 각기 다른 직원 PC, 기업 클라우드 등에서 실행됨
- IT 부서는 모든 에이전트의 종류, 소유자, 접근 권한을 지속적으로 파악하고 관리해야 하는 과제를 안고 있음
- 기존 방식으로는 프롬프트 인젝션을 포함한 새로운 위협을 체계적으로 통제하기 어려움

### 마이크로소프트는 Agent 365와 Project Perception을 통해 보안 문제 해결을 시도함

- 마이크로소프트의 Agent 365 및 Project Perception은 AI 에이전트의 대규모, 체계적 보안 관리 솔루션으로 소개됨
- 각각의 에이전트에 개별적인 '신원(Identity)'를 부여하여, 소유자와 권한 범위를 명확히 함
- 임무 단위로 권한을 한시적으로 제한하며, 환경 변화(예: 위협, 위험 수준 변화)에 따라 필요한 조치가 자동 적용됨

### 권한 관리와 보안 제어의 자동화로 대규모 에이전트 관리 문제를 해결함

- 동적 권한(Dynamic Permissions)은 에이전트가 단일 작업을 위해 필요자원에 한해 한시적으로 제한된 접근권을 부여하도록 함
- 위험 기반 접근 제어(Risk-based Access Controls)는 단순 로그인이 아니라, 에이전트의 실제 작업 및 정책 변화 상황에 따라 추가 검증 및 제한이 작동함
- 마이크로소프트 Guardian Agent 등 전용 AI 에이전트 관리도구가, 일일이 개별 사건을 조사하지 않고 한 번에 전체 위험을 관리하도록 도와줌

### Project Perception의 '에이전트 인사이트'가 기업 보안의 취약점을 가시화함

- Project Perception에서는 '에이전트 인사이트(Agent Insights)'라는 시각적 분석 도구로 에이전트 권한 및 보안 취약점을 한눈에 확인 가능
- 기존 보안 정책에서 놓치는 부분을 식별해, 추가적인 통제가 필요한 지점을 제안함
- 에이전트 유형, 권한 범위, 실제 활용 내역 등이 통합적으로 모니터링됨

### 변화 적용 전 실제 영향도를 팀이 꼼꼼히 검토하여, 운영 안정성을 보장함

- 기업 관리자는 제안된 보안 변경 사항에 대해 사전에 영향도 분석 및 검토가 가능함
- 실무자 검토 후, 제한적인 범위에서 먼저 적용(점진적 도입)하고, 이상이 없을 경우 전사적으로 확대해 보안을 강화함
- 철저한 사전 검토 및 점진적 롤아웃 방식이 대규모 조직에서도 에이전트 관련 보안 위험을 최소화함

### 필자의 개인 경험과 마이크로소프트 솔루션의 차별점이 대조적으로 설명됨

- 필자는 직접 구축해 통제하는 한 명의 AI 에이전트를 위해 보안 대책을 마련했으나, 마이크로소프트는 수백 개 에이전트에 동일한 수준의 통제를 대규모로 적용하는 방식을 제안함
- 기업 현장에선 신속한 확장성과 탄탄한 보안 프로세스가 병행되어야 함을 의미함

### 영상의 결론은 기업 현장에서 AI 에이전트 보안이 체계적으로 관리되어야 함을 시사함

- 프롬프트 인젝션 등 신종 위협에 대응하려면, 단순한 사용자 수준 보안 통제를 넘어 기업 차원의 고도화된 시스템이 필요함
- 마이크로소프트의 Agent 365, Project Perception, Guardian Agent는 대규모 AI 에이전트 관리를 위한 중요한 솔루션임
- 복잡한 에이전트 환경이 일반화됨에 따라, 최신 접근 제어, 위험 분석, 점진적 보안 적용 방식 등이 필수적으로 요구됨
