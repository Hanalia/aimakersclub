## *프롬프트 인젝션은 AI 에이전트 보안의 시작일 뿐이다 (당신에게 필요한 것을 소개)* 핵심 요약

- 영상은 AI 에이전트와 시스템 통합 시 발생하는 '프롬프트 인젝션(prompt injection)' 위험을 소개함
- 제작자는 '두 번째 두뇌(Second Brain)' 체계를 구축하여 개인의 업무 효율화에 활용하며, 외부 시스템과 데이터 접근이 필수적임을 언급
- 프롬프트 인젝션이란 AI가 외부 데이터에서 악의적 명령을 읽고 예기치 않은 동작을 할 수 있는 위험을 의미함
- 개인 분야에서는 수많은 보안 점검(체크) 및 권한 제한을 직접 설정해 대응하고 있음
- 대기업 환경에서는 수백 개의 AI 에이전트가 다양한 클라우드 및 직원 기기에서 작동하며, IT 부서가 각각의 에이전트와 권한, 접근 범위를 파악하기 어려움
- 마이크로소프트는 Agent 365, 프로젝트 Perception을 통해 조직 내 에이전트의 '신원' 부여, 접근 영역 제한, 위험 변화에 따른 제어 기능 등 솔루션을 제공함
- 새로운 '에이전트 인사이트' 기능을 통해 현재 보안 통제가 허점(취약점)을 남기는 지점과 위험 관리 현황을 시각적으로 파악 가능함
- Guardian 에이전트가 팀 전체에 걸친 리스크 대응을 지원하며, 동적 권한 관리 및 정책 기반 접근 통제로 보안 수준을 높임
- 권한 지급은 시간 단위, 특정 과업 단위 등 매우 세밀하게 제어할 수 있고, 기존 직원의 권한 구조에는 영향을 미치지 않음
- 모든 변경은 팀의 검토 후 점진적(gradual)으로 도입할 수 있음

## 세부 요약 - 주제별 정리

### AI 에이전트가 외부 데이터에서 원치 않는 명령을 받을 수 있는 위험이 꾸준히 존재함

- 영상 제작자는 자신의 두 번째 두뇌(Second Brain)를 통해 다양한 업무를 자동화하고 있음
- 이러한 AI 에이전트를 사용하려면 여러 시스템과 데이터에 접근 권한을 부여해야 함
- 프롬프트 인젝션(prompt injection)은 AI가 외부에서 받은 데이터에 악의적 명령어가 포함되어 있을 때, 사용자가 의도하지 않은 명령이 실행될 수 있는 취약점임
- 예를 들어, AI가 읽는 문서나 메일에 은닉 명령이 삽입되어 AI가 이를 잘못 수행할 수 있음
- 이런 위험은 개인 자동화뿐 아니라 조직 전체에서 중요한 문제로 대두됨

### 제작자는 AI 에이전트에 다중 보안 점검 및 권한 제한을 직접 구현하여 위험을 예방함

- 제작자는 실제 두 번째 두뇌 시스템에서 모든 수신 데이터가 대규모 언어 모델(LLM)에 전달되기 전, 자체적인 보안 체크로 위험여부를 검증함
- 시스템의 각 부분에 보안장치를 삽입해 외부에서 들어오는 모든 입력을 점검함
- AI 에이전트의 접근 권한은 '최소한의 필요 범위'로 한정하여 허용함
- 이 방법은 제작자가 모든 프로세스를 직접 개발하고 여러 보안 컨트롤을 운영하기 때문에 가능한 것임

### 대기업의 AI 에이전트 도입 환경에서는 수백 개의 에이전트 관리와 통제가 어려워짐

- 개인 개발 환경과 달리, 기업에서는 수많은 AI 에이전트가 동시에 운영되어 복잡성이 극대화됨
- 에이전트는 클라우드, 개별 직원 기기 등 여러 장소에 분산되어 있음
- IT 부서는 다음 사항을 파악해야 함:
    - 어떤 에이전트가 존재하는지
    - 그 에이전트의 주(소유자)는 누구인지
    - 각 에이전트가 무엇에 접근 가능한지
- 수시로 생성·변경·삭제되는 에이전트의 생애주기 전체를 파악하고 통제하는 것이 어려움

### 마이크로소프트는 Agent 365와 프로젝트 Perception을 통해 기업용 AI 에이전트 관리를 체계적으로 지원함

- 마이크로소프트는 이 복잡한 에이전트 환경에 대응하는 특화 솔루션을 도입
- Agent 365 및 프로젝트 Perception이 대표적임
- 이 솔루션들은 각 에이전트에 '고유 신원(Identity)'을 부여하여 관리의 체계성을 높임
- 에이전트별로 명확히 권한을 지정하고, 실제 필요한 임무 범위 내에서만 접근을 허용함
- 위험 상황 변화에 따라 손쉽게 권한과 정책을 수정하고, 즉각 반영 가능함
- 이 과정에서 기존 인사 및 직무 권한 체계는 건드리지 않으므로 직원의 기존 권한과 충돌이 없음

### 프로젝트 Perception의 '에이전트 인사이트'로 보안 통제의 허점을 진단할 수 있게 됨

- 프로젝트 Perception의 '에이전트 인사이트(Agent Insight)' 기능을 제공함
- 이 기능은 현재 보안 정책이 빠져 있는 허점(Gap), 통제가 약한 부분, 위험도 높은 영역을 자동으로 식별해 줌
- 에이전트별·업무별 취약점, 권한 부여 현황, 미흡한 관리지를 한눈에 파악 가능
- 이를 통해 IT 팀은 단순 개별 건 단위가 아닌, 전체 에이전트 계층에서 체계적인 위험 관리를 수행함

### Guardian 에이전트가 전사적인 에이전트 위험 대응과 분석을 효율화함

- 프로젝트 Perception 내 Guardian 에이전트가 도입됨
- Guardian 에이전트는 개별 에이전트의 이슈 분석 뿐 아니라, 조직 내 전체 에이전트의 통합 리스크 관리가 가능하게 함
- 단일 사고, 개별 이벤트 대응 방식을 넘어서 전체 에이전트 환경을 동시에 살핀다는 강점이 있음

### 동적 권한 관리 및 과업 단위의 제한이 AI 에이전트 보안 수준을 대폭 향상시킴

- 에이전트 권한은 고정적이 아니라, 과업이나 목적별로 동적으로 부여(동적 권한, Dynamic Permission)됨
- 예: 특정 자원에 대한 접근은 "2시간 동안만", "특정 프로젝트에 대해서만" 허용하는 구조
- 이로써 불필요하게 넓은 권한, 오랜 기간의 권한 할당 등 기존 보안 취약점을 해소함

### 위험 기반의 접근 통제가 로그인 이외의 행동에도 실시간으로 적용됨

- 권한과 접근 제어는 단순 로그인 시점에만 적용되는 것이 아님
- 에이전트의 실시간 행동, 요청 등 매 순간 기존 정책과 위험 수준을 기준으로 평가됨
- 위험도가 높다고 판단되면 즉각 권한 제한 또는 행위 차단이 이뤄짐
- IT 팀은 각 권한 및 정책 적용 효과를 미리 미리 확인(preview)하고, 정식 도입 전 점진적(gradual rollout)로 시행 가능함

### 제작자는 단일 에이전트에 적용한 기법을 수백 개 에이전트로 확장하는 마이크로소프트의 시스템에 협력함

- 제작자는 자신이 한 에이전트에 적용했던 보안 점검과 권한 제한 경험을 언급
- 이러한 방식을 기업 내 '수백' 개의 에이전트에 확장 적용 가능하게 한 것이 마이크로소프트의 솔루션임
- 제작자는 마이크로소프트와 협업하였으며, 이 접근 방식 및 시스템에 대한 추가 자료 링크를 영상 설명에 첨부할 예정임
