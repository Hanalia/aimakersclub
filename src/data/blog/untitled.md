## *나는 AI 에이전트가 코드를 병합하는 것은 믿지만 프로덕션으로 바로 배포하는 것은 신뢰하지 않는다* 핵심 요약

- 코드를 AI 에이전트가 밤새 자동으로 병합하게 할 수는 있지만, 프로덕션(실사용 환경)으로 직접 배포하는 것은 신뢰하지 않음
- 현재 AI 소프트웨어 공정은 스테이징(staging) 환경까지만 자동화되며, 이후 실제 배포 전에는 사용자 직접 검토가 필수
- AI가 실행하는 테스트와 리뷰는 코드가 ‘정상적으로 보이는지’만 확인하며, 실제 사용자 환경에서의 영향은 알 수 없음
- 수년간 사용된 방법은 기능 플래그(feature flag) 뒤에 변경사항을 감추고 일부 사용자에게만 제공하면서 모니터링하는 방식
- 기존에는 엔지니어가 직접 플래그를 추가해야 했기 때문에 실제로 활용되지 않는 경우가 많았음
- AI 에이전트가 대량으로 풀리퀘스트를 생성할 때 이러한 프로세스를 수작업으로 관리하기는 어려움
- Launch Darkly의 '릴리즈 오토파일럿(Release Autopilot)'은 에이전트가 기능 플래그 작업까지 자동화하여 배포 위험을 줄임
- 이 서비스는 변경의 위험도 판단, 성과 지표 설정, 단계별 자동 릴리즈, 실시간 관측, 플래그 정리까지 모두 자동 수행
- 실제 변경 반영 전에는 반드시 사람이 최종 승인해야 하므로 완전히 자동화된 구조가 아닌, 신뢰성을 유지함
- Launch Darkly의 협력으로 제작됐으며, 관련 링크가 영상 설명란에 있음

## 세부 요약 - 주제별 정리

### AI 에이전트가 코드 병합은 자동화하지만 프로덕션 배포는 신뢰할 수 없다고 판단함

- AI 에이전트들이 밤새 코드를 자동으로 병합하는 것은 가능하다고 밝힘
- 하지만 이 코드 변경사항을 생산(프로덕션) 환경에 바로 배포하는 것까지는 신뢰하기 어렵다고 강조
- 이유는 자동 테스트와 리뷰만으로는 실제 변경이 미칠 영향까지 완전히 검증할 수 없기 때문임

### AI 소프트웨어 공정의 자동화 범위는 스테이징 환경에서 멈춘다고 설명함

- “나의 AI 소프트웨어 공장은 스테이징 환경까지만 자동화된다”고 언급
- 그 이후, 실제 배포(프로덕션 반영) 전 단계에서 직접 점검하는 절차를 유지한다고 밝힘
- 에이전트가 실행하는 자동화 리뷰와 테스트는 코드의 정합성을 확인하는 수준에 머무름

### 실제 사용자 앞에서만 코드 변경의 영향이 온전히 드러남을 지적함

- “코드가 실제 사용자 앞에 나가기 전까지는 변화의 진짜 효과를 알 수 없다”는 점을 강조
- 테스트 통과만으로는 부족하고, 실제 프로덕션 환경에서 예측치 못한 문제가 발생할 수 있음을 언급

### 과거부터 기능 플래그가 점진 릴리즈의 해법으로 제시되어 왔음을 설명함

- 수년 전부터 널리 사용된 답은 “변경사항을 기능 플래그(feature flag)” 뒤에 숨기는 것임
- 이렇게 하면 소수 사용자 집단에게만 변경사항이 노출되고, 문제가 발생하면 즉시 플래그를 끄는 방식으로 대응 가능

### 기능 플래그 수동 추가의 한계로 인해 실제 현장 적용은 제한적이었음

- 기능 플래그는 엔지니어가 직접 코드에 삽입(수동 추가)해야 했다고 설명
- 번거로움 때문에 많은 팀이 이 방식을 완전하게 적용하지 못했다고 지적
- 팀 규모가 커지고, AI 에이전트가 대량의 풀리퀘스트를 생성하는 시대에는 수작업으로 일일이 관리하기 거의 불가능

### Launch Darkly가 AI 시대에 맞는 자동화된 기능 플래그 배포 관리 솔루션을 제안함

- Launch Darkly는 프로덕션에 실제 적용된 후에도 변경 동작을 세밀하게 조정하고 통제할 수 있게 돕는 서비스임
- 이 서비스가 제공하는 ‘릴리즈 오토파일럿(Release Autopilot)’ 기능을 소개

### 릴리즈 오토파일럿가 기능 플래그 주입, 위험도 평가, 자동 릴리즈, 관측까지 모두 자동화함

- AI 에이전트가 직접 기능 플래그 관련 작업(삽입, 설정 등)까지 자동 지원
- 변경의 위험도를 자동 분류(risk classification)해, 위험성이 높으면 플래그로 감싸도록 자동 처리
- 핵심 성과 지표(success metrics)를 설정해, 프로덕션에 배포될 변경 사항의 성능을 측정
- 자동 릴리즈 플랜 수립: 변경은 소수 사용자(카나리 릴리즈)에게 먼저 전달, 상태가 양호해야 점진적 확장

### 실시간 관측과 플래그 정리 작업도 자동화되어 위험 관리가 체계적으로 이뤄짐

- 각 코드 변경마다 라이브 프로덕션 신호를 기반으로 변동 사항을 모니터링(feature level observability)
- 오래된 플래그, 불필요한 플래그는 깔끔하게 정리(flag cleanup)하는 작업까지 자동화

### 최종 배포에 앞서 엔지니어의 승인 절차가 남아 신뢰성을 높임

- 모든 변경 사항에 대해 기능 플래그 적용(제안)이 풀리퀘스트 상에서 명확히 드러남
- 실제 프로덕션에 반영되기 전, 반드시 엔지니어가 승인해야지만 배포가 완료됨
- “AI 에이전트를 더 강하게 신뢰할 필요는 없다. 모든 변경은 실사용자에게 배포 전에 사람이 최종 승인한다”고 강조

### Launch Darkly의 협업을 영상 제작자가 명시하고 링크를 안내함

- 영상 말미에 Launch Darkly와의 협업임을 밝힘
- 서비스 링크가 영상 설명란에 있다고 안내함
