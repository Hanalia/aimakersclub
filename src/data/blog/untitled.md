## *코딩 에이전트가 코드를 찾는 데 과도한 토큰을 소모하는 문제와 그 해결책* 핵심 요약

- 이 영상은 코딩 에이전트(Coding Agent)가 코드 수정을 요청받았을 때 실제로 많은 토큰을 소모하는 과정을 분석함
- 코드의 실질적 작성을 위해 토큰이 쓰이는 것이 아니라, ‘어떤 코드를 바꿔야 하는지 찾는 과정’에서 다량의 리소스와 토큰이 소비됨을 지적
- 검색(Search) 자체는 빠르고 비용이 싸지만, 검색결과로 나오는 파일들을 모두 읽는 과정에서 컨텍스트(토큰)가 급증함
- 코딩 에이전트가 모든 관련 파일을 읽어야 한다는 구조적 한계는, 코드의 명칭이 다르거나 예상과 다르면 중요한 부분을 쉽게 놓치게 함
- 사실상 에이전트는 ‘어떤 파일/코드가 이 변경 요청과 연관되어 있나?’라는 질문에 대답하기 위해 많은 토큰을 소모함
- 이 비효율을 극복하기 위한 방법으로 Sonar Vortex 도구를 상세히 소개
- Sonar Vortex는 코드베이스 내에서 클래스/인터페이스/함수 호출 등을 파일과 행 단위까지 즉각 파악해주는 그래프 기반 툴임
- Sonar Vortex 적용 전후 토큰 사용량을 비교한 결과, 80,000 토큰에서 크게 절감되는 등 6~34%의 토큰 절감 효과가 입증됨(SONAR 자체 연구)
- 해당 세만틱 네비게이션 기능은 Java, C#, JavaScript, TypeScript, Python, Rust 등 다양한 언어를 지원
- 이 도구는 SonarQube Cloud에서 Sonar Agent Essentials Add-on과 함께 구동되며, 영상 설명에 링크 제공
- Sonar와의 협업을 통해 도구를 테스트하고 관련 데이터를 제공함

## 세부 요약 - 주제별 정리

### 코딩 에이전트는 코드 작성이 아니라 코드 식별에 더 많은 토큰을 소모한다는 점이 문제로 드러남

- 코딩 에이전트 사용 시 비용의 대부분은 코드 작성을 위한 것이 아니며, 실제로는 적합한 코드를 찾는 데 소모됨
- 간단한 변경이 아닌 실제 업무를 지시할 경우, 에이전트는 엄청난 양의 파일을 검색해 적합한 부분을 찾으려 함
- 이 과정에서 단순 검색은 빠르지만, 검색된 다수의 파일/코드 내용을 하나하나 읽거나 분석해야 하며, 이 때문에 컨텍스트(즉, 토큰)가 기하급수적으로 필요함
- 사용자는 “수정이 필요한 코드가 어디에 있는지” 라는 정보를 답해야 하나, 현 시스템은 이를 효율적으로 지원하지 못함

### 코드 검색 과정의 한계로 인해 변경이 제대로 반영되지 않는 리스크가 존재함

- 검색(Search)은 항상 일종의 ‘추측’(Guess)에 기반하고 있음
- 만약 바꿔야 할 코드가 다른 식별자나 명칭을 사용한다면, 에이전트가 이를 인식하지 못하고 놓치게 됨
- 결과적으로, 수정은 검색이 식별한 코드에는 적용되나, 그 외 숨은(덜 명확한) 지점은 반영되지 않을 가능성
- 따라서 단순히 “찾은 부분”만 바꿔서는 충분하지 않다는 구조적 한계가 존재

### 사실상 코딩 에이전트는 ‘관련 코드 식별’이라는 단일 질문을 위해 많은 자원을 소비함

- 동작 원리를 근본적으로 보면, 에이전트는 “사용자 요구에 맞춰 변경해야 할 코드가 무엇인가?”라는 질문에 미리 답해야 함
- 그러나 이를 직접적·효율적으로 처리할 수 있는 시스템적 지원이 부족함

### Sonar Vortex는 코드베이스 내 코드 관계를 빠르고 정확하게 학습하여 토큰 소모를 획기적으로 줄여줌

- Sonar Vortex는 Sonar가 시장에 내놓은 새로운 도구로, 코드베이스 내 패턴·관계·호출 구조 등을 미리 분석해 데이터 그래프로 구축함
- 이 구조 덕분에 예를 들어 “어떤 클래스가 이 인터페이스를 구현하고 있는가?”, “이 함수를 어디서 호출하고 어떤 파일/라인과 연결되는가?” 등의 질의를 즉시 파악할 수 있음
- 검색이 아니라 ‘직접 쿼리’ 방식으로 보다 신속하게 관련 코드를 탐색함

### Sonar Vortex 적용 후 동일한 과제에서 토큰 사용량이 대폭 절감되는 효과가 나타남

- 영상 제작자는 실험을 통해, 기존 방식으로는 단 한 차례의 파일/코드 소팅 작업에서만 무려 80,000 토큰이 소모되었음을 확인
- Sonar Vortex를 적용한 후, 동일한 과제에 대해 훨씬 적은 토큰으로 원하는 코드 위치 및 컨텍스트를 얻을 수 있었음
- 추가적인 프롬프트를 통한 질의 시에도 토큰 절감 효과가 유지됨
- Sonar의 공식 연구 결과, 6건의 리팩토링 작업을 10회씩 반복 수행한 결과 토큰 소비가 평군 6~34%까지 줄었음을 입증

### Sonar Vortex는 주요 언어를 지원하며 실시간 그래프 업데이트로 빠른 코드 분석이 가능함

- 지원 언어: Java, C#, JavaScript, TypeScript, Python, Rust
- 그래프 구축 및 쿼리 처리는 개발자 로컬PC에서 이뤄짐
- 별도의 컴파일러나 언어 서버 없이, 코드 변경이 감지되면 1밀리세컨드 이내에 그래프가 업데이트됨
- 이는 전체 코드베이스가 아직 컴파일되지 않은 상태(에이전트 작업 중)에도 즉각적인 분석이 가능하다는 장점

### Sonar Vortex는 SonarQube Cloud 환경에 Agent Essentials Add-on과 함께 적용되며, 사용자는 실제 링크를 통해 바로 접속 가능함

- 영상 제작자는 Sonar와의 협업 하에 Sonar Vortex를 테스트하였음
- Sonar Vortex 공식 정보 및 사용법 문서 링크는 동영상 설명란에 포함되어 있음

### 정밀한 코드 식별 도구의 도입이 에이전트 기반 개발 자동화의 효율성을 크게 개선함을 실증함

- 기존 방식에서는 코드 검색과 파일 열람이 토큰 소모의 주범이라는 구조적 문제를 구체적으로 짚음
- Sonar Vortex 같은 세만틱 네비게이션 도구를 통한 구조적 개선은, 오픈AI 기반 코딩 자동화·에이전트 등 실무에 바로 적용 가능함을 실험을 통해 보여줌

### 본 영상은 Sonar Vortex 도입으로 실제 토큰·비용 절감 사례와 실시간 코드 분석의 장점을 명확하게 시연함

- 직접 대비를 통해 Sonar Vortex 도입 시 토큰 감소 및 업무 효율성 증대를 객관적으로 검증
- Sonar Vortex 및 관련 기술은 향후 코드베이스를 다루는 자동화 분야의 핵심 도구임을 시사

### 영상의 모든 구체적 데이터, 예시, 수치는 실제 실험과 Sonar의 공식 리포트에서 인용됨

- 80,000 토큰 실사용 예시, 6~34% 절감 수치, 지원 언어, 실시간 그래프 갱신 지연(1ms), 실용적 사용 환경 등의 정보가 모두 실제 데이터 기반임
- Sonar와 영상 제작자 간 협업을 통해 수치와 실험이 교차 검증됨
