## *프롬프트 인젝션은 AI 에이전트 보안의 시작일 뿐이다 (여기에 필요한 것이 있다)* 핵심 요약

- 영상은 사용자가 AI 에이전트(“두 번째 두뇌”)에 다양한 작업과 시스템, 데이터 접근 권한을 위임함으로써 야기되는 보안 문제를 소개함
- 특히 “프롬프트 인젝션(Prompt Injection)” 위험을 강조하며, 외부 데이터가 AI 에이전트에 예상치 못한 명령을 내릴 수 있다는 점을 지적함
- 개인적으로는 모든 데이터가 실제 LLM(대형 언어 모델)에 도달하기 전 철저한 보안 검증 체계를 구축하고, 최소한의 리소스 접근만 허용한다고 설명
- 하지만 기업 환경에서는 수많은 에이전트가 클라우드 및 직원 장치에 분산되어 운영되고 있어, 각 에이전트의 신원, 소유자, 접근 권한 파악이 필수적임
- 마이크로소프트는 이러한 문제를 해결하기 위해 Agent 365와 프로젝트 퍼셉션(Project Perception)을 개발함
- 이 시스템은 각 에이전트에 고유 신원 부여, 업무 별 접근 범위 지정, 실시간 리스크 변화 대응 등 보안 체계를 자동화함
- Project Perception의 새로운 인사이트 기능으로 현 보안 통제의 취약점 위치를 시각화하고, Guardian 에이전트로 전사적 위험 대응이 가능함
- 동적 에이전트 권한(Dynamic Permission)을 이용해 미션별로 한정적·시간제 접근을 실현함
- 리스크 기반 접근 제어로 로그인이 아닌 행동 단위마다 위협과 정책을 평가함
- 보안 소관자들이 권장 보호책을 검토·영향 사전 확인·점진적 적용이 가능함으로써, 수백 개 AI 에이전트 관리의 새로운 패러다임을 제시함

## 세부 요약 - 주제별 정리

### AI 에이전트 활용이 점점 늘어나며 다양한 시스템·데이터 접근권이 필요해지고 있음

- 영상 제작자는 “두 번째 두뇌”라 부르는 AI 에이전트를 사용해 대다수 업무를 관리함
- 이로 인해 AI 에이전트에게 많은 시스템, 클라우드, 데이터 등에 광범위한 권한을 부여할 수밖에 없음
- 권한 부여가 사용 편의성은 높이지만 그에 상응하는 보안 위협이 동반됨

### 프롬프트 인젝션은 외부 지시가 의도하지 않은 결과를 초래할 수 있는 중대한 리스크임

- 프롬프트 인젝션(Prompt Injection)은 외부 데이터가 AI 에이전트에게 예상치 못한 명령을 내리는 공격 기법임
- 예를 들어, LLM이 외부 문서를 읽었을 때 그 문서 내에 영향력 있는 명령이 삽입될 경우 사용자가 명시하지 않은 행동을 하게 됨
- 제작자는 이 위험을 “계속해서 신경 써야 하는 문제”라고 직접 강조함

### 개인 사용자 환경에서는 고도화된 보안 점검 및 권한 최소화 전략을 적용해서 리스크를 줄임

- 영상 제작자는 직접 자신이 구축한 AI에 여러 보안 점검 절차를 추가했다고 밝힘
- 모든 데이터가 실제 LLM에 도달하기 전에 필터링 및 검증 단계를 거침
- 에이전트에게는 정말로 필요한 데이터와 시스템에 대해서만 접근 권한을 부여함(권한 최소화 원칙)
- 이렇게 함으로써 프롬프트 인젝션을 일정 부분 차단하고, 의도된 행동 외의 일이 발생하지 않도록 방어

### 기업 환경은 AI 에이전트가 대규모로 분산되어 있어 관리가 훨씬 복잡해짐

- 개인과 달리 기업에서는 수많은 에이전트가 클라우드 서비스 및 각 직원 디바이스에 동시에 동작함
- 이 경우, 각 에이전트가 무엇을 할 수 있으며, 누가 소유하고 있는지, 어떤 데이터에 접근 가능한지 등 “가시성 확보”가 필수적임
- IT 부서는 모든 에이전트의 동작을 파악하고 통제하는 강력한 체계를 요구받음

### 마이크로소프트는 Agent 365 및 Project Perception으로 엔터프라이즈 급 에이전트 보안을 추진함

- 마이크로소프트는 Agent 365와 Project Perception이라는 신제품/프로젝트를 통해 위 이슈를 해결하고자 함
- 이들은 기업에서 수백 개의 AI 에이전트를 중앙 집중식으로 관리할 수 있도록 지원함
- 각 에이전트별 신원, 권한, 동작 이력 등을 체계적으로 관리할 수 있게 됨

### 고유 신원·정의된 역할·동적 범위 설정으로 AI 에이전트의 리스크를 정밀하게 통제함

- 에이전트마다 고유한 신원을 부여하여 관리자 입장에서 “누가 무엇을 하는지” 명확히 파악하게 함
- 역할 기반으로 업무 상 필요한 접근 범위만 부여함(필요한 작업/리소스에만 제한적 허용)
- 위험도 변화(예. 신규 보안취약점 노출 등)에 따라 에이전트 행동 및 접근 범위를 실시간으로 제약하거나 관리

### Project Perception의 인사이트 기능으로 기존 보안 정책의 취약점과 사각지대를 자동 시각화함

- Project Perception에는 “인사이트” 기능이 추가됨
- 이 기능을 통해 기존 보안 통제 및 정책이 어디에서 취약점을 노출하고 있는지 한눈에 파악 가능
- 기존에 일일이 건건이 조사하던 것을 시스템적으로 자동 감지하고 리포팅할 수 있음

### Guardian 에이전트를 통해 기업 전체 에이전트 위험을 중앙에서 선제적으로 관리할 수 있음

- Guardian라는 특수한 에이전트가 도입됨
- 기업 IT 부서는 Guardian 에이전트를 활용해 에이전트 환경 전체의 리스크 관리를 중앙에서 수행함
- 이를 통해 모든 자회사/부서/직원의 에이전트를 통합적으로 모니터링 및 제어 가능
- 기존에는 개별 상태를 조사했으나, Guardian 에이전트로 모든 케이스 동시 관리 지원 가능함

### 동적 권한(Dynamic Permission)으로 작업 단위 제한적, 일시적 권한 부여가 실현됨

- Dynamic Permission 기능을 활용하면, 특정 작업이나 한시적 이벤트에 맞춰 에이전트의 접근권을 일시적으로만 허용 가능
- 예를 들어, 에이전트가 평상시에 접근 못하는 리소스도 특정 임무 처리 시에만 일시적으로 권한을 부여
- 지원하는 리소스에 대해서만 이 같은 임시 접근 허용함

### 리스크 기반 접근 제어는 로그인 시점이 아니라 모든 행동 단계마다 실시간으로 위험 및 정책을 평가함

- 기존의 접근제어는 로그인 시점에만 권한 확인됐으나, 이 시스템은 행동(Action) 단위로 위험 평가와 정책 점검을 수행함
- 에이전트 행동에서 비정상적이거나 위험한 시도가 나타나면 실시간으로 차단하거나 경고 지원
- 데이터 위치, 작업 유형, 현재 정책 등 다양한 요소를 종합해 결정

### 관리자 검토 및 점진적 배포 기능으로 신뢰성 있고 투명한 보안 조치를 제공함

- 기업 보안 관리자 및 IT팀은 각종 보안 보호책을 권장안으로 받아보고, 적용 전에 영향 및 효과를 미리 확인(프리뷰) 가능
- 어떤 변화가 발생할지 미리 테스트해보고, 승인/거부 및 점진적 공개가 가능해 관리 편의성과 신뢰성을 높임
- 영상 제작자는 자신이 한 대의 에이전트에 적용했던 보안 방식을, 이제 수백 대/수천 대에 손쉽게 자동 구현할 수 있다고 강조함
