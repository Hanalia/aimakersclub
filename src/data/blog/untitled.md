## *코딩 에이전트는 코드 찾기에 지나치게 많은 토큰을 소비하며, Sonar Vortex가 이를 효율적으로 해결함* 핵심 요약

- 영상은 코딩 에이전트의 토큰 소비 문제를 지적하며, 코드 작성 자체보다 '수정이 필요한 코드 위치 찾기'가 더 많은 비용과 리소스를 소모한다고 강조함
- 코드 수정 요청 시 에이전트는 관련된 모든 파일을 찾아 읽고, 그 과정에서 유의미한 코드 변경 이전에 대량의 토큰을 사용함(예시: 8만 토큰 소모)
- 파일 검색 자체는 빠르고 저렴하지만, 읽고 판단하는 과정에서 많은 컨텍스트(토큰)가 소모됨
- 검색은 항상 추측에 기반하므로, 변수나 함수명이 다르게 되어 있으면 중요한 변경 지점을 놓칠 수 있음
- 사용자가 원하는 변경에 필요한 구체적 코드 위치를 기존 에이전트는 직접적으로 식별할 수 없음
- Sonar Vortex는 이 문제를 해결하는 도구로 소개됨: 코드베이스를 미리 분석해 정확히 어떤 파일/클래스/함수가 연관되는지 빠르게 매핑
- Sonar Vortex를 활용할 경우, 동일한 프롬프트 처리에도 큰 Token 절감효과를 보이며, 후속 질문까지 효율적으로 수행 가능함
- Sonar의 실험 결과, 6개 코드 리팩토링 임무에서 토큰 소비가 평균 6~34% 절감됨
- Sonar Vortex는 Java, C#, JavaScript, TypeScript, Python, Rust 등 주요 언어 지원
- SonarQube Cloud 및 Sonar Agent Essentials Add-on을 통해 사용 가능하며, 로컬 머신에서 매우 빠르고 정확하게 작동함

## 세부 요약 - 주제별 정리

### 코드 에이전트의 코드 작성 비용 대부분은 수정 위치 찾기에 집중됨

- 대부분의 코딩 에이전트 사용 비용은 코드 작성이 아니라 ‘수정할 코드 위치 찾기’에 집중됨
- 사용자가 단순한 변경이 아닌, 실제 임팩트가 큰 변경 요청 시 이 문제가 두드러짐
- 에이전트는 관련 파일 탐색과 분석에 상당한 시간을 소모하며, 이는 추가토큰 소모로 연결됨

### 코드 검색 과정에서 발생하는 과도한 컨텍스트(토큰) 소모

- 검색 자체는 빠르고 저렴하지만, 그 이후의 ‘파일 읽기’ 과정에서 대량의 토큰이 필요
- 의미 있는 코드 수정을 진행하기 전, 이미 수많은 파일의 내용을 읽어 토큰이 빠르게 소모됨
- 예시로, 하나의 수정 요청에서 80,000 토큰이 소비된 사례가 언급됨

### 검색 기반 접근은 인간과 마찬가지로 추측에 의존해 변경 누락 가능성 내포

- 검색어와 실제 변수, 함수명, 구조가 다르면, 관련 있는 코드를 에이전트가 놓칠 위험이 큼
- 탐색된 부분에서만 변경이 적용되어 취약점을 만들거나, 전체 변경이 누락될 수 있음
- 즉, ‘모든 관련 코드를 찾았는가’라는 질문에 에이전트는 명확히 답하지 못함

###  
코드베이스 내 '관련 코드' 위치를 직접적·정확하게 식별하는 방법 부재

- 유저는 "내 기능 수정에 필요한 코드가 어디에 있는가?"라는 직접적 질문에 명쾌히 답하는 도구가 필요함
- 현재 코딩 에이전트들은 이 요구를 검색과 추측에 의존하여 만족시키지 못함
- 코딩 업무의 근본적인 효율성 저하와 누락 문제의 원인임

### Sonar Vortex는 코드 의존성과 구현 정보를 직접 쿼리해 효율적 탐색을 제공함

- Sonar Vortex는 코드베이스를 분석, 사용자가 구체적으로 '어디가 연결되어 있는지' 질의할 수 있게 만듦
- 예시: “어떤 클래스가 특정 인터페이스를 구현하나?”, “누가 이 함수를 호출하나?”, “리턴 호출 지점은 어디인가?”
- 결과를 파일명과 줄 단위로 빠르게 매핑하여 제공
- 이로 인해 의미없는 검색-일람-분석 단계를 건너뛰고 핵심만 빠르게 파악 가능

### Sonar Vortex와 기존 방식의 실제 토큰 소비 효율 비교

- 동일한 코드베이스, 동일한 프롬프트 조건에서 실험 수행
- 기존 에이전트 방식: 코드 검색 후 읽기만 해도 80,000 토큰 소모됨
- Sonar Vortex 사용 시, 중복된 정보 요청(후속 프롬프트 포함)에도 '동일 수준이거나 더 적은 토큰' 소비로 해결 가능함
- 이로써 코드 에이전트의 리소스 효율이 크게 개선됨

### Sonar의 공식 실험 결과, 6~34% 토큰 절감 효과가 확인됨

- Sonar의 자체 테스트: 총 6개의 리팩토링 작업을 각 10회 반복 실험
- 전통적 방법과 Sonar Vortex 방식을 비교하여 토큰 소모량 측정
- 평균적으로 6~34%의 토큰 절약 효과가 나타남(상황과 작업 복잡도에 따라 차이 존재함)
- 데이터 기반 실험 결과로 신뢰성 부여

### Sonar Vortex는 주요 프로그래밍 언어와 다양한 환경에서 즉시 적용 가능

- 지원 언어: Java, C#, JavaScript, TypeScript, Python, Rust 등
- SonarQube Cloud와 Sonar Agent Essentials Add-on에서 활용 가능함
- 코딩 에이전트가 활용하는 중에도 실시간 분석 결과를 반영함

### Sonar Vortex는 로컬 환경에서 빠르고, 비컴파일 상태에서도 동작 가능

- Sonar Vortex는 코드 변경 즉시 약 1ms 내에 의존성 그래프를 갱신
- 별도의 컴파일러·언어 서버 필요 없이, 로컬 머신에서 직관적이고 빠르게 작동함
- 에이전트가 동작하는 도중 코드베이스가 컴파일되지 않은 상태에서도 분석 결과를 제공

### Sonar Vortex는 실무 적용성을 높이고, 영상 설명란에서 접근 가능

- Sonar와의 협업 의뢰를 통해 본 채널에서 여러 차례 Sonar 솔루션을 소개한 경험 보유
- Sonar Vortex 관련 정보 및 접근 경로(링크)는 영상 설명란에 제공됨
- 영상 제작자는 Sonar Vortex의 실용성과 효율성에 긍정적 경험을 토대로 추천 언급
