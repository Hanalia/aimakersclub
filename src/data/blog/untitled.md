## *나는 AI 에이전트가 코드를 머지하도록 믿지만, 프로덕션 배포는 직접 확인함* 핵심 요약

- 영상에서는 AI 에이전트가 코드 병합(Merge)을 자동화하지만, 실 사용자에게 서비스가 배포되는 프로덕션 환경에는 바로 적용하지 않는다고 설명함
- AI 소프트웨어 팩토리는 스테이징(staging) 환경까지만 배포를 자동화하며, 이후 실제 배포 여부는 직접 리뷰함
- 이유는 테스트 및 리뷰가 코드가 ‘정상적으로 보이는’ 것만 평가할 뿐, 실제 사용자에게 주는 영향은 직접 디플로이 후에만 알 수 있기 때문임
- 실 서비스에서 변경사항의 영향을 안전하게 확인하려면 ‘기능 플래그(feature flag)’로 일부 사용자에게만 공개하는 방식이 효과적임
- 문제는 기능 플래그를 코드를 작성하는 엔지니어가 직접 추가해야 하는 번거로움 때문에, 실제 도입이 어렵고, 자동화 에이전트가 대규모로 코드 변경 시 적용이 현실적으로 힘들었음
- ‘LaunchDarkly’라는 서비스는 프로덕션의 코드 변경을 실시간으로 제어할 수 있게 하며, 최근 에이전트가 기능 플래그 작업을 자동으로 처리하는 ‘Release Autopilot’ 기능을 출시함
- Release Autopilot은 위험도 분류, 성공 지표 설정, 캐너리 릴리스(일부 사용자 대상 릴리스), 실시간 관찰, 플래그 정리까지 단계별로 자동화함
- 자동화가 진행되어도 최종적으로는 풀리퀘스트(Pull Request)에서 제안을 승인해야 실제 변경이 이뤄지므로, 사람이 직접 통제할 수 있음
- 모든 변경사항은 실 사용자 그룹에 대해 검증을 거쳐 전체 배포되기 때문에, AI 에이전트에 대한 신뢰를 지나치게 높이지 않아도 됨
- 영상 말미에는 LaunchDarkly의 협력에 감사를 표하며 링크를 소개함

## 세부 요약 - 주제별 정리

### AI 에이전트가 코드 병합을 신뢰하지만 프로덕션 배포는 직접 관리함

- 영상 제작자는 AI 에이전트에게 코드 병합을 전적으로 맡기지만, 최종적인 프로덕션(실 배포)까지는 신뢰하지 않는다고 언급함
- 에이전트가 밤새도록 자동으로 코드를 머지(Merge)하지만, 실제 서비스로의 배포는 직접 검토 후 진행함
- AI 소프트웨어 개발 환경이 점점 자동화되고 있으나, 현업에서는 "완전 자동화"에 한계가 있다고 지적함

### 스테이징 환경까지만 AI 자동화를 허용하는 이유를 설명함

- 소프트웨어 배포 파이프라인에서 테스트, 코드 리뷰 등은 AI가 자동 처리할 수 있음
- 스테이징 환경까지 배포하는 것은 비교적 안전하지만, 프로덕션까지 자동 처리하면 예측하지 못한 문제가 발생할 수 있음
- "내 코드가 맞는 것처럼 보인다"는 수준의 검증만 가능하고, 실제 사용자 관점의 영향은 파악할 수 없음
- 진짜 변화의 영향은 실제 사용자 환경에서만 나타나기 때문에, 마지막 배포 단계는 사람이 직접 개입함

### 기능 플래그(Feature Flag)가 안전한 배포의 해답임을 강조함

- 수년간 검증된 안전한 배포 방법은 기능 플래그를 활용하는 것임
- 기능 플래그를 적용하면 변경사항을 전체에 배포하지 않고, 일부 사용자만 사용하게 하여 위험을 최소화할 수 있음
- 문제가 발생하면 곧바로 해당 기능을 비활성화(스위치 오프)할 수 있음
- "이 방법은 이미 오래전부터 답이었지만, 실제 현장에서는 적용에 번거로움이 있었음"이라고 지적함

### 기존에는 기능 플래그 도입이 수동적이고 번거로웠던 현실을 짚음

- 기능 플래그를 추가하려면 엔지니어가 직접 코드를 작성해야 했음
- 많은 팀이 이 방식의 번거로움 때문에 부분적으로만 적용했거나, 아예 적용하지 못함
- 특히 대규모로 에이전트가 여러 풀리퀘스트를 열 때, 플래그 추가 및 관리가 현실적으로 어려웠음

### LaunchDarkly는 프로덕션 배포의 '변경 제어'를 지원함

- LaunchDarkly는 소프트웨어가 실제 라이브(production) 환경에서 어떻게 동작하는지를 통제할 수 있게 도와주는 서비스임
- 실시간 플래그 시스템을 통해 변경사항이 실제로 적용된 후에도, 행동을 즉시 수정하거나 취소할 수 있음
- 다양한 개발팀이 프로덕션 제어 문제를 해결하기 위해 활용함

### 'Release Autopilot'은 에이전트가 플래그 작업을 자동으로 처리함

- 최근 런칭된 'Release Autopilot' 기능은 AI 에이전트가 풀리퀘스트 생성 시, 관련 기능 플래그 작업까지 자동 수행함
- 사람이 하던 반복적인 기능 플래그 래핑 작업을 완전히 자동화함

### 자동화 단계별로 위험 평가, 성과 기준 설정, 점진적 릴리스를 체계적으로 수행함

- Release Autopilot의 단계:
    - **1단계: 위험 분류** – 변경사항의 위험도를 분석하여 플래그 적용 여부를 판단
    - **2단계: 성공 지표 설정** – 프로덕션에서 어떻게 성과를 측정할지 미리 정의
    - **3단계: 자동 릴리스 플랜 시작** – 변경사항을 일부 사용자(캐너리 릴리스)에게만 우선 배포
    - **4단계: 점진적 확장** – 성과가 기준을 충족하면 점진적으로 전면 배포
    - **5단계: 실시간 관찰** – 실제 사용자 데이터를 기준으로 변경사항의 정상 동작을 상시 모니터링
    - **6단계: 플래그 정리** – 더 이상 필요 없는 플래그를 코드베이스에서 자동 정리

### 자동화와 통제의 균형을 위해 최종 승인 절차를 남김

- Release Autopilot이 자동화 절차를 진행해도, 최종적으로 풀리퀘스트에 플래그 적용 제안이 올라옴
- 실제 코드 변동은 담당자가 직접 승인(approve)해야만 적용됨
- 사람이 통제권을 갖고, 필요에 따라 ‘신뢰를 에이전트에게 과도하게 맡길 필요 없음’을 강조함

### 변경사항은 최종적으로 실 사용자 집단 대상 검증 이후 전체 배포됨

- 모든 변경사항은 각각 실 사용자 일부 집단에게 사전 적용하여 검증함
- 실 사용자 수준에서의 검증(실험/관찰) 과정을 마친 후에만 전체 배포가 이뤄지므로, 품질 리스크를 최소화할 수 있음
- 이러한 과정 덕분에 완전 자동화의 위험 없이도 대규모 AI 기반 소프트웨어 공장 운영이 가능함

### LaunchDarkly와의 협업 의도를 밝히고, 서비스 링크를 안내함

- 영상 마지막에 LaunchDarkly와의 협업에 감사 인사를 밝힘
- 추가 정보 및 서비스 접속은 영상 설명란의 링크를 통해 안내함
