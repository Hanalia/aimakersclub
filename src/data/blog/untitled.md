## *코딩 에이전트가 코드 찾기에 너무 많은 토큰을 낭비한다 – 해결 방법은 Sonar Vortex다* 핵심 요약

- 영상은 코딩 에이전트가 실제 코드를 작성하기 전, ‘코드를 찾는 과정’에서 상당한 토큰(콘텍스트 비용)을 소모한다는 문제를 지적함
- 코드베이스에서 원하는 위치나 관련 코드를 찾는 데 더 많은 자원이 사용되며, 실제 코드 변경은 오히려 적은 토큰이 필요함
- 에이전트가 파일을 찾고 읽는 과정에서 대량의 파일을 열람하며, 이로 인해 의미 있는 작업 전 상당한 토큰이 소모됨(예: 케이스에서 80,000토큰)
- 단순한 코드 검색은 빠르고 저렴하지만, 적합한 코드 위치를 판별하려면 전체 파일을 읽게 되어 비효율적임
- 검색은 항상 추측(guess)에 기반하므로, 에이전트가 이름이 다르게 지정된 중요한 코드를 놓치기도 함
- 이 문제를 해결하는 도구로 Sonar의 ‘Sonar Vortex’가 소개됨
- Sonar Vortex는 인터페이스 구현, 함수 호출, 콜백 등의 코드 관계를 파일/라인 단위로 즉각 조회 가능하게 해줌
- Sonar Vortex를 쓸 때 같은 변경 요청에 더 적은 토큰을 사용했으며, Sonar의 공식 실험에서는 6~34%의 토큰 절감 효과가 있었음
- 이 기능은 현재 Java, C#, JavaScript, TypeScript, Python, Rust 등 주요 언어에서 지원
- Sonar Vortex는 SonarQube Cloud에서 Agent Essentials Add-on과 함께 사용 가능함

## 세부 요약 - 주제별 정리

### 코딩 에이전트의 주요 비용은 코드 작성이 아니라 관련 코드 탐색에 집중됨

- 대부분의 경우, 코딩 에이전트가 소모하는 자원의 핵심은 ‘코드를 실제로 작성하는 것’이 아님
- 에이전트는 사용자가 요청한 변경 사항을 적용하기 전에, 어떤 코드가 목적에 맞는지 찾아내는 데 수많은 토큰과 시간을 투자함
- 코드베이스가 크고 변경 요청이 복잡할수록 이 과정이 더욱 비효율적으로 진행됨

### 에이전트의 코드 탐색 과정은 파일 읽기에 막대한 토큰을 요구함

- 에이전트가 관련 코드 위치를 찾으려면, 우선적으로 검색을 진행하고, 연관성이 있어 보이는 모든 파일을 읽어야 함
- 검색 자체는 빠르고 저렴하지만, 읽기(read) 단계가 토큰 소모의 핵심 원인임
- 첫 번째 실제 사례에서, 단순한 변경 요청에도 약 80,000토큰 이상의 콘텍스트가 소비됨

### 검색 기반 탐색에는 구체적인 한계와 누락 위험이 내재함

- 단순한 문자열 검색에 의존할 경우, 변수명/함수명이 다르거나 별도로 명명된 코드 부분은 놓치기 쉬움
- 에이전트의 ‘검색’은 완전하지 않으며, 실제로 변경해야 할 부분을 누락할 확률이 있음
- 이를테면, 변경된 함수나 클래스가 이름이 다르다면 검색 결과에 나타나지 않음

### 코딩 에이전트는 핵심적으로 “어떤 코드가 사용자의 변경 요구에 관련이 있는가”를 찾아야 하는 문제에 직면함

- 본질적으로, 전체 토큰 소비의 이유는 “관련 코드 위치의 효율적 확인”에 있음
- 코딩 에이전트는 사용자의 요청에 대하여, 코드베이스 내 ‘관계’를 파악해야 하지만, 현재 방식은 이를 직접적으로 해결하지 못함

### Sonar Vortex는 코드의 구조적 관계를 직접 질의하여 효율적으로 탐색을 지원함

- Sonar Vortex는 기존 Sonar 플랫폼 위에서 동작하는 신규 기능
- 이를 통해, ‘해당 인터페이스를 구현하는 클래스’, ‘특정 함수를 호출하는 코드’, ‘이벤트/콜백의 호출 및 반환’ 등의 관계를 즉각적으로 파일 및 라인 단위까지 추적 가능
- 검색이 아닌 “질문-응답(쿼리)” 방식의 직접 탐색이 실시간으로 이루어짐

### Sonar Vortex 사용 시 코드 탐색이 실시간 그래프 데이터 기반으로 처리되어 확연히 빨라짐

- Sonar Vortex가 사용하는 코드 관계 그래프는 로컬 컴퓨터에서 즉시 생성됨
- 데이터베이스, 외부 컴파일 혹은 Language Server가 필요 없음
- 코드가 바뀌어도 1밀리초 내에 그래프가 새로 갱신됨
- 에이전트가 여러 파일을 읽어야 했던 비효율이 해소됨

### 컴파일 환경에 구애받지 않으며, 코드 변경 후에도 빠르게 추적 가능함

- 에이전트로 변경 작업을 수행하는 중, 일반적으로 코드베이스는 완전히 컴파일되지 않은 상태
- Sonar Vortex는 별도의 컴파일 과정 없이도 변경 사항을 반영한 탐색이 즉시 가능

### 실제 실험에서 Sonar Vortex 사용 시 토큰 소모가 유의하게 감소함

- 동일한 코드 변경 요청에 대해, 기존 방식(검색+읽기)에서는 80,000토큰이 소모됨
- Sonar Vortex를 활용할 경우, 같은 질의를 더 적은 토큰 수로 해결할 수 있었고, 후속 질의(추가 프롬프트)를 해도 여전히 효율적임
- Sonar 내부 실험에서는, 6개 리팩토링 작업을 10회 반복 시 6%~34%의 토큰 절약이 관측됨

### 다양한 현대 프로그래밍 언어를 지원하며 SonarQube 환경에서 동작함

- Sonar Vortex의 코드 관계 탐색은 Java, C#, JavaScript, TypeScript, Python, Rust 등 대표 언어에서 제공됨
- SonarQube Cloud 플랫폼에서 ‘Sonar Agent Essentials’ 애드온을 함께 사용해야 기능이 활성화됨

### Sonar와의 협력 및 영상 설명란에 Sonar Vortex 링크 안내

- 영상 제작자는 Sonar에 협업에 대해 감사 인사를 전함
- Sonar Vortex 관련 추가 정보 및 링크는 유튜브 영상 설명란에 안내되어 있음
