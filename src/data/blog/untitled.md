## *프롬프트 인젝션은 AI 에이전트 보안의 시작일 뿐이다 (필요한 것은 이것이다)* 핵심 요약

- 영상은 AI 에이전트, 특히 개인 및 기업이 사용하는 ‘두 번째 두뇌’ 도구의 보안 위험성에 주목함
- 프롬프트 인젝션(Prompt Injection)이란 외부 데이터가 AI 에이전트에게 원래 사용자가 요청하지 않은 일을 하도록 하는 문제임을 설명
- 제작자는 AI 에이전트의 입력 데이터마다 여러 보안 점검 절차를 직접 구축하여 대응해왔음을 밝힘
- AI 에이전트의 권한은 반드시 필요한 범위만 부여되어야 하며, 접근 가능한 시스템도 엄격히 제한해야 함을 강조
- 기업에서는 수십, 수백 개의 에이전트가 각기 다른 환경(클라우드, 직원 기기 등)에 퍼져 있어 보안 관리가 매우 복잡함
- 마이크로소프트의 Agent 365와 Project Perception 솔루션이 이 문제 해결을 위해 등장했음을 언급
- 해당 솔루션들은 AI 에이전트에 고유의 ‘정체성’(Identity)과 제한된 권한, 위험 변화에 따른 동적 통제, 실시간 모니터링을 제공함
- 예외 처리, 동적 권한(시간 및 과업 한정), 리스크 기반 접근통제 등 다양한 보안 수단이 통합적으로 운영됨
- 팀은 마이크로소프트 솔루션을 통해 한 번의 요청 케이스별 대응이 아니라 에이전트 전반의 위험을 구조적으로 관리할 수 있게 됨
- 최종적으로, 제작자는 수백 개의 에이전트 관리에서도 동일한 강도의 보안 관리가 가능해진 환경을 강조하며, 관련 링크를 소개함

## 세부 요약 - 주제별 정리

### AI 에이전트 ‘두 번째 두뇌’는 강력하지만 외부 접근에는 커다란 보안 리스크가 있음

- 제작자는 ‘두 번째 두뇌’(Second Brain) AI 에이전트를 활용해 다양한 개인 및 업무 작업을 자동화하고 관리함
- 이 시스템은 많은 IT 시스템과 데이터에 대한 접근 권한을 가짐
- 개별 사용자 입장에서는 강력한 효율성을 제공하지만, 바로 이 ‘접근 권한’이 심각한 보안 위험으로 이어질 수 있음을 경고

### 프롬프트 인젝션으로 인한 AI 오작동 위험이 언제나 존재함

- 프롬프트 인젝션(Prompt Injection)은 AI 시스템이 외부 입력(예: 사용자의 메시지나 외부 데이터)로부터 예기치 않게 조작될 수 있는 공격임
- 예시: AI 에이전트가 외부 데이터를 읽다가, 사용자 의도와 무관하게 특정 행동(예를 들면, 민감 정보 노출, 시스템 명령 실행 등)을 하게 될 수 있음
- 이런 이유로 제작자는 AI 에이전트가 받는 모든 입력을 LLM(Large Language Model)에 전달하기 전에 세밀하게 점검

### 보안 점검과 권한 제한이 AI 에이전트 운용의 기본이 되어야 함

- 제작자는 프롬프트 인젝션 등 위험을 예방하기 위해 각 단계별 ‘보안 체크(검사)’ 프로세스를 구축함
- 모든 인풋이 실제 LLM에 전달되기 전에 안전성을 검증
- AI 에이전트가 접근할 수 있는 데이터 및 시스템 범위를 최소한으로 제한함 (최소 권한 원칙의 현실적 적용)
- 이러한 직접적 통제는 본인이 직접 에이전트를 설계/개발했기에 실현이 가능했다고 밝힘

### 기업 환경에서는 수많은 에이전트와 복잡한 접근통제가 발생함

- 대기업, 중소기업에서는 수많은 AI 에이전트가 동시에 운영되고 있음
- 이러한 에이전트는 일부는 클라우드에서, 일부는 직원의 로컬 장치에서 구동됨
- IT 부서에는 어떤 에이전트가 어디에서 실행 중인지, 누가 소유/관리 중인지, 어떤 시스템에 접근 가능한지 정확하게 파악하는 것이 매우 어렵다는 과제가 있음

### 마이크로소프트의 ‘Agent 365’와 ‘Project Perception’이 보안 해법을 제시함

- 마이크로소프트는 AI 에이전트 보안 관리 솔루션으로 Agent 365와 Project Perception을 개발함
- Agent 365는 각 에이전트에 고유의 ‘디지털 아이덴티티’(정체성)를 부여함
- 에이전트의 권한(접근 가능 범위, 실행 가능한 작업 등) 및 업무 범위를 명확하게 정의
- 현실적으로 에이전트가 수행하는 작업의 위험도가 변경될 때 이를 동적으로 컨트롤(격리, 제한 등) 가능
- 기본적으로 직원의 기존 권한과는 별개로 에이전트의 접근 권한을 세분해 부여할 수 있음

### Project Perception은 보안 사각지대를 시각화하고, 통합적 리스크 대응을 가능케 함

- Project Perception의 ‘에이전트 인사이트(Agent Insights)’는 기존 보안 제어가 미치지 못하는 지점(사각지대, 취약점)을 실시간으로 파악 가능하게 함
- ‘가디언(Guardian) 에이전트’는 단일 케이스별 대응이 아니라, 전체 에이전트 생태계 내 위험 인자를 종합적으로 탐지 및 해결할 수 있도록 지원함

### 동적 권한(Dynamic Permissions)과 리스크 기반 통제로 미세 조정이 가능함

- 동적 권한(Dynamic Permissions)은 각 에이전트가 필요할 때만 과업 단위로, 제한된 시간/범위 내 자원 접근을 허용함 (ex. 일정 시간 동안만 특정 데이터베이스에 접근)
- 리스크 기반 접근통제(Risk-based Access Controls)는 단순 로그인 순간뿐만 아니라, 구체적인 에이전트 작업 전체를 실시간으로 평가하여 정책을 적용함
- 이로써 예기치 못한 행동이 감지되면 즉시 차단하거나, 정책 위반시 추가 승인을 요구

### 모든 보호 조치는 IT팀이 미리 검토·승인 후 순차적으로 적용할 수 있도록 설계됨

- IT/보안팀은 새로운 보호 조치를 추천받아 기능적 영향(impact)을 사전에 미리 시뮬레이션, 검토할 수 있음
- 실제 배포 전 ‘점진적(gradual) 롤아웃’을 통해 문제 없이 적용되는지 확인 가능
- 위험도 높은 상황이 감지되면 즉시 반응하고, 에이전트 전체에 일괄적으로 정책을 반영할 수 있음

### 개인은 한 명의 에이전트에만 집중할 수 있지만, 기업은 수백 개의 에이전트 관리가 필요함

- 제작자 본인은 한 명의 AI 에이전트(두 번째 두뇌)의 보안을 수기적으로 깊게 관리했음
- 반면, 기업이나 조직은 수많은 에이전트를 동시에, 그리고 구조적으로 통제·보안해야 하는 어려움을 겪음
- 마이크로소프트 솔루션 덕분에 대규모 환경에서도 동일한 수준의 통제가 가능해졌음을 언급

### 마이크로소프트와의 협업 경험 및 참고 링크 안내

- 제작자는 마이크로소프트와 해당 프로젝트 협업을 진행했음을 밝혔으며 감사의 뜻을 전함
- 영상 설명란에 추가 정보와 관련 솔루션 링크를 제공할 예정임을 안내하며 영상 마무리
