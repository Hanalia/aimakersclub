## *프롬프트 인젝션은 AI 에이전트 보안 문제의 시작일 뿐이다 (필요한 것은 무엇인가?)* 핵심 요약

- 영상에서는 업무 효율을 위해 '두 번째 두뇌(AI 에이전트)' 사용 경험을 바탕으로 AI 보안의 복잡성과 해결책을 다룸
- 프롬프트 인젝션(Prompt Injection)이란 AI가 외부 데이터에서 악의적 명령을 받아 사용자가 의도하지 않은 행동을 하게 되는 보안 위협임을 설명
- 이러한 위험 때문에, AI 에이전트에 보내는 모든 데이터에 다양한 보안 점검을 적용하고, 에이전트 접근 권한은 반드시 필요한 범위로 제한해야 함을 강조
- 개인 단위에선 보안 통제가 상대적으로 쉽지만, 기업 환경에서는 수십~수백 개의 AI 에이전트가 각기 다른 장치·클라우드·직원 계정에서 활동해 관리와 통제가 어려움
- IT 부서는 각각의 에이전트 현황, 소유자, 접근 범위를 명확히 파악하고 통제할 수 있는 솔루션이 필요함
- 마이크로소프트는 Agent 365와 Perception 프로젝트로 이처럼 복잡한 AI 에이전트 관리를 지원하는 보안 체계를 구축
- 주요 기능은 에이전트별 고유 신원 부여, 접근 권한과 미션 범위 제한, 동적이고 임시적 접근 권한 관리 등임
- Perception 프로젝트의 인사이트 기능은 현재 보안 통제의 빈틈을 파악하여 '가디언 에이전트'와 함께 전사적으로 위험에 대응할 수 있게 지원
- 에이전트의 접근 권한은 실시간 리스크와 정책을 기반으로 지속적으로 평가·제어되며, 사용자 승인·적용 영향을 사전 미리 검토할 수 있는 기능 제공
- 영상 마지막에서 "이제 수백 개의 에이전트에 대해 이렇게 보안 수준을 맞출 수 있다"고 강조하며, 마이크로소프트의 기술 협조에 감사 인사를 전함

## 세부 요약 - 주제별 정리

### AI 에이전트 사용은 더 많은 시스템과 데이터 접근을 필연적으로 요구함

- 영상 제작자는 "두 번째 두뇌"로 불리는 AI 에이전트를 활용해 다수의 업무를 자동화하고 관리함
- 이로 인해 다양한 시스템과 개인 데이터에 대한 AI의 접근 권한이 필수적임
- 높은 생산성의 대가로, AI 에이전트가 민감한 정보, 계정, 업무 시스템에 넓은 접근 범위를 갖게 됨을 지적
- 이런 상황에선 AI의 안전성과 신뢰성이 보장되어야 하며, 데이터 유출·오동작 방지 대책이 매우 중요해짐

### 프롬프트 인젝션(Prompt Injection)은 실시간으로 AI 행위를 조작할 수 있는 위험한 공격임

- 프롬프트 인젝션이란, 외부 데이터나 입력이 AI에게 사용자가 원하지 않은 명령(행동)을 내리는 보안 위협임
- 이는 AI가 채팅 메시지, 이메일, 문서로부터 의도치 않은 명령어를 받아 잘못 작동하게 만드는 공격임
- 제작자는 AI가 항상 데이터와 상호작용해야 하므로 프롬프트 인젝션을 늘 고려해야 한다고 강조
- 실제로 프롬프트 인젝션을 방지하기 위해 데이터의 흐름을 실시간으로 검증하고 필터링하는 과정을 추가함

### 효과적 AI 보안을 위해 다단계 체크와 검증 흐름을 구축해야 함

- AI가 외부에서 받은 정보를 곧바로 LLM(대형언어모델)에 전달하지 않고, 독립적인 보안 검증 단계를 거침
- 어떠한 외부 데이터도 AI의 내부 핵심 엔진(LLM)으로 들어가기 전에 자연어 지시어, 의심스러운 명령어, 위험 플래그 등을 정밀하게 점검
- 이러한 방식으로 AI가 예기치 못한 행동이나 보안 위협에 노출되는 것을 사전에 차단할 수 있음
- 실제 영상에서는 "아무 의심 없이 LLM에 모든 것을 보내지 않는다"는 점을 구체적으로 언급

### 권한 최소화 원칙에 따라 AI 에이전트 접근을 제한하는 것이 기본적 방어선임

- AI 에이전트는 필요한 기능 수행만을 위해 반드시 필요한 최소한의 시스템·데이터 접근권만을 갖게 설정함
- 불필요한 파일, 앱, 데이터베이스 등에는 일체 접근 금지 조치
- 에이전트별 권한 설정, 사용 목적에 맞춘 범위 제한이 반복적으로 강조됨
- 이런 보안 설정은 제작자가 단일 에이전트 환경에서 수동으로 관리해 가능했다고 밝힘

### 개인 단위에선 수작업 통제가 가능하지만, 기업에선 에이전트의 확산과 감독이 복잡해짐

- 기업 환경에서는 수십~수백 개 AI 에이전트가 클라우드, 로컬 디바이스, 사내 인프라 등 다양한 환경에서 운영됨
- 모든 에이전트의 정확한 목록, 소유자, 현재 권한 범위를 실시간 파악·관리하는 일은 IT 부서에 큰 부담이 됨
- 에이전트의 확산 규모가 커질수록 프롬프트 인젝션, 데이터 유출, 오용 위험도 기하급수적으로 증가

### 마이크로소프트는 Agent 365와 Project Perception으로 기업형 에이전트 보안 문제를 구조적으로 해결하고자 함

- 마이크로소프트는 Agent 365와 Perception 프로젝트를 통해 복잡한 에이전트의 신원, 권한, 활동 범위, 리스크 관리 등을 지원
- AI 에이전트마다 고유의 ID(신분증)을 부여하고, 담당 임무/업무별로 권한을 엄격히 정의
- 에이전트의 접근 대상 리소스와 허용 임무 전체가 체계적으로 관리됨을 언급
- 변화하는 위험 상황에도 각 에이전트별로 독립적 보안 경계를 유지하며, 직원 계정의 본래 접근 권한엔 영향이 없음

### Project Perception의 '인사이트'는 현재 보안 통제의 취약점을 실시간으로 보여줌

- Perception 프로젝트는 에이전트별 행동, 접근 현황, 미확인 위험 상황을 실시간으로 시각적으로 제공
- IT관리자는 다양한 에이전트의 위험 노출 구간, 통제 사각지대를 한눈에 파악할 수 있음
- 기존 대비 전사적 위험에 대한 사전 탐지와 대응이 가능해짐

### '가디언 에이전트'로 여러 에이전트의 집단적 위험을 효율적으로 대응할 수 있음

- Perception은 Guardian Agents(보호자 에이전트)를 통해 한 번에 여러 에이전트의 위험 상황에 자동 대응함
- 즉, 개별 건마다 별도의 수동 조사가 아니라, 조직 전체 관점의 집단적 모니터링 및 조정이 구현됨
- 위험이 감지된 경우 자동으로 조치하거나, IT팀에 경고와 옵션을 제공

### 에이전트 권한은 임무 단위의 동적·임시적 할당으로 보다 촘촘하게 관리됨

- Dynamic Permission(동적 권한 시스템)은 각 에이전트가 특정 업무·타임프레임 안에서만 제한적으로 자원에 접근하도록 설계됨
- 시간 및 목적 기반의 최소권한 원칙이 현장에 적용됨
- 이를 통해 불필요한 권한 남용, 장기적 권한 홀딩 위험 감소

### 실시간 정책 평가와 승인, 점진적 적용을 통해 안정적으로 보안을 강화할 수 있음

- 에이전트의 접근은 로그인 시점뿐 아니라, 실제 리소스 접근/행동 단위별로 리스크 및 정책 점검이 반복됨
- 보안 정책 제안은 IT팀이 직접 검토, 영향도(impact) 시뮬레이션, 단계적(gradual) 승인 및 적용이 가능하도록 프로세스화됨
- 이를 통해 현장 혼선 없이, 안정적이고 체계적으로 보안 개선을 지속함

### 여러 에이전트 환경에서도 이같은 보안 전략을 대규모로 적용하는 것이 가능해졌음을 강조함

- 영상 제작자는 "이제 나는 단일 에이전트 뿐만 아니라 수 백 개의 에이전트에게도 동일한 수준의 보안을 적용할 수 있다"며 소감을 밝힘
- 마이크로소프트와의 협업 사례임을 구체적으로 언급
- 최종적으로 이러한 체계가 AI 도입 기업 환경에서 핵심적임을 암시하며 마무리함
