## *코딩 에이전트는 코드 찾기 과정에서 불필요하게 많은 토큰을 소모하며, Sonar Vortex가 이를 효율적으로 해결함* 핵심 요약

- 해당 영상은 코딩 에이전트가 실제 코드 변경 작업보다 "수정이 필요한 코드를 찾는 과정"에서 더 많은 토큰 및 리소스를 소모한다는 문제를 지적함
- 변화가 간단하지 않은 경우, 에이전트는 연관된 파일들을 모두 찾고 그 내용을 일일이 읽으며 상당한 토큰을 소비함
- 코드 검색은 빠르고 저렴하지만, 실제로 파일을 읽고 분석하는 과정에서 대량의 컨텍스트(토큰)가 소모됨
- 에이전트의 검색 기능은 완벽하지 않아, 이름이 다르거나 예상과 다른 코드 영역은 쉽게 놓칠 수 있음
- 결과적으로 에이전트는 "어떤 코드가 원하는 변경과 관련있는지"라는 질문에 비효율적으로 접근함
- Sonar Vortex는 이러한 문제를 해결하기 위한 도구로, 코드베이스를 미리 분석하여 직관적으로 관련 클래스를 찾을 수 있게 함
- Sonar Vortex 사용 시 코드 구조 그래프가 로컬에서 빠르게 생성되고, 컴파일 없이도 실시간(약 1밀리초) 내에 갱신됨
- 기존 방식 대비 Sonar Vortex 활용 시 약 6~34%의 토큰 절감 효과가 Sonar의 연구를 통해 확인됨
- Sonar Vortex는 Java, C#, JavaScript, TypeScript, Python, Rust를 지원하며 SonarQube Cloud와 연결되어 있음
- 영상에서는 동일한 코드베이스에서 Sonar Vortex 활용 전후 토큰 소모량을 비교하며, 개선점을 실증적으로 보여줌

## 세부 요약 - 주제별 정리

### 코딩 에이전트는 코드 작성보다 코드 위치 파악에 가장 많은 리소스를 사용함

- 코딩 에이전트를 사용할 때, 실제 비용의 대부분은 코드를 새로 작성하는 것이 아니라, "수정 또는 추가할 코드 위치를 찾는 데" 들어감
- 복잡하지 않은(trivial하지 않은) 변경을 명령하면, 에이전트는 관련된 파일들을 모두 검색하고 그 내용을 읽음
- 이 과정에서 많은 시간과 토큰(컨텍스트 리소스)이 소모됨
- 즉, 코드베이스를 전체적으로 분석해야 적용해야 할 위치를 결정할 수 있음

### 코드 파일 읽기 과정이 검색 대비 비용 및 토큰 소모에서 훨씬 부담이 큼

- 파일 검색 자체는 속도가 빠르고 저렴함
- 하지만 코드 파일을 실제로 읽고 내용을 파악하는 과정에서 방대한 양의 컨텍스트(토큰)를 소모함
- 코드 변경을 시작하기 전에 이미 컨텍스트 한도의 대부분을 소진할 수 있음
- 이는 특히 대규모 코드베이스에서 심각한 비효율로 이어짐

### 코드 검색 로직의 한계로 인해 일부 관련 코드를 에이전트가 놓칠 수 있음

- 검색(Suche)은 항상 추측(raten)의 영역임
- 함수나 클래스의 이름이 예상과 다를 경우, 에이전트의 검색에서는 해당 부분이 누락됨
- 실제로 존재하는 관련 코드지만 올바른 키워드로 노출되지 않아 변경이 누락될 수 있음
- 결과적으로 에이전트가 식별한 부분만 정확히 변경하지만, 전체적으로 필수적인 모든 변경이 이루어진다고 보장할 수 없음

### 에이전트의 본질적 질문은 "어떤 코드가 변경에 관련되는가?"에 있으며 이를 직접적으로 해결하지 못함

- 에이전트는 수많은 파일을 읽고 분석해서 결국 "어떤 코드가 사용자 요구와 관련이 있는가"라는 질문에 답하고자 함
- 기존 에이전트는 이 질문에 직접적으로 답할 수 있는 구조가 아님
- 이로 인해 여전히 많은 불필요한 작업과 리소스 낭비가 발생함

### Sonar Vortex는 관련 코드를 직접적이고 효율적으로 식별하는 솔루션을 제공함

- Sonar Vortex는 기존 Sonar 플랫폼(코드베이스 분석 도구)을 기반으로 추가된 도구임
- Sonar Vortex를 활용하면 인터페이스를 구현한 클래스, 함수의 호출자, 반환 관계 등을 파일과 정확한 코드 라인 단위로 직접 조회할 수 있음
- 이 방식은 "검색" 대신 "직접 질의"로, 매우 효율적임

### 그래프 기반 분석으로 빠른 질의 응답이 실현되며 실시간 업데이트도 제공함

- Sonar Vortex는 코드베이스의 구조 정보를 그래프로 로컬 환경에 생성함
- 외부 컴파일러, Language Server 없이도 실시간(약 1밀리초) 내에 업데이트됨
- Agent가 단일 작업을 수행하는 동안 코드베이스가 완전히 컴파일되지 않아도 정보 갱신이 즉시 가능함
- 이로 인해 작업 중간 과정에서의 정보 갭(지연, 부정확성)을 최소화할 수 있음

### Sonar Vortex 적용 사례에서는 대폭적인 토큰 소모 절감이 실증됨

- 영상 내 실험: 동일한 코드베이스와 명령 프롬프트로, 처음엔 전통적 방식, 두 번째엔 Sonar Vortex를 통한 작업을 수행
- 기존 방식에서는 변경 작업에 약 80,000 토큰이 소모됨(단순 파일 검색 및 읽기만 해당)
- Sonar Vortex로 동일 작업을 수행하고, 추가 질문(prompt)까지 진행해도 전체 토큰 사용량이 기존과 거의 동일하거나 더 적음
- 특히 Sonar 자체 연구에 따르면, 6개의 리팩토링 과제를 10회 반복 수행시 6%~34%의 토큰 절감이 실험적으로 확인됨

### Sonar Vortex의 언어 지원 범위와 시스템 연동 구조가 소개됨

- Sonar Vortex의 효과는 Java, C#, JavaScript, TypeScript, Python, Rust에서 재현됨
- SonarQube Cloud와 Sonar Agent Essentials Add-on을 통해 통합 사용 가능함
- 이로 인해 팀환경이나 다양한 프로젝트에서 적용이 간편함

### Sonar와의 협력을 통해 실제 도구 데모 및 추가 정보 접근성을 제공함

- 영상은 Sonar와의 협업을 통해 제작되었음을 명시함
- Sonar Vortex 도구 및 관련 정보, 링크는 영상 설명란에 안내함
- 채널 내에서도 Sonar 도구 시리즈를 다수 다루고 있음을 덧붙임
