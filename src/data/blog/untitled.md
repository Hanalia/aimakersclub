## *코딩 에이전트는 코드 찾기 과정에서 과도한 토큰을 소모하며, Sonar Vortex가 이를 효율적으로 해결함* 핵심 요약

- 본 영상은 코딩 에이전트가 실제로 코드 작성이 아닌, "수정할 코드 찾기" 과정에서 대부분의 토큰과 비용을 소모하고 있음을 강조함
- 에이전트가 코드베이스의 수정 요청을 받으면, 관련성을 판단하기 위해 많은 파일을 검색 및 읽으며 이 과정에서 막대한 토큰이 사용됨
- 검색(Searching) 자체는 저렴하고 빠르나, 찾은 파일들을 모두 읽으며 판단하는 과정에서 비용과 토큰 사용이 급증함
- 코드명이나 네이밍이 예상과 다를 경우, 중요한 코드도 누락될 수 있다는 한계 있음
- 이러한 문제점은 사실상 "수정해야 할 코드가 무엇인가?"라는 단일 질문에 효율적으로 대답하지 못함에서 비롯됨
- 이를 근본적으로 해결하는 도구로 Sonar Vortex가 소개됨
- Sonar Vortex는 클래스-인터페이스 구현 관계, 함수 호출 및 반환 등 구조 정보를 빠르게 추적 및 식별할 수 있음
- Sonar Vortex는 개발자 컴퓨터에서 직접 그래프를 생성, 별도 컴파일러/Language Server 필요 없이 실시간(약 1ms)으로 갱신됨
- 실제 실험에서 전통적 에이전트 방식은 8만 토큰을 소비했으나, Sonar Vortex 사용 시 동일 요청에서 더 적은 토큰 사용을 확인함
- Sonar 공식 연구에 따르면 6가지 리팩토링 시나리오에서 6~34%의 토큰 절감 효과가 입증됨
- 해당 기능은 Java, C#, JavaScript, TypeScript, Python, Rust 등을 지원하며, SonarQube Cloud와 연동되어 있음

## 세부 요약 - 주제별 정리

### 코딩 에이전트의 토큰 소모는 코드 작성이 아닌 코드 탐색 과정에서 집중적으로 발생함

- 사용자가 Coding Agent에게 코드베이스의 변경을 요청할 때, 에이전트는 실제 코드 작성보다 "수정 대상 코드 찾기"에 훨씬 더 많은 시간과 자원을 투입함
- 특히, 변경사항이 비트리비얼(복잡하거나 큰 규모) 할수록 이 경향이 더 강함
- 에이전트는 관련성이 있을 법한 모든 파일을 탐색(Search)하고, 이 파일들이 실제로 관련이 있는지 판단하기 위해 일일이 읽어야 함
- 이 과정 중 "검색(Search)"은 빠르고 비용이 저렴하지만, "읽기(Reading Files)" 단계에서 대량의 토큰(컨텍스트)을 소모하게 됨
- 때에 따라 수정해야 할 코드가 예상과 다른 이름으로 존재할 경우, 검색 단계에서 누락될 위험도 동시에 존재

### 단순 검색(Searching)이 아니라 코드 의미 파악이 근본적인 문제임을 지적함

- 코딩 에이전트가 본질적으로 해결해야 할 문제는 "어떤 코드가 사용자의 변경 요청에 진짜로 관련이 있는지"를 판단하는 것임
- 검색은 언제나 추측(Guessing)에 기반하기 때문에 네이밍, 구조 등이 다르면 실제 수정 대상 코드를 놓칠 수 있음
- 사용자 요구에 모두 부합하는 변경이 되도록 하려면, 검색 외의 정확한 식별 도구가 필요함

### Sonar Vortex는 코드베이스 구조 분석을 통해 직접적이고 효율적인 답을 제공함

- Sonar Vortex는 Sonar 플랫폼 위에서 동작하는 추가 도구로, 현재 코드베이스를 분석하여 구조적 연관성을 즉각적으로 제공함
- 예를 들어, 어느 클래스가 특정 인터페이스를 구현하는지, 누가 특정 함수를 호출했는지, 어떤 파일과 몇 번째 줄에 연결되어 있는지 빠르게 추적이 가능함
- 단순 검색이 아닌 데이터베이스화된 그래프 구조로 의미 단위의 탐색이 이루어짐

### Sonar Vortex는 개발자의 로컬 환경에서 실시간으로 코드 관계 그래프를 생성 및 갱신함

- Sonar Vortex는 자체적으로 코드 관계 그래프를 개발 PC(로컬)에서 직접 빌드함
- 별도의 컴파일러나 Language Server에 의존하지 않고, 에디팅 도중 코드가 수정되어도 약 1 밀리초(ms)의 짧은 시간 내 즉시 그래프가 재생성됨
- 코드베이스 자체가 컴파일되어 있지 않은 상황(에이전트 동작 도중 등)에도 정상적으로 의미 탐색이 가능함

### Sonar Vortex 사용 전후 토큰 사용량과 효율성 차이가 실제 사례로 비교됨

- 기존 방식: 코딩 에이전트가 전체 파일을 탐색 및 읽기에 80,000 토큰을 소비함
- Sonar Vortex 도입 후: 동일 프롬프트, 이어지는 추가 질의에도 이전과 유사한(혹은 더 적은) 토큰만 소모됨
- 동일한 결과에 도달하는 데에 소모되는 비용(토큰량)이 명확히 감소됨

### Sonar의 공식 연구에서 6~34%의 토큰 절감 효과가 데이터로 입증됨

- Sonar에서 6가지 리팩토링 작업을 10회 반복 수행하는 실험을 진행함
- 이 과정에 Sonar Vortex를 활용했을 때, 토큰 사용량이 최소 6%에서 최대 34%까지 절감됨이 연구 데이터로 확인됨
- 토큰 효율성이 실제 코드 실무에서 유의미하게 향상될 수 있음이 객관적으로 증명됨

### Sonar Vortex는 다수의 프로그래밍 언어와 플랫폼 환경을 지원함

- 분석 및 탐색 기능은 현재 Java, C#, JavaScript, TypeScript, Python, Rust 등 6가지 언어를 지원함
- SonarQube Cloud 기반 위에서 관리/제공되며, 추가적으로 Sonar Agent Essentials Add-on이 요구됨

### Sonar Vortex의 활용법과 특징이 간결히 시연 및 요약됨

- Cloud Code 환경에서 Sonar Vortex에 직접 코드 접근 권한을 부여하면, 검색이 아닌 "직접 정보 질의"가 가능함을 실시간 예제로 보여줌
- 사용자가 별도 컴파일이나 재시작 없이 즉시 코드 구조 정보를 받을 수 있음
- 영상 하단에 Sonar Vortex에 대한 자세한 정보 및 링크가 제공됨

### 코딩 에이전트와 Sonar Vortex의 근본적 차이점이 정리됨

- 기존 에이전트: 검색과 파일 읽기에 의존해 명시적으로 전체 맥락을 파악, 토큰 소모가 ↑
- Sonar Vortex: 코드 의미(구조)를 그래프로 직접 추출하여, 필요한 부분만 정확히 식별 및 질의
- 동일 결과 도출 시 Sonar Vortex가 더 빠르고, 더 적은 자원을 활용하여 효율적임

### 영상의 목적과 추가 참고 사항이 명시됨

- 본 영상은 많은 코딩 에이전트가 겪는 근본적 비효율(토큰 낭비)의 원인과, Sonar Vortex 등 새로운 도구로의 개선 사례를 팩트 위주로 알리고자 함
- 영상 제공자(Cole Medin)는 Sonar사와의 협업 및 기존 Sonar 플랫폼 보도를 여러 차례 진행한 바 있다고 언급
- Sonar Vortex의 공식 웹사이트 링크가 영상 설명란에 포함됨
