## *당신의 코딩 에이전트는 코드만 알 뿐 실제 앱은 알지 못한다 (해결책은 여기!)* 핵심 요약

- 코딩 에이전트(예: Claude Code, Codex, GitHub Copilot)는 저장소의 모든 파일을 읽을 수 있지만, 실제 애플리케이션의 동작 및 구성에 대해선 이해하지 못함
- 데이터 연결 상태, 배포 위치, 의존성 구조, 최근 장애 등 핵심 정보는 코드가 아닌, 애플리케이션이 운영되는 플랫폼에 저장됨
- 따라서 기존 코딩 에이전트는 이와 같은 중요한 운영·배포 지식을 파악하지 못함
- 모든 정보를 한 곳에서 에이전트가 접근할 수 있는 환경이 필요함
- OutSystems 플랫폼과 OutSystems MCP를 활용하면 코딩 에이전트가 전체 앱 구조, 데이터 모델, 의존성, 배포, 로그 등 실시간 정보를 직접 파악 가능
- 에이전트는 OutSystems 클라우드에 연결하여 실제 애플리케이션의 엔티티, 화면, 로직, 역할 등을 세션 내에서 분석·변경·배포·점검할 수 있음
- 빌드 및 배포는 OutSystems 내장 에이전트 'Mentor'에게 넘겨 이관 및 자동화 처리
- 장애 발생 때는 동일 세션에서 로그와 트레이스를 즉시 불러와 원인 진단 가능
- 에이전트는 사용자와 동일한 권한(아웃시스템스 권한 체계)에 따라 동작하므로 보안도 통제됨
- OutSystems MCP는 무료 개인 버전도 제공되어 누구나 기존 코딩 에이전트와 바로 연결 가능함

## 세부 요약 - 주제별 정리

### 코딩 에이전트는 코드 파일만 읽을 수 있지만 실제 애플리케이션을 이해하지 못함

- 대부분의 코딩 에이전트는 저장소(repository) 내의 모든 소스 코드를 읽을 수 있는 기능을 보유
- 그러나 실제 앱의 작동방식이나 전체 아키텍처, 운영 현황 등은 알지 못함
- 데이터가 어떻게 연결되어 있는지, 어디에 배포되고 있는지, 각 컴포넌트 간의 의존관계 등이 파악 불가
- 예를 들면, 무엇이 무엇에 의존하고, 어젯밤에 무슨 장애가 발생했는지와 같은 현황 정보에 접근하지 못함

### 실제 운영 및 배포 관련 정보는 코드가 아니라 플랫폼에 존재함

- 앱의 모든 운영 정보(데이터 연결, 배포 위치, 의존성, 장애 이력 등)는 코드 자체에 있지 않음
- 각종 메타 데이터, 운영 로그, 배포 상세 내역, 시스템 의존성 등은 애플리케이션이 올라가 있는 플랫폼(예: OutSystems)에 존재
- 즉, 에이전트가 코드만 본다고 해서 개발자와 동일하게 앱 전체의 상태를 볼 수는 없음

### 코딩 에이전트가 앱 전체 정보를 한 곳에서 볼 수 있어야 효율이 상승함

- 제대로 된 지원을 위해선 코딩 에이전트가 개발자처럼 앱 전체 구조·상태를 모두 볼 수 있어야 함
- 모델 데이터, 실제 배포, 의존성, 로그에 이르기까지 포괄적 정보가 한 곳에 모여야 함
- 이럴 경우에만 에이전트가 실질적인 빌드, 배포, 진단까지 자동화하거나 지원 가능

### OutSystems는 코딩 에이전트와 앱 정보를 직접 연결하는 솔루션 제공

- OutSystems는 애플리케이션 PaaS(Platform-as-a-Service)로, 현대적인 개발·운영 환경을 지원
- OutSystems MCP(Mentor Connection Platform)를 도입하여, 외부 코딩 에이전트와 실제 애플리케이션을 바로 연결하는 길을 열어줌
- 이를 통해 개발자는 에이전트를 OutSystems 개발자 클라우드에 연결 가능

### OutSystems MCP를 이용하면 코딩 에이전트가 앱 전체를 분석·관리할 수 있음

- Claude Code, Codex, GitHub Copilot 등 주요 코딩 에이전트가 OutSystems MCP에 직접 연결 가능
- 연결 즉시 단일 세션에서 애플리케이션 구조, 데이터 모델, 의존성, 배포 상태, 로그 등 모든 정보를 가져올 수 있음
- 에이전트는 실제 엔티티(Entity), 화면(Screens), 로직(Logics), 역할(Roles) 등을 파악하고, 각 요소의 상호 의존 관계를 매핑함

### 에이전트가 빌드 전 실제 엔티티·화면·로직·역할 및 의존성을 탐색함

- 코딩 에이전트가 변경 작업 시작 전, 애플리케이션 내 모든 엔티티, 화면, 로직, 역할을 조사
- 각 요소가 무엇에 의존하고 있는지, 실제 동작하고 있는 구조는 어떤지 탐색
- 이 분석은 개발 실수의 최소화와 의존성 오류 방지에 크게 기여

### Mentor라는 OutSystems 내장 에이전트가 자동 빌드·배포를 처리함

- 코드 변경/개발이 완료되면, 빌드는 OutSystems 플랫폼 내장 코딩 에이전트인 'Mentor'가 담당
- Mentor가 새로운 빌드 결과물을 자동으로 애플리케이션에 배포(Deploy)하는 역할 수행
- 활용 예시: 사용자 에이전트가 구조 변경, Mentor가 빌드 및 배포 진행

### 장애가 발생하면 같은 세션에서 즉시 로그와 트레이스를 확인하여 원인 분석 가능

- 만약 문제가 발생하거나 장애가 생기면, 에이전트는 동일 세션에서 로그(Log)와 트레이스(Trace)를 실시간으로 수집
- 이를 기반으로 신속하게 문제 원인을 진단, 정확한 위치 파악 및 처리 가능
- 이는 전통적인 코드 기반 에이전트와 확연히 차별화되는 강점

### 에이전트 권한은 사용자의 플랫폼 권한과 일치하여 보안이 유지됨

- 에이전트는 OutSystems 사용자의 권한 체계를 그대로 따름
- OutSystems에서 특정 작업·정보 접근 권한이 없는 경우, 코딩 에이전트 역시 해당 작업을 수행할 수 없음
- 이를 통해 과도한 권한 남용·보안 취약점 발생을 선제적으로 차단

### OutSystems MCP는 무료 개인 버전을 제공하며 기존 코딩 에이전트와 즉시 연동 가능함

- OutSystems MCP 개인 버전은 무료로 제공되며, 활성화 후 누구나 바로 사용 가능
- 기존에 사용하던 어떤 코딩 에이전트와도 즉시 연결하여 실제 애플리케이션 전체를 통합적으로 관리·개발할 수 있음
- 영상 설명란에 OutSystems 관련 링크가 제공됨, 영상 제작자는 아웃시스템즈와 협력해 본 내용을 안내
