## *프롬프트 인젝션은 AI 에이전트 보안의 시작일 뿐임(여기에 필요한 것이 있다)* 핵심 요약

- 영상은 AI 에이전트(작업 자동화 소프트웨어)를 여러 시스템과 데이터에 연결하며 발생하는 보안 위험에 대해 다룸
- 개인적으로 ‘마이 세컨드 브레인’을 활용하여 업무를 자동화하지만, 이때 에이전트가 외부 데이터로부터 예상치 못한 명령(Prompt Injection)을 받을 수 있다는 문제를 지적
- 이를 방지하고자, 중요한 데이터가 LLM(대형언어모델)에 전달되기 전 다양한 보안 검증을 직접 구현했으며, 에이전트 접근 권한도 필요한 범위로 제한함
- 그러나 개인 단위와 달리, 기업에서는 수많은 에이전트가 클라우드와 직원 PC에서 동시에 동작하며, IT 부서는 각 에이전트의 존재, 소유자, 접근 권한을 모두 파악해야 하는 어려움 존재
- 마이크로소프트가 이 문제를 해결하기 위해 Agent 365 및 Project Perception을 개발 중임을 소개
- 이 솔루션은 각 에이전트에 고유한 ID를 부여하고, 업무별 접근 범위를 엄격히 제한하며, 보안 위험 변화에 따라 유연하게 제어 가능하도록 설계됨
- Perception 프로젝트의 ‘새로운 에이전트 인사이트’ 기능은 기존 보안 통제의 취약점과 허점을 시각적으로 분석하고, Guardian 에이전트가 전체 에이전트에 대해 집단 위험 대응을 지원함
- 동적 권한 및 위험 기반 접근 제어로 에이전트마다 임시적·한정적 리소스 접근이 가능하며, 관리자는 모든 변화의 영향을 사전 미리보기와 점진적 적용이 가능해진다
- 개인은 1개 에이전트를 통제하면 충분하지만, 조직에서는 이런 프레임워크가 수백 개 에이전트 관리에 필수임을 강조

## 세부 요약 - 주제별 정리

### AI 에이전트를 통한 자동화는 곧 민감한 데이터 및 시스템 접근 문제로 이어짐

- 발표자는 ‘마이 세컨드 브레인’이라는 AI 기반 에이전트 시스템을 사용하여 자신의 각종 업무를 자동화하고 있음
- 이러한 시스템은 생산성 및 작업 효율을 향상시키나, 동시에 다양한 내부 시스템·민감한 데이터에 접근할 필요가 있어 보안 리스크가 대두
- 권한을 너무 넓게 부여하면 데이터 유출·오용 가능성이 커지고, 지나치게 제한하면 자동화의 의미가 떨어짐

### 프롬프트 인젝션 공격은 사용자의 의도 외의 행동을 야기할 수 있음

- 프롬프트 인젝션(Prompt Injection)은 AI 에이전트가 외부에서 받은 데이터(텍스트 등)를 읽는 과정에서 악의적 명령을 삽입해 비의도적 행동을 유발하는 공격 방식임
- 예를 들어, 정상 텍스트처럼 보이는 데이터 속에, 에이전트에게 허가되지 않은 작업을 유발하는 명령이 숨겨질 수 있음
- 이런 공격은 사용자가 직접 명령하지 않은 일을 에이전트가 수행하게 만들어 위험도가 매우 높음

### 실제 LLM에 도달하기까지 다층 보안 검사 및 접근제한이 필수적임

- 영상 속 발표자는 모든 외부 입력이 실제 LLM에 전달되기 전에 여러 단계에 걸친 보안 검증 절차를 직접 설계
- 보안 검사의 목표는 악의적 명령이나 예기치 않은 프롬프트 인젝션 위협을 차단하는 것임
- 또한, 에이전트가 접근 가능한 시스템·리소스 범위를 엄격히 제한하여 사고 확산을 방지

### 개인과 달리, 기업 환경에서는 에이전트 수 증가로 보안 관리가 극도로 복잡해짐

- 기업에서는 수십, 수백 개 에이전트가 클라우드와 직원들의 로컬 장치에서 동시에 동작
- IT 관리팀은 각각의 에이전트가 어디에 있는지, 누가 소유하는지, 어떤 데이터와 시스템에 접근 가능한지 모두 실시간으로 파악해야 함
- 단순한 접근제한이나 체크리스트로는 확장된 에이전트 보안 리스크를 관리하기 어렵다는 점이 드러남

### 마이크로소프트는 Agent 365와 Project Perception을 통해 에이전트식 보안 관리의 새로운 표준을 제시함

- 마이크로소프트가 개발한 Agent 365와 Project Perception은 조직 내 에이전트 보안 문제를 해결을 목표로 함
- 각 에이전트에 고유 ID(디지털 신원)를 부여해 개별적으로 식별 및 추적할 수 있음
- 업무 목적, 리소스 종류, 조직 정책에 맞춰 접근 범위를 세밀하게 지정하는 것이 가능함

### 에이전트 접근 권한을 동적으로 제한해 위험을 실시간으로 차단함

- 접근 권한은 에이전트의 현재 업무(Task)에 따라 임시적·제한적으로 부여됨(예: 특정 시간, 특정 리소스)
- 위험도를 시스템이 지속적으로 감시하며 높은 위험 징후 발생 시 자동으로 권한을 축소하거나 추가 보안조치 실시
- 이 방식은 불필요하게 광범위한 권한 부여로 인한 보안사고 리스크를 크게 줄여줌

### Project Perception의 ‘에이전트 인사이트’로 기존 보안의 취약점을 실시간 파악 가능함

- Perception 프로젝트 내 ‘에이전트 인사이트(Agent Insights)’는 시스템 내 모든 에이전트의 상태와 권한 분포, 취약점 현황을 시각적으로 보여줌
- 관리자 및 보안 담당자가 조직 내 어디에 통제 취약점이 있는지 한눈에 파악하고 신속하게 대응할 수 있음
- ‘Guardian’ 에이전트는 개별적 사건 대응이 아니라 전체 에이전트 그룹 내의 위험을 한 번에 모니터링하고 대처

### 위험 기반 접근 제어(Risk-Based Access Control)로 로그인 이외의 상황도 지속 평가함

- 전통적 방식은 로그인, 인증 시점에만 접근을 제어했음
- Project Perception은 에이전트가 실제로 지원하는 행동 및 업무 맥락, 현재 위험도, 정책 준수 여부를 지속적으로 평가
- 위험 또는 정책 위반 시 실시간으로 접근 권한 제어 및 추가 조치 가능

### 변경 사항은 미리 검토·시뮬레이션 후 전체 조직에 단계적으로 적용됨

- 관리자는 새로운 보안 설정 적용 전, 미리 영향도를 시뮬레이션(Previews)하고 추천된 보호책을 검토 가능
- 승인된 보호책만 순차적으로 배포하여 조직 전체의 서비스 연속성을 보장함
- 기존 인프라와 직원의 접근 권한에는 영향을 주지 않으므로, 업무단절없이 보안 강화를 실현

### 소규모 환경의 보안 수단을 수백 개 에이전트 상황까지 확장하는 방식을 제시함

- 영상 발표자는 개인적으로 1개 에이전트 대상 보안 제어 방식을 활용했음을 밝힘
- 마이크로소프트의 솔루션은 이러한 노하우를 대기업 환경, 즉 수십~수백 개 에이전트가 혼재하는 상황까지 자동적으로 확장해 적용 가능하도록 설계됨
- 실제 협업 과정에서 마이크로소프트와 함께 이 시스템을 구축했다고 강조하며, 관련 링크를 제공함
