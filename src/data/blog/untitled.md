## *나는 AI 에이전트가 코드를 머지하는 것은 신뢰하지만, 프로덕션 배포는 직접 검토한다* 핵심 요약

- 영상 제작자는 AI 에이전트가 코드 머지(merge)를 자동으로 처리하게 맡길 정도로 신뢰하지만, 실제 프로덕션 반영(배포, shipping)은 본인이 직접 검토 후 진행함
- AI 소프트웨어 파이프라인은 스테이징 환경까지만 자동화되고, 프로덕션 반영은 수동 검토 필요
- 에이전트가 관리하는 테스트와 리뷰는 코드가 ‘겉보기에 적합한지’만 확인하며, 실제 변경의 영향은 사용자 앞에 적용되기 전까지 확실히 알 수 없음
- 수년간의 업계 경험을 바탕으로, 중요한 기능 배포 시 ‘피처 플래그(Feature Flag)’로 변화된 코드를 제한적 사용자에게 노출시키고, 문제 발생 시 즉시 비활성화하는 방법이 표준으로 사용됨
- 전통적으로 엔지니어가 수작업으로 플래그 코드를 삽입해야 했기 때문에, 많은 팀들이 이 프로세스를 완전히 자동화하지 못했음
- 대량의 PR(풀리퀘스트)을 자동 생성하는 에이전트 시대에는 기존 플래그 관리에 인력이 따라가기 어려움
- LaunchDarkly는 배포 후 실시간 통제, 기능 플래그 관리, 그리고 최근 출시한 ‘Release Autopilot’을 통해 플래그 삽입 작업 역시 에이전트가 수행 가능하도록 지원함
- Release Autopilot은 위험 분류, 프로덕션 성공 지표 설정, 카나리 릴리즈, 실시간 관찰, 플래그 정리까지 자동화하여, 사람이 직접 모든 변경을 최종 승인하도록 설계됨
- 모든 단계는 풀리퀘스트에서 명시적으로 승인 받아야 적용되므로, 에이전트 신뢰도를 무조건적으로 높이지 않아도 됨
- LaunchDarkly와의 협업을 언급하며, 영상 설명란에 추가 정보를 제공한다고 안내

## 세부 요약 - 주제별 정리

### AI 에이전트는 코드 병합을 자동화할 수 있지만 프로덕션 반영은 신뢰할 수 없음

- 영상 제작자는 AI 에이전트가 밤새 코드를 병합(merge)하는 것은 신뢰한다고 밝힘
- 하지만 코드가 바로 프로덕션(실제 서비스 환경)까지 배포되는 것은 신뢰하지 않음
- 모든 변경사항은 우선 스테이징(staging) 환경까지만 자동화로 진행
- 최종적으로 프로덕션에 반영되기 전, 본인이 직접 코드 리뷰와 검증을 수행함

### 에이전트가 수행하는 테스트와 리뷰는 코드의 적합성만 확인할 뿐 실제 영향은 알 수 없음

- AI 에이전트가 실행하는 테스트와 리뷰는 코드가 ‘겉보기에’ 맞는지만 확인 가능
- 실제로 코드 변경이 사용자에게 어떤 영향을 미치는지는 실서비스에서만 파악 가능
- 기존 자동화 도구만으로는 변경의 ‘실질적 위험’을 완전히 파악하기 어려움

### 피처 플래그(Feature Flag) 도입으로 점진적 배포와 신속한 롤백이 가능해짐

- 수년 동안 업계 표준으로 자리잡은 방식은 ‘피처 플래그’를 이용하는 것임
- 새로운 변경은 플래그로 감싸서 일부분 사용자에게만 우선 배포
- 이상 징후나 문제 발생 시 즉각적으로 플래그를 끄고 영향을 최소화할 수 있음
- “답은 이미 오래 전부터 나와 있었다”고 언급

### 수작업 플래그 삽입은 번거롭고, 많은 팀이 완전 자동화를 실현하지 못함

- 엔지니어가 직접 플래그 코드를 삽입해야 했던 과거의 시스템이 언급됨
- 거의 모든 팀이 이 과정을 완전히 자동화하지 못했고, 실제 플래그 관리를 소홀히 하는 경우 많았음
- 대규모로 반복되는 PR 작업에 사람 인력이 따라가지 못함

### 대규모 Pull Request를 자동화하는 에이전트 시대에 기존 방법이 한계에 부딪힘

- 에이전트가 대량의 Pull Request를 생성하는 환경에서는 플래그 관리를 사람이 수동으로 따라가기가 비효율적임
- 실시간으로 많은 변경이 이루어지면서, 위험 통제가 어려워지는 문제 지적

### LaunchDarkly는 프로덕션 배포 후에도 변경 사항 통제를 제공하며 최신 자동화 솔루션을 도입함

- LaunchDarkly는 실시간 배포 변경사항 통제 및 기능 플래그 관리 솔루션을 제공하는 회사임
- 최근 ‘Release Autopilot’ 기능을 출시하여, 에이전트 기반 개발 환경에 특화된 자동화 지원을 시작함

### Release Autopilot은 엔지니어가 직접 하지 않아도 플래그 처리와 배포 계획을 자동으로 관리함

- Release Autopilot은 에이전트가 자동으로 피처 플래그를 추가하는 기능을 담당
- 사람이 단계별로 직접 관여하지 않고도 플래그 구현, 위험 식별, 배포 단계 관리가 가능해짐

### 위험 분류부터 카나리 릴리즈, 실시간 관찰, 자동 플래그 정리까지 Release Autopilot이 단계별 지원함

- 위험(Risk) 분류 기능: 변경의 위험도를 평가하여 플래그 적용 여부를 결정
- 성공 지표(Success Metrics) 설정: 배포된 변경이 성공적으로 동작하는 기준을 정의
- 자동 배포 계획: 우선 소수 사용자(카나리)를 대상으로 릴리즈하고, 문제가 없으면 점진적으로 범위 확대
- 피처 관찰(Observability): 프로덕션 환경에서 실시간으로 변경사항 작동 여부를 관찰
- 플래그 정리(cleanup): 쌓인 플래그들을 정리하여 코드베이스를 깔끔하게 유지

### 최종 승인 구조로 완전 자동화 위험성을 방지하고, 에이전트 신뢰도와 무관하게 심사 절차를 거침

- 자동화 플래그 추가가 풀리퀘스트(PR) 단계에서 ‘제안’만 되고, 실제 적용 전에는 최종 승인이 반드시 필요
- 따라서, 에이전트의 신뢰 수준이 높지 않아도 사람이 직접 모든 변경을 컨트롤할 수 있음
- 모든 변경사항은 실제 사용자 일부에게 먼저 적용되어 결과를 확인한 뒤 더 큰 범위로 확장됨

### 영상 마무리에서 LaunchDarkly 협업을 언급하고, 추가 정보 제공처를 안내함

- 영상의 협업 스폰서로 LaunchDarkly를 명시
- 더 자세한 정보는 영상 설명란에 링크로 제공한다고 안내함
