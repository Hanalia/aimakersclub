## *나는 내 AI 에이전트에게 코드 머지는 맡기지만, 프로덕션 배포는 직접 확인한다* 핵심 요약

- AI 에이전트가 밤새 코드를 병합(merge)하게 할 정도로 자동화 신뢰도가 높지만, 실제 프로덕션 배포(ship)는 신뢰하지 않는다.
- AI 소프트웨어 공장은 스테이징(staging) 환경까지만 자동화하고, 실제 배포는 사람이 리뷰한다.
- 에이전트가 수행하는 테스트와 리뷰는 코드가 "겉보기엔" 문제없음을 보여주지만, 실제 영향은 실사용자 앞에서만 확인 가능하다.
- 코드 변경의 실제 성능과 부작용 파악을 위해선, 변경을 기능 플래그(feature flag)로 감싸 일부 사용자에게만 공개하고 이상 시 즉시 롤백하는 접근이 필요하다.
- 과거에는 기능 플래그 추가가 엔지니어의 수작업으로 이루어져, 많은 팀들이 미완성 상태로 도입하거나 관리에 실패했다.
- AI 에이전트가 대규모로 PR(풀 리퀘스트)을 열게 된 오늘날엔, 이 플래그 작업을 자동으로 처리하는 도구가 필요하다.
- Launch Darkly는 프로덕션 단계에서 변경사항을 제어할 수 있는 기능 플래그 시스템을 제공한다.
- 새로 출시된 Launch Darkly의 "릴리즈 오토파일럿(Release Autopilot)"은 에이전트가 플래그 추가·삭제 과정을 자동으로 처리한다.
- 변경의 위험도 분류, 성공 지표 설정, 카나리 릴리즈, 실시간 관측, 플래그 마무리 정리 등 모든 단계를 자동화함으로써 안정적인 배포 과정을 보장한다.
- 여전히 마지막 승인은 사람이 직접 해야 하며, 누구나 실사용자 대상 테스트 후 안전하게 전체 배포할 수 있다.

## 세부 요약 - 주제별 정리

### 나는 AI 에이전트에게 코드 병합은 맡기지만 프로덕션 배포까지는 신뢰하지 않는다

- 밤새 코드를 자동으로 병합하는 등의 역할은 AI 에이전트에게 맡길 수 있을 정도로 신뢰도가 높아졌다.
- 하지만 프로덕션(실제 사용자 환경) 환경에는 변경사항을 바로 배포하지 않는다.
- 이유는 실제 변화의 영향(부작용 여부 등)을 확인할 수 없기 때문이다.

### 내 AI 소프트웨어 공장은 스테이징 환경까지만 자동화하며 최종 배포는 직접 점검한다

- 소프트웨어 개발 파이프라인에서 "스테이징(staging)" 환경까지는 자동화해서 에이전트가 작업한다.
- 프로덕션에 반영하기 전에는 직접 검토하고 승인 과정을 거치도록 한다.
- 자동화된 테스트와 코드 리뷰가 통과해도, 실제로 어떤 변화가 있을지 확신할 수 없기 때문임을 강조한다.

### 에이전트의 테스트와 리뷰는 코드의 겉모습만 확인할 뿐 실제 효과는 실사용자 환경에서만 알 수 있다

- 에이전트가 수행하는 자동화된 테스트와 리뷰는 코드가 외형상 올바른지에 대한 피드백만 제공한다.
- 실제 코드 변경이 서비스에 미치는 영향, 에러, 성능 저하 등은 실제 사용자가 접했을 때만 알 수 있다.

### 코드 변경을 안전하게 실사용자에게 점진적으로 공개하는 해법은 오래전부터 존재했다

- 기존에도 변경 사항을 바로 전면 배포하지 않고, "기능 플래그(feature flag)"로 감싸 일부 사용자에게만 노출하는 방법이 널리 쓰였다.
- 문제 발생 시 기능 플래그를 꺼서 즉각적으로 변경을 롤백할 수 있다.
- 이 방법은 여러 해 전부터 효과적인 전략으로 알려져 왔다.

### 전통적으로 기능 플래그 추가는 엔지니어의 수작업이 필요해 대부분의 팀이 완전한 도입에 실패했다

- 기능 플래그를 코드에 넣는 작업은 엔지니어가 일일이 손으로 처리해야 했다.
- 결국 시간과 노력 등 관리 부담으로 인해 대부분의 개발 팀에서 부분 적용에 그쳤다.
- 특히 대규모 PR이 발생하는 상황에서는 이 기능이 현실적으로 제대로 적용되지 못했다.

### 에이전트가 대규모대로 PR을 생성하는 시대에는 기능 플래그 관리의 자동화가 더욱 시급하다

- 현재는 AI 에이전트가 다수의 변경(PRs, 풀 리퀘스트)을 한꺼번에 제출할 수 있다.
- 이런 대규모 상황에선 기능 플래그 관리를 수작업으로 할 수 없으며, 자동화 솔루션이 필요하다.

### Launch Darkly는 프로덕션 환경에서 변경사항을 통제할 수 있는 플래그 시스템을 제공한다

- Launch Darkly라는 전문 SaaS 도구는 실시간으로 프로덕션 환경의 기능 플래그 전체를 관리한다.
- 기능 플래그를 활용해 각 변경(build, 코드 변경)에 대한 릴리즈 정책 적용이 가능하다.

### Launch Darkly의 "릴리즈 오토파일럿"은 기능 플래그의 자동 생성과 운용을 에이전트에 맡긴다

- 최근 출시된 "Release Autopilot" 기능으로, 에이전트가 PR 단계에서 플래그 관련 작업을 모두 자동 처리.
- 사람이 따로 기능 플래그 추가/삭제 코드를 작성하지 않아도 된다.
- 모든 단계가 플랫폼에서 순차적으로 자동화된다.

### 위험도 분류, 성공 지표 설정, 카나리 릴리즈, 실시간 관측, 플래그 클린업까지 전체 배포 과정을 자동화한다

- "Risk classification(위험도 분류)": 변경의 위험도를 판별, 필요시 플래그로 감싼다.
- "Success metrics(성공 지표 설정)": 변경 후 실사용자 환경에서 어떤 성과를 기대할지 자동 지정한다.
- "Automatic release plan(자동 릴리즈 계획)": 카나리 릴리즈 방식으로, 초기엔 일부 사용자에게만 적용, 문제가 없을 때 점진적 확대.
- "Feature level observability(기능 단위 관측)": 실시간으로 라이브 신호를 바탕으로 문제가 없는지 지속 모니터링.
- "Flag cleanup(플래그 클린업)": 장기간 불필요하게 남은 플래그를 정리하고 코드베이스를 청결하게 유지한다.

### 최종 승인 버튼으로 사람이 직접 통제할 수 있어 전면 자동화의 위험을 막는다

- 모든 변경은 PR(풀 리퀘스트) 상에서 새로운 기능 플래그 도입이 "제안"되는 형태로 노출된다.
- 실제 코드베이스에 적용되기 전에 담당자가 직접 승인해야만 변경이 실제 서비스에 반영된다.
- 따라서 AI 에이전트를 완전히 신뢰할 필요 없이, 마지막 검토와 통제 권한은 사람이 가진다.
- 실사용자 대상의 안전성 테스트를 거친 후에만 전체 서비스로 전개할 수 있다.
