## *프롬프트 인젝션은 AI 에이전트 보안의 시작일 뿐이다 (당신이 진짜로 필요한 것)* 핵심 요약

- 영상은 AI 에이전트(스마트 자동화 도구)를 실제로 업무에 활용하면서 직면하는 보안 위협과 이슈를 구체적으로 제시함
- 사용자는 ‘두 번째 뇌’라고 부를 만큼 다양한 업무를 AI 에이전트에 맡기지만, 이는 민감한 시스템 및 데이터에 대한 폭넓은 접근 권한을 의미함
- AI 에이전트가 외부 데이터를 읽을 때, 사용자가 의도하지 않은 명령(Prompt Injection)이 실행될 수 있다는 심각한 보안 우려가 있음
- 이에 따라, 영상 제작자는 직접 보안 점검 시스템을 구축해 외부 입력을 대형언어모델(LLM)에 전달하기 전에 필터링하고, 접근권한을 필수 범위로만 제한함
- 개인 수준에서는 직접 구축이 가능하지만, 기업 환경에서는 수많은 에이전트가 직원들의 기기와 클라우드 환경에 분산되어 더욱 복잡한 관리가 필수임
- 이 문제를 해결하기 위해 Microsoft가 “Agent 365”와 “프로젝트 Perception”을 개발, 에이전트 별 고유한 신원, 세분화된 접근권한, 리스크 기반의 동적 권한 및 통합 관리 기능을 제공함
- 프로젝트 Perception은 기존 시스템의 보안 취약 지점을 시각화하고, Guardian 에이전트가 팀 전체를 한 번에 보호할 수 있도록 지원함
- 동적 권한 부여와 리스크 기반 액세스 제어, 점진적 도입 및 미리보기 기능 등 관리 편의성과 안전성이 모두 확장되어 기업용 에이전트 보안 강화에 기여함

## 세부 요약 - 주제별 정리

### AI 에이전트의 활용이 업무 생산성과 함께 보안 리스크를 동반함

- 제작자는 ‘두 번째 뇌’(Second Brain) 역할을 하는 AI 에이전트로 자신의 많은 업무를 자동화, 관리 중임
- 실질적으로 AI 에이전트가 여러 시스템과 데이터에 접근해야 하므로, 각종 민감 정보, 회사 내부 시스템과 연결됨
- 이로 인해, 에이전트를 신뢰할 수 있으려면 보안에 대한 깊은 고민과 대비가 필요함

### 프롬프트 인젝션(Prompt Injection) 공격이 가장 기본적이고 심각한 보안 위협임

- AI 에이전트가 외부 데이터를 읽는 과정에서, 그 데이터에 명령이 숨겨져 있을 수 있음
- 즉, 사용자가 명령하지 않은 행동을 에이전트가 수행할 가능성이 있음
- 이런 유형의 공격을 프롬프트 인젝션이라고 하며, AI 에이전트 실무 활용시 가장 먼저 고려해야 할 보안 우려로 지적됨

### 제작자는 직접 보안 필터링 시스템을 도입해 리스크를 최소화함

- 영상 제작자는 모든 외부 입력 데이터를 대형언어모델(LLM)로 보내기 전, 자체적으로 보안 체크를 거치게 설계함
- 보안 점검 시스템을 ‘두 번째 뇌’ 내부에 내장해, 잠재적 명령 주입 및 악의적 지시를 차단함
- 에이전트의 접근권한도 가능한 한 최소화, 꼭 필요한 자원과 데이터에만 접근가능하도록 제한 설정

### 조직 환경에서는 에이전트의 수와 다양성 때문에 보안 관리가 훨씬 복잡해짐

- 개인 사용자는 직접 보안 설계를 할 수 있지만, 기업에서는 수많은 에이전트가 직원들의 기기 및 클라우드 상에서 동작함
- IT 부서는 “어떤 에이전트가 어디에 설치되어 있는가, 누가 소유자인가, 어떤 권한을 갖고 있는가?”라는 질문에 즉각 답해야 함
- 에이전트 관리와 보안 통제에 체계적이고 중앙화된 방식이 요구됨

### Microsoft는 Agent 365와 프로젝트 Perception을 통해 조직형 에이전트 보안 관리를 지원함

- Microsoft는 이 문제의 해결을 위해 “Agent 365”와 “프로젝트 Perception”이라는 새로운 플랫폼을 개발
- 각 에이전트에게 고유한 신원(Identity)을 부여하고, 접근권한을 업무 단위로 세밀하게 분할
- 위험도가 변할 때마다 에이전트의 행동과 권한을 즉각적으로 제한하거나 변경 가능

### 프로젝트 Perception은 에이전트 보안의 사각지대를 가시적으로 드러냄

- Perception은 조직 내 누구에게 어떤 권한이 있고, 어떤 통제 지점이 취약한지를 대시보드로 시각화해 보여줌
- IT 관리자는 자신의 보호 장치의 빈틈(보안 사각지대)이 어디에 있는지 실시간으로 파악 가능

### Guardian 에이전트 기능으로 팀 전체의 위험 관리를 자동화함

- 개별 에이전트별로 사건을 추적하는 대신, Guardian 에이전트가 팀 전체를 단일 정책 기반 아래 통합 보호
- 특정 이벤트가 발생할 때 마다 일일이 조사할 필요 없이, 조직 전체를 아우르는 리스크 관리가 가능해짐

### 동적 권한(Dynamic Permission) 기능으로 에이전트의 접근을 임시적·목적 기반으로 제한함

- Dynamic Permission 기능을 통해, 에이전트가 특정 임무를 수행할 때만 자원에 일시적으로 접근하도록 제한
- 지원 자원에 대해서만 필요 시간 동안 접근 가능, 업무 종료 시 자동으로 제한 복원

### 위험 기반의 액세스 제어와 정책 일관성을 확보함

- Risk-based access control 기능을 통해, 에이전트의 행동(행동 컨텍스트)과 현행 보안 정책을 복합적으로 평가
- 단순 로그인 시점이 아니라 실제 명령 실행 시점마다 보안 정책 적용 및 재평가가 진행됨

### 관리자는 권고 보호조치 미리보기 및 점진적 적용으로 안정적인 운영이 가능함

- 시스템은 관리자에게 새롭게 권고되는 보안 보호조치를 제시하며, 적용 시 미칠 영향(예: 업무 차질)을 사전 미리보기로 제공
- 관리자 승인 하에 점진적(Gradual rollout) 적용이 가능해서, 대규모 환경에서도 안전하게 신규 보안 정책을 도입할 수 있음

### 여러 에이전트에 대한 동일한 보안을 일괄 적용하여 확장성과 효율성을 달성함

- 영상 제작자는 이러한 시스템을 한 명의 에이전트에 단독 적용했으나, Microsoft 솔루션으로는 수백 개의 에이전트에도 일괄 적용 가능
- 대규모 조직 환경에서 AI 에이전트 보안의 확장성과 효율성을 동시에 확보함
