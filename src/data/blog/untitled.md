## *나는 내 AI 에이전트가 코드를 병합하는 건 믿지만, 실제 배포는 신뢰하지 않는다* 핵심 요약

- 영상 제작자는 AI 에이전트가 코드 병합까지는 신뢰하지만, 프로덕션(실서비스) 배포까지 맡기지는 않는다고 언급함
- AI 소프트웨어 자동화 공정은 스테이징 환경(테스트 서버)까지만 진행되고, 실제 배포 전에는 직접 검토를 거침
- 에이전트가 수행하는 테스트와 리뷰는 코드가 "겉보기에" 맞는지를 판단할 뿐, 실사용자 환경에서의 진짜 영향은 확인할 수 없음
- 이전부터 실사용자 영향 파악을 위해 ‘피처 플래그(feature flag)’와 소수 사용자 대상 배포(롤아웃) 전략이 활용됨
- 과거에는 엔지니어가 직접 플래그 코드 삽입 작업을 해야 했으나, 번거로움과 대규모 PR 발생으로 실질 적용에 제약이 있었음
- Launch Darkly 제품은 배포된 코드의 동작을 프로덕션 단계에서 정밀하게 통제할 수 있게 하여 시장에서 이미 주요 역할을 함
- 새로운 ‘Release Autopilot’ 기능은 AI 에이전트가 피처 플래그 추가 작업을 자동화하여 사람이 일일이 처리하지 않아도 됨
- 위험도 분류, 성공 메트릭 및 가드레일 설정, 카나리 릴리스(선별 소수 사용자 배포), 실시간 피처 관측, 플래그 정리 등 절차가 자동 처리됨
- 완전 자동이 아니라, 풀 리퀘스트(PR) 단계에서 승인 전까지 실제 변경이 적용되지 않아 ‘사람 확인’이 보장됨
- 결국 모든 변경은 실제 사용자에 대한 영향이 확인되고 승인된 후에만 전체 배포가 이루어짐

## 세부 요약 - 주제별 정리

### AI 에이전트에게 전체 배포를 맡기지 않는 이유가 명확히 존재함

- 영상 제작자는 자신의 AI 에이전트들이 야간에도 코드를 자동 병합(merge)하도록 신뢰한다고 밝힘
- 그러나 코드가 실서비스(프로덕션) 서버에 직접 배포(ship)되는 것은 에이전트에게 맡기지 않는다고 단언함
- AI 소프트웨어 팩토리 자동화의 한계점이 존재하며, 스테이징(검증용) 환경까지만 자동화 공정이 이뤄짐
- 이유는 자동화된 테스트와 리뷰 과정이 코드의 겉모습이나 논리만 체크할 뿐, 실제 이용자 환경에서의 문제점까지 감지할 수 없기 때문임

### 실사용자 환경에서의 코드 영향은 사전 예측이 어려움

- 에이전트가 실시하는 리뷰와 테스트 등은 "코드가 보기에는 올바른지"를 평가함
- 하지만 코드 변경이 진짜 사용자 거래, 데이터, 실서비스 흐름에 어떤 영향을 미칠지는 실제 운영에 투입 전까지 알기 어렵다고 강조
- 실사용자 트래픽에 미치는 영향, 예기치 못한 버그, 비즈니스 핵심 이슈 등은 자동 툴만으로 전체 판단이 불가함

### 피처 플래그를 통한 점진적 배포가 올바른 해답이 되어 옴

- 영상에서는 "이 문제에 대한 해답은 이미 몇 년 전부터 있었다"고 언급
- 그 해답은 프로덕션 변경 사항을 피처 플래그(feature flag, 기능 토글) 뒤에 숨기고, 일부 사용자(예: 내부, 베타 그룹)에게만 점진적으로 공개하는 접근임
- 문제 발생 시 플래그를 즉시 비활성화할 수 있어, 위험 제어 및 서비스 연속성 유지 강점이 있음

### 과거에는 피처 플래그 적용이 수동이었기에 확산에 한계가 있었음

- 플래그 삽입이나 관리 작업을 엔지니어가 직접(수동) 코드에 추가해야 했음
- 이런 번거로움 때문에 많은 팀들이 피처 플래그를 완전히 적용하지 못하거나, 꾸준히 관리하지 못하는 한계가 있었음을 설명

### AI 에이전트의 대규모 코드 변경 PR에서 피처 플래그 관리가 어려워짐

- 대규모 PR(풀리퀘스트) 발생 상황에서는 수동 플래그 관리가 비효율적임
- 사람이 모든 PR을 일일이 플래그 추가하고 관리하는 것은 현실적으로 불가능해짐

### Launch Darkly 제품은 실서비스 단계에서 배포 통제를 가능하게 함

- Launch Darkly는 소프트웨어 배포 시 코드 변경의 실제 프로덕션(실서비스) 동작을 정밀하게 제어 가능한 주요 툴로 자리매김
- 실시간 모니터링, 롤백, 플래그 비활성화 등 복수의 통제 기능 제공

### Release Autopilot 기능은 AI 에이전트가 플래그 작업을 자동 수행하게 만듦

- 최근 런치 다클리에서 "Release Autopilot" 기능을 새롭게 출시함
- 이 기능은 AI 에이전트가 피처 플래그 생성 및 관리 작업을 자동화함으로써, 대규모 반복 작업 부담을 줄여 줌

### 자동화된 위험 분류, 성공 기준 설정, 점진 릴리즈 및 클린업 절차가 추가됨

- 에이전트가 코드 변경의 위험도를 자동 분류하여, 위험 높은 변경에는 강제로 피처 플래그를 적용
- 성공 측정을 위한 메트릭(metrics)이 자동 설정됨 (예: 성능, 오류율 등)
- 배포 계획 자동 생성: 처음에는 카나리 릴리즈(일부 소수 사용자)로 한정하여 문제가 없는 경우에만 대상 범위를 확대함
- 코드가 실서비스에 적용된 후 관측 지표(관측 가능성, observability)를 통해 실시간으로 체크
- 필요 없는 플래그 혹은 만료된 플래그는 코드베이스에서 자동으로 정리(cleanup)됨

### 업무 흐름상에서 완전 자동화 대신 ‘최종 승인’ 안전장치가 보장됨

- 완전 자동화가 아니라, 풀리퀘스트 단계에서 AI 에이전트가 플래그 적용 및 배포 계획을 "제안"만 함
- 실제 전체 변경 사항은 사람이 직접 검토 및 최종 승인한 뒤에야 적용되어 추가 리스크를 막음
- 덕분에 AI 에이전트에 대한 신뢰 부담 없이, 사람의 '감독' 아래 운영 가능함

### 모든 변경은 실제 사용자에게 적용된 성과 확인 및 승인 후 전체 배포됨

- 최종 승인 전까지는 완전 배포가 이뤄지지 않아, 전체 서비스에 이상 영향 최소화
- 실제 사용자 반응, 실시간 지표, 성공/실패 체크 결과를 토대로 전체 릴리즈 확장 여부를 결정함

### 영상 마무리 및 제휴 고지

- 영상 말미에서 제작자는 Launch Darkly와 협업하며 기능을 소개했다고 언급
- 더 자세한 정보나 링크는 영상 하단 설명란에서 확인 가능함
