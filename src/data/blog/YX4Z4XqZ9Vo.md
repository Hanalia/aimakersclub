## *대부분의 문서 독자는 이제 AI 에이전트이다* 핵심 요약

- 본 영상은 Mintlify CTO 이한비와 Coinbase AI 제품 총괄 링컨 머가 등장하여, 현대 인터넷과 소프트웨어 환경에서 ‘AI 에이전트’가 핵심 사용자로 부상함에 따른 변화와 기업 전략을 다룸
- 화자는 AI 에이전트가 점점 인터넷에서 주요 행동 주체가 되며, 이전의 디자인/프론트엔드 중심 문서 설계가 무의미해지고, 정확한 데이터 및 적절한 API 접근성이 핵심 요소가 된다고 주장
- Coinbase는 AI 에이전트와 스테이블코인(특히 X402 등) 기술이 결합되는 시점에서, 자사 서비스의 ‘API 우선 설계’와 ‘금융 보안 및 인증’ 강화를 적극적으로 진행 중임
- AI 에이전트의 자율성은 마이크로페이먼트(최소 100만 분의 1센트 단위)까지 지원하는 암호화폐의 장점과 맞물려, 자동 거래·서비스 접근의 새로운 장을 열고 있음
- 지난 1년간 약 1억 건 이상의 AI 에이전트 기반 온체인 거래가 이뤄졌으며, 주로 API와 서비스 구독·이용에 집중됨
- Mintlify 측 통계에 따르면, 개발자 문서 페이지의 ‘AI 에이전트’ 비중이 1년 만에 10%→80%로 급증하였으며, 이는 인간 방문자 수 변화 없이 에이전트 사용량 자체가 폭발적으로 증가한 결과
- 개발사와 서비스 기업들은 API 및 인터페이스 다변화(MCP, CLI 등)를 통해 AI 에이전트 친화적 환경을 구축해야 하며, 장기적으로 ‘인간-에이전트-서비스’ 상호작용이 일상화될 전망
- 문서 작성·유지에는 여전히 ‘인간의 창의성’과 AI 기반 자동화가 공존하며, 기업들은 핵심 모듈 이외는 자체 구축보다 전문 솔루션 활용(빌드 vs. 바이) 전략이 권장됨
- 에이전트의 자금 접근성, 안전성, 장기 실행력 등은 금융 인프라와 NFT/DAO 등 블록체인 구조를 통해 한층 발전 중임
- 빠르게 진화하는 시장에서, 기업은 기술 변화와 표준 업데이트를 전담 유지하는 외부 도구 활용이 유지비·경쟁력 측면에서 유리하다고 강조함

## 세부 요약 - 주제별 정리

### AI 에이전트의 부상은 소프트웨어 문서 설계와 사용자 경험의 본질을 바꾸고 있음

- Mintlify(2022년 설립)가 기존에는 디자인을 중시하는 ‘디자인 중심’ 회사였으나, 현재는 AI 에이전트가 주요 독자가 되면서 새로운 전략이 필요해짐
- AI 에이전트는 웹사이트 디자인·브랜딩에는 관심이 없으며, 오로지 페이지 용량(콘텍스트 윈도우)·정확성 등 데이터 품질이 중요해짐
- 에이전트는 오류 혹은 마찰이 발생하면 즉시 다른 서비스로 이탈할 수 있으므로, 문서의 정확성과 자동화 통한 최신성 유지가 필수적임
- ‘생산성’ 관점에서 개발 팀(EPD)이 AI 도입으로 비약적으로 앞서가고 있으며, 조직 전체가 AI 기반 자동화로 속도를 맞춰야 함
- 좋은 문서의 기준은 AI와 사람이 다르게 인식하며, 자동 알림 및 관리 자동화로 ‘문서 노후화 방지’가 중요하다고 언급

### AI 에이전트와 디지털 결제 수단(특히 암호화폐)의 만남이 새로운 기회를 창출함

- Coinbase는 AI 에이전트가 실제 거래(특히 스테이블코인 기반)를 할 수 있는 환경이 급속히 현실화됨에 주목
- ‘모바일 전환’이 새 패러다임을 만들었던 과거처럼, 이제는 ‘모바일→에이전트’로 진화하는 변혁 시기가 도래
- API를 통한 기능 개방이 서비스의 필수 구조가 되고 있으며, 현재는 브라우저 상호작용에도 한계·위험(보안, 인증 등)이 많음
- 미래에는 사용자가 “내 계정을 AI에게 완전히 맡기는” 상황이 올 것이라 제시(모바일 뱅킹 도입 초창기와 미래 에이전트 금융관리 비교)
- 에이전트가 API로 계좌 접근 및 한도, 가드레일 등 통제가 가능한 구조가 필수임

### 암호화폐의 API 결제와 미세 결제 기능이 에이전트 경제에서 결정적 역할을 함

- X402: Coinbase 등에서 주도하는 ‘인터넷 네이티브 결제 표준’으로, Cloudflare/Stripe/Amex/Mastercard/Visa 등이 공동 참여하는 재단 설립
- 암호화폐(특히 디지털 달러·스테이블코인)는 전 세계 어디서든 저렴하고, 빠르며, ‘허가 불필요’ 방식으로 송금·결제 가능
- 가장 큰 장점은 마이크로트랜잭션(1000분의 1~100만 분의 1센트 수준)이 가능해, 다양한 API/서비스를 아주 작은 단위로 정산 가능
- AI 에이전트가 자유롭게 거래하고 돈을 쓸 수 있게 되면 자율성과 활용도가 비약적으로 향상됨

### 이미 1억 건 수준의 에이전트 기반 온체인 거래가 실현되고 있음

- 지난 1년간 실제로 약 1억 건(agentic transactions)의 에이전트 주도 암호화폐 거래가 이뤄졌음(모두 공개적으로 감사 가능)
- 주로 API 거래, 서비스 이용료 지불 등 활용이 많음
- 전통적 온라인 서비스는 사이트별로 회원가입, 계좌 충전, API 키 입력 등 복잡한 과정을 요구하지만, 에이전트는 지갑만 있으면 여러 API를 즉시 결제·이용 가능
- 이로 인해 ‘금전 접근이 곧 활동 범위’임을 강조—AI에게도 마찬가지로, 에이전트의 결제/거래 능력이 곧 독립성과 활용성 확장의 열쇠임

### API, MCP, CLI 등 다양한 인터페이스 전략이 공존하며 에이전트 친화적 아키텍처가 필요함

- Coinbase는 에이전트 친화성 확보를 위해 API 우선(AI-Friendly APIs) 정책을 적극 추진
- MCP(자연어 기반 인터페이스), CLI(터미널 명령조작) 등도 필요하지만 본질은 모두 API에 연결됨
- 에이전트가 활용할 수 있는 형식이라면 래핑이 달라질 뿐, API가 기본 지층임을 강조
- 각 자 인터페이스는 상황별 이점/한계가 있으며, 현재는 어디가 '종착점'이 될지 모르는 초기에 있다고 평가

### 에이전트에 돈을 맡길 수 있는 ‘금융적 자율성’이 장기 에이전트의 핵심 조건임

- 에이전트가 결제수단·금융 계정을 가지면 보호장치(한도, 인증) 등을 갖추고, 독자적으로 각종 서비스/정보/기업 설립까지 대리 가능
- DAO(탈중앙 자율조직)는 기존에 ‘자동화된 조직’ 비전을 품었으나, 현실은 인간의 관여로 인해 비효율/파편화됨
- 진짜 DAO적 자동화를 구현하려면 ‘에이전트+금융자율성’ 조합이 필요하며, AI가 실질적으로 자기 권한 아래서 업무를 처리해야 함

### 개발자 문서 사이트에서 에이전트의 트래픽 비율이 폭증하며, 문서 전략이 달라지고 있음

- Mintlify 내 통계: 2023년 초 전체 트래픽 중 에이전트 비율 10% → 현재(2024년) 80%로 증가
- 회사 내부적으로 ‘에이전트 뷰율’ 기록, 직원들이 매주 도달률을 예측하며 경향성 관측
- 인간 뷰어는 줄지 않고 에이전트 사용량만 급증, AI 특유의 ‘방대한 콘텍스트’ 활용이 핵심 변수로 분석
- 에이전트의 완전 자동화 활용을 위해선 문서의 적시성, 일관성, 정확도 확보가 더욱 중요

### AI 및 소프트웨어 기업들은 API/자동화 투자가 필수적임을 깨닫고 있으며, 전통적 방식과의 혼재기임

- 에이전트는 개발자와 비슷하게 운영되므로(바시 셸, CLI 명령 등에 능숙), 처음엔 개발자 지향성이 강하다고 설명
- 대다수 소프트웨어 기업은 기술이 전통적으로 보이더라도 API 확대를 놓쳐선 안 된다고 언급
- 결국 모든 인터페이스를 에이전트화 해야 하며, 현재는 ‘개발자/에이전트 친화 아키텍처’로 집중하는 추세

### 인간이 직접 작성한 문서와 AI가 자동 생성한 문서는 그 쓰임새와 가치가 다름

- ‘서사적/창의적’ 글쓰기(팀 커뮤니케이션 등)는 인간의 섬세함이 여전히 필요, 실제 개발자들도 코드 작성은 AI에 의존하지만 문서화는 인간이 직접 하는 경향
- 팀 내부에서도 AI 생성 vs. 수기 작성 문서 간에 분업·구분이 나타나고 있음
- 기술 문서(예: API 변화, PR 내용, 의사결정 요약 등)는 사실 표집 과정이므로, 해당 부분은 자동화가 적합
- 실제로 관련 PR·컨텐츠 수집, 요약, 적소 삽입 등은 AI 기반 자동화로 업무 효율을 높일 수 있다고 봄

### 에이전트와 상호작용할 때 인사이트 도출의 한계 및 사람 중심 접근의 필요성도 남아있음

- AI 에이전트와 대화만으로는 현실적 인사이트(사용자 페인포인트 등)를 얻기 어렵고, ‘환각현상(hallucination)’에 따른 잘못된 우선순위 도출 위험
- 혁신 속에서도 고객·실사용자와의 대화를 통한 요구사항 파악은 여전히 중요하다고 강조

### 기업 및 팀들은 ‘자체 개발 vs. 외부 솔루션 활용’(Build vs. Buy) 논의가 중요해짐

- AI 시대에는 생산성 도구, 특히 문서 플랫폼 등은 유지관리 부담과 경쟁력 때문에 “내부에서 직접 만든다”와 “외부 제품에 위탁한다”의 평가가 더욱 중요해짐
- 핵심 역량이 아닌 부분에 대해선 전문 솔루션을 쓰는 게 유지비·최신성과 경쟁력 면에서 우월
- 해커톤 등에서 만든 자체 툴의 관리/유지 회피 현상, 엔터프라이즈 세일즈 현장에서도 같은 경향
- 기업은 변화가 빠른 에이전트/인터페이스/표준 환경을 전문 공급자에 맡기고, 자체 역량은 본연의 미션에 집중해야 유리
