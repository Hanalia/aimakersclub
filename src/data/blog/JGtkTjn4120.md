## *AI가 개인의 생산성을 100배로 높여도 조직 전체의 생산성은 그렇게 늘지 않는 이유* 핵심 요약

- 이 영상은 미첼 트로야노브스키(Basis 공동창업자)가 "개인은 AI로 100배 빨라질 수 있지만 조직은 그렇지 않은 이유"를 설명함
- 개인 개발자나 AI 전문가들은 코웍, ChatGPT, Codex, 클라우드코드 등 AI/에이전트 도구를 활용해 큰 생산성 향상을 경험하고 있음
- 그러나 회계법인 등 기업 차원의 생산성은 그만큼 비약적으로 향상되지 않고 있음
- 그 이유는 조직이 ‘일관적 프로세스’와 ‘신뢰’를 통해 대규모 업무를 위임하는 방식과, 개인이 AI 도구를 써서 일하는 방식의 차이 때문임
- 현재 에이전트(Agent) 제품의 두 가지 핵심 문제점: 사용자 역량 격차(Competency Gap)와 프로세스 결여(Process Gap)
- 사용자 역량 격차는 에이전트를 잘 활용하려면 개인이 복잡도를 관리하고 내부 동작을 이해해야 하는데, 일반 지식근로자는 어렵다는 점
- 프로세스 결여는 각 사용자가 제멋대로 에이전트를 쓰도록 두면 조직 전체의 일관성과 신뢰성을 해칠 수 있다는 점
- 이러한 문제 극복을 위해, 일관적이고 ‘의견(opinion)’이 반영된 에이전트 프로세스 설계가 필요
- 동시에, 결과 중심(Eval) 평가만으로는 에이전트가 실제 업무에서 신뢰할 만한 일관성을 보장하는지 확인이 어렵기 때문에, 프로세스적 신호 감시 등 다양한 방법이 필요함
- 대표적인 대응법으로 ‘행동 명세(Behavior Spec)’, ‘포킹(Forking)’, ‘시뮬레이션(Simulation)’ 등 조직적 감독·향상 도구를 제시함
- 결국, 조직 차원의 AI/에이전트 확산을 위해서는 단순성과 신뢰성, 그리고 ‘의견이 있는 프로세스’가 핵심임

## 세부 요약 - 주제별 정리

### AI는 개인의 생산성을 극적으로 끌어올리지만, 조직 차원에서는 같은 효과가 나지 않음

- 발표자는 본인의 생산성이 AI 덕분에 100배, 10배가량 늘었다고 체감함
- 개발 컨퍼런스 참가자, ChatGPT 등 최신 에이전트를 쓰는 사람 대부분이 비슷한 체험을 함
- 하지만 실제 기업, 회계법인, 일반 조직의 평균 생산성은 그렇게 비약적으로 증가하지 않음
- 개인과 조직의 시스템, 업무 방식, 신뢰 관계의 구조 차이에서 그 원인을 찾음

### 조직은 임의적이지 않은 '프로세스 신뢰'를 통해 대규모로 생산성을 위임함

- 기업(특히 회계법인 등)은 전사적, 계층적 프로세스를 활용해 업무를 위임함
- 예시: 회계법인의 대표는 현장 실무자가 구체적으로 뭘 어떻게 하는지 잘 모름
- 그럼에도 업무가 일정 품질 이상으로 수행된다고 신뢰함 — 이는 사람이 ‘완전히 결정적(deterministic)’이지 않음에도, ‘프로세스’가 있기 때문
- 최소한의 프로세스(예: 은행 데이터 추출을 회사가 승인한 특정 소프트웨어로만 진행)는 일관된 결과의 기반이 됨
- 각자가 자유롭게 방식(예: ‘PDF 추출법’을 아무거나 구글링해서 선택)으로 일을 하면 조직 운영이 불가능함

### 현재 AI/에이전트 도구는 '사용자 역량 차이'와 '프로세스 부재'란 두 가지 병목에 직면함

- 코웍, ChatGPT, Codex, Cloud Code 등 최신 AI 기반 에이전트 제품이 많아졌음
- 그럼에도 조직 생산성이 비약적으로 오르지 않는 첫 번째 원인: '사용자 역량 격차'
    - 에이전트 사용 시 사용자가 자기 역량/기억/적용 시점을 스스로 관리해야 함
    - 이 과정은 소수의 전문가에겐 쉽지만, 대부분의 지식근로자들에겐 쉽지 않음
- 두 번째 원인: '프로세스 결여'
    - 현 에이전트 제품은 "원하는 대로 에이전트에게 시키라"고 유도
    - 이는 조직 내 프로세스의 수직적, 일관적 하달 구조와 충돌하며, 결과적으로 신뢰/확장성 훼손

### 일관성과 신뢰성을 갖는 조직형 에이전트 구축을 위해 ‘의견(opinion)’공정이 필수적임

- 실제 업무 대행 가능한 에이전트(Production Agent)로 나아가려면, 위 두 문제를 반드시 해결해야 함
- ‘의견(Opinions)’이란 에이전트가 업무를 처리할 때 사용하도록 명시적으로 정한 방법론·원리·태도·선호
- 예시 1: PDF에서 정보를 추출할 때, 어떤 OCR 방식(파이썬, 오픈소스 라이브러리, VLM, OCR 제공 API 등)을 쓸지 조직적 판단이 필요
- 예시 2: "파워포인트 자료를 만들 때, 최종 화면 캡처본을 한번 찍어본다"처럼, 실무 전문성이 반영된 간단하지만 효과적인 의견이 있음
- 일부 의견은 정확성만이 아닌, 속도, 비용, 안정성 등 비기능 조건도 판단 기준에 포함시킴

### 에이전트의 업무 행위를 ‘행동 명세(Behavior Spec)’로 문서화하여 조직 전체의 일관성을 확보함

- 에이전트의 실제 행동은 시스템 프롬프트, 프로그레시브 디스클로저(단계별 정보공개), 도구 설명, 모델 학습 데이터 등 여러 신호의 합침임
- '행동 명세(Behavior Spec)' 개념은 "에이전트가 어떤 상황에서 어떤 행동을 해야 하는가"를 특정 의견 기반으로 사전 정의하는 방식임
- 명세는 제품 설계서처럼, 상세히 적는 것이 아니라 조직적으로 꼭 중요한 의견만을 추려 정의
- 실제 프로덕트/엔지니어링팀 내 협업 기준이 되며, 평가(Eval) 기준으로도 사용할 수 있음

### 결과 중심 평가(Eval)만으로는 조직 생산성 확장에 한계가 있으므로, 프로세스(행동) 중심 감독이 병행되어야 함

- Outcome-based Eval(정답이 명확한 평가 기준)은 테스트 셋(100~1000 케이스)에선 유효
- 실제 프로덕션에서 수십만 건 이상의 다양한 업무(trajectory)가 등장하며, 각 실행 경로(trajectories)의 분포가 매우 넓어짐
- 트루스(진실 데이터)가 없는 케이스가 대부분이므로, 결과 중심 평가만으로 실전 신뢰성 보장이 불가
- 행동 명세와 조직 내부 감독 체계로, 에이전트가 "의견(운영규칙)에 맞게 일했는가"를 신호(signal) 형태로 꾸준히 수집해야 함

### 포킹(Forking) 기법을 활용해 특정 업무 경로별 에이전트 행동을 비교·분석할 수 있음

- 포킹: 테스트·프로덕션에서 에이전트가 규정된 의견(Behavior Spec)에 어긋나는 행동을 했을 때, 그 시점 이전/이후로 분기시켜 실험하는 방법
- Forking을 통해 특정 경로에서 왜 의도와 다른 행동이 나왔는지, 컨텍스트 변경/입력 조정 등으로 재현·실험 가능
- Outcome-based evals로는 추적 불가한 '프로세스상 원인'을 발견하고, 시스템 개선에 실질적으로 기여

### 시뮬레이션(Simulation)으로 비용 효율적인 환경 내 에이전트 동작 반복 실험이 가능함

- 코딩에이전트(예: Codex 등)에게 스스로를 ‘서브에이전트’로 생성하게 하여 특정 상황에서 어떻게 행동하는지 시뮬레이션 가능
- 실제 환경을 완전히 복제하지 못하더라도, 저비용·고속으로 반복 실험이 가능해, 개발/설계 변경을 빠르게 테스트 가능
- 내부적으로 포킹 시스템이 구축되기 전 1년 반 이상, 가장 빠르고 효과적인 실험 도구로 활용됨

### ‘의견(opinion)’이 명확해야만, 행동 신호(signal) 수집→프로세스 개선→자기 개선 에이전트 구축이 가능해짐

- 평가 신호(signal)를 체계화할수록 ‘의견(운영원리)’의 필요성이 커짐
- 명확한 의견 없이 프로세스를 설계하면, 신뢰성과 단순성을 동시에 얻을 수 없음
- 그래서 처음 좁은 영역에서 일관·신뢰성 확보된 에이전트가 신뢰를 쌓으며 점차 확장될 수 있음

### 인간 조직과 마찬가지로, 신뢰할 수 있고 일관성 있는 에이전트일 때만 현업에 실질적 영향을 미침

- 협업 과정의 예시: PR(코드 리뷰) 시, 파일 영향도(=업무 중요도)와 ‘작성자의 신뢰도’에 따라 검토 수준이 달라짐
- 에이전트도 이와 유사하게, 신뢰도가 쌓여야 업무 위임 범위와 영향도가 늘어남

### 조직 생산성을 진정으로 확장하려면 '의견 반영된 프로세스' 설계와, 단순성·신뢰성 확보가 핵심임

- AI/에이전트에 자유재량을 부여한다고 반드시 더 나은 결과·혁신적 방식으로 업무가 수행되는 것은 아님
- 조직은 새로운 혁신보다 신뢰성과 예측 가능성을 우선시하며, 조직원 모두가 활용 가능한 단순성과 일관성을 중시
- 결론:“에이전트가 확산하려면 단순해야 하고, 신뢰받으려면 일관·신뢰성 갖춰야 하며, 그 핵심은 ‘의견’에 있다”
- 조직 내 에이전트의 점진적 신뢰·업무 확장은 견고한 의견과 행동 명세 기반 프로세스에서 출발함
