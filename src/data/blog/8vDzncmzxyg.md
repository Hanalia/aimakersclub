## *AI 에이전트는 매 세션마다 신규 입사자처럼 시작한다* 핵심 요약

- 본 영상은 Sonar의 Kilian Carlsen-Phelan이 "에이전틱(Agentic) 코딩 루프에서의 코드 검증 자동화"를 주제로 발표한 내용임
- AI 코딩 에이전트는 매 세션마다 프로젝트의 기존 규칙, 아키텍처, 코딩 표준 등을 인지하지 못한 새로운 입사자와 같아 반복적인 맥락 수집이 필요해 비효율적임
- 이러한 맥락 탐색으로 인한 비효율은 개발 속도 저하, 토큰과 비용 낭비, 코드 품질 저하로 이어짐
- Sonar가 개발한 Sonar Vortex는 코딩 에이전트와 연동되어 프로젝트 컨텍스트를 사전에 주입, 코드 작성 전부터 규칙·아키텍처·표준 정보를 인식할 수 있도록 지원함
- Sonar Vortex의 자동적·결정론적 코드 검증 기능을 통해 보안 문제 등 새로운 결함의 유입을 사전에 방지하고, 에이전트가 직접 반복적으로 오류를 수정하도록 유도함
- 자체 사례와 시연에서, 짧은 시간 내 테스트 스위트를 작성했음에도 보안 문제(임시파일 권한 미설정)를 Vortex가 검출 및 교정됨을 실증함
- Sonar 자체 설문(1,100명 개발자) 결과, 96%가 AI 생성 코드에 완전한 신뢰를 보내지 않으나, 실제 사전 검증은 48%에 불과함을 데이터로 제시
- Sonar Vortex 도입 시 토큰 사용량 36% 감소, 제품 장애 44% 감소, 오탐율도 낮게 유지되는 등 생산성과 신뢰성이 크게 향상됨
- Vortex는 주요 코딩 에이전트(Cloud Code, Codex, Antigravity 등) 및 커스텀·오픈소스 에이전트 모두와 연동 및 적용 가능함
- 결정론적(Differministic) 방식 기반의 Sonar Vortex는 예측 가능하고 일관된 검증 결과를 제공함으로써 개발팀의 신뢰·개발 속도·코드 품질을 모두 향상시킴

## 세부 요약 - 주제별 정리

### AI 코딩 에이전트는 항상 프로젝트 규칙을 처음부터 학습해야 하는 구조적 한계가 존재함

- 에이전트 기반 코딩 도구는 세션을 시작할 때마다 프로젝트에 대한 사전 지식이 없음
- 기존 개발 컨벤션, 코딩 가이드라인, 아키텍처 규칙 등 내부 규정을 모르고 시작함
- 예를 들어 새로운 API 엔드포인트를 생성하라는 요청에서는 기존 엔드포인트 구현 방식을 스스로 소스 코드를 검색하며 파악해야 함
- 컨텍스트 확보에 따라 성능이 들쭉날쭉해지고, 소스 전체를 탐색할 수 있어 토큰과 비용이 많이 소모됨
- 이 과정은 반복적인 비효율과 코드 품질 문제를 야기할 수 있음

### 기존 코드베이스 내 존재하는 문제 패턴이 반복적으로 AI에 의해 재생산되는 위험이 크다는 데이터가 확인됨

- 모든 코드베이스에는 크고 작은 문제점이 항상 존재함을 인정함
- 에이전트는 기존 코드의 좋지 않은 패턴을 그대로 학습하여 재현할 가능성이 높음
- 에이전트 도입 시 새로운 버그가 유입되는 것은 "if"가 아니라 "when(언제나)"의 문제임을 강조
- 사전 자동 검증 없이 코드를 배포할 경우 유지보수 및 품질관리가 사실상 불가능해짐

### Sonar Vortex는 AI 코딩 에이전트에 프로젝트 맥락을 미리 알려주고, 결정론적 검증을 통해 오류 발생 및 반복 수정을 크게 줄임

- Sonar Vortex는 모든 주요 코딩 에이전트와 연동되는 플러그인 형태임
- 코드 작성 전에 프로젝트의 아키텍처, 코드 규칙, 허용 라이브러리 등 세부 정보를 에이전트에 자동으로 제공함
- 각 파일, 기능별로 변경이 감지될 때마다 자동으로 SonarQube 분석을 통해 안전성·품질을 검사함
- Deep check(심층 분석)도 지원, 보안 및 크로스파일 데이터 플로우 관련 이슈까지 감지함
- 반복적인 수동 확인 과정 없이 즉각적인 교정과 피드백이 가능하여 개발 생산성이 향상됨

### 실사용 사례에서 Sonar Vortex가 발견한 임시파일 권한 미설정 보안 이슈는 전통적 코드 리뷰로 잡기 어려운 문제임이 부각됨

- 자사 실험에서 에이전트가 2분 이내에 테스트 스위트와 간단한 파일 압축해제 기능을 코딩
- 하지만 테스트 코드와는 별개로 임시파일 생성 시 파일 권한 미설정이라는 보안 이슈를 자동 감지
- 해당 문제는 숙련 개발자도 명시적으로 리뷰하지 않으면 발견이 어려움
- 보안 결함 발견 시 에이전트가 직접 코드를 수정·재수행함으로써 반복적인 핑퐁 리뷰를 크게 줄임
- 팀원 및 시니어 엔지니어의 반복적인 개입, 피드백 필요성이 크게 감소

### 대규모 개발자 설문에서 AI 코드에 대한 신뢰(4%만 완전 신뢰)와 실제 검증률(48%만 사전 검증)의 격차가 심각함

- Sonar가 1,100명 이상의 개발자를 대상으로 설문조사 수행
- 96%의 개발자가 AI 생성 코드에 완전한 신뢰를 보내지 않음
- 그럼에도 불구하고, 사전 검증 및 코드 리뷰를 실제로 수행하는 비율은 절반 미만(48%)에 불과
- 검증 없이 프로덕션에 코드가 적용되는 현황을 "위험한 일"로 지적

### Sonar Vortex 사용 시 토큰 소비, 장애, 오탐율 등 다양한 수치 개선 효과가 검증됨

- 프로젝트 전체 평균 토큰 사용량 36% 감소(특히 기존 코드 리팩터링의 경우 효과 뚜렷)
- 제품 장애(프로덕션 장애) 44% 감소 효과 확인
- 오탐률(false positive rate)이 매우 낮아 노이즈 없이 효과적으로 품질 저해 요인만 선별
- SOP(표준운영절차) · 워크플로우 자동화 환경에서 더욱 높은 신뢰성을 제공함

### Sonar Vortex는 다양한 AI 코딩/리뷰 에이전트와 쉽게 연동 및 확장 가능하도록 설계됨

- Cloud Code, Codex, Antigravity 등 주요 상용 코딩에이전트와 기본적으로 호환됨
- 오픈소스, 자체개발(커스텀) 에이전트에도 MCP 클라이언트를 통한 탑재 지원
- SonarQube, MCP, CLI 기반 도구로 손쉽게 개발 환경에 플러그인 형태로 적용 가능
- SonarQube를 이미 CI(지속적 통합) 파이프라인에 적용 중이라면, Vortex가 기존의 분석 정보를 활용

### Sonar Vortex의 결정론적 분석은 AI→AI의 크로스 체크(검증 AI가 다른 AI를 리뷰)와 비교해 더 신뢰할 수 있는 검증 체계를 제공함

- AI가 스스로 생성한 코드를 다른 AI로 검증(예: Claude가 코딩하고 Claude나 다른 LLM이 검증)은 오류와 허상(hallucination, 오탐)의 문제가 반복됨
- Sonar Vortex의 결정론적(Deterministic) 분석은 언제나 동일 코드를 동일 방식으로 평가, 예측 가능성과 준수성(compliance)를 보장함
- AI 기반 리뷰 도구(Guitar 등)는 별도로 존재하지만, Vortex는 코드 생성 및 검증 파이프라인 사이에서 결정론적 가이드라인 역할을 수행함
- 새로 추가된 코드에 대해서는 반드시 수정·교정을 강제하고, 기존 코드의 잠재적 문제는 알림만 제공함

### 실제 데모 사례에서 Sonar Vortex가 6개의 이슈(새 코드 2개, 기존 코드 4개)를 자동 검출하고, 반복 교정을 통해 보안 품질을 높였음을 입증함

- Claude가 생성한 코드 변경 사항을 Vortex가 분석, 그 중 2개 문제는 새로 작성한 코드에서, 4개는 기존 코드에서 탐지
- 임시파일 생성 경로 권한 문제의 경우, Claude가 기본값 활용으로 한차례 문제를 수정했다 판단했으나 Vortex가 더 강한 명시적 권한 설정을 요구함
- 반복 분석→교정 과정을 통해 보안 및 품질 측면에서 기준을 준수
- 매 파일 수정/추가 시마다 자동 분석이 수행되어 Review 지연 및 품질 저하 위험 제거

### Sonar Vortex 도입 시 개발팀이 얻는 현실적 이점은 검증 감소, 즉각적 오류 수정, 비용·시간 효율, 개발자 시간 확보임

- PR 리뷰에서 매번 수작업으로 코드를 검증·수정하는 번거로움과 시간 소모 감소
- 실시간 코드 수정 및 즉각적 검증으로 보안성 증대 및 신뢰성 향상
- 리워크·수정·리뷰 반복 과정 최소화로 비용, 시간, 개발자 에너지 낭비 방지
- 자동화된 Agentic Workflow 신뢰도를 높여 개발자들이 본연의 생산적 업무에 더 집중할 수 있도록 지원
- Sonar를 이미 활용하거나, 에이전틱 개발·검증 도구를 도입 고려 중인 개발자라면 즉시 적용 가능함

### AI 코드 에이전트의 "맥락" 및 "초기 가이드" 설정이 성능·신뢰성 향상의 핵심 레버임을 재차 강조함

- 코딩 에이전트 단계에서 맥락(context)·가이드라인 미리 제공이 결정적 성능 차이를 만들어냄
- 에이전트의 모델 성능 고도화보다, '전 단계 컨텍스트 제공'이 반복되는 리워크와 개입을 줄이는데 더 효과적임
- Sonar Vortex가 코드 베이스의 전체 맵, 테스트 패턴, 언어별 가이드라인, 커스텀 요구사항 모두 자동 전달
- 기존처럼 파일 전체를 일일이 탐색하는 비효율이 일어나지 않고, '빠른 이탈, 빠른 적용' 구조로 코딩 루프 혁신 가능
