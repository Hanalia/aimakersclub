## *내 코드 외에는 모두 엉망이다 (All Code Is Slop Except Mine) — Lauren Tan, SpaceXSI* 핵심 요약

- SpaceX SI의 Lauren Tan(일명 Potato)은 AI 코딩 에이전트 시대에 품질 유지와 생산성 극대화 노하우를 공유함
- 본인은 최근 한 달간 3,000개 이상의 pull request(코드 병합 제안)를 자동화해 실서비스에 반영함
- AI 에이전트(자동 코딩 시스템) 시대에는 기존의 '천재 프로그래머'가 아니어도 누구나 '코드 생산기'가 될 수 있게 됨
- 에이전트에게 맡기는 코드 품질과 신뢰성은 엄격한 규칙, 코드 가이드, 자동화된 검증 체계(테스트, 린트, 형식 검증 등) 설계에 달려있음
- 생산성과 품질의 균형을 위해 코드베이스를 '정원'에, 에이전트를 '정원사'에 비유함. 품질 높은 코드 패턴이 곧 에이전트의 학습원료가 됨
- 실제 사례로, Graph Bot, Grabot, Dune, Dunanaps 등에서 에이전트를 위한 다양한 제한/검증 규칙과 자동화 도구를 설계·적용함
- 코드베이스를 관리할 때, 반복되는 문제는 규칙(린트) 또는 코드 아키텍처 개선으로 근본적으로 차단함
- 런타임 확인, 형식 검증(TLA+, Lean), 속성 기반 테스트(Pombadil) 등 다양한 프로그램적 검증 툴을 결합해 신뢰도를 높임
- 결과적으로, 최근 한 달에 11,000건의 PR을 생산하고, 오류 발생률은 0.5% 이하에 머무르는 등 품질과 속도 모두 달성함
- 에이전트 자동화를 시작하기 전, 반드시 ‘양질의 코드 기반 및 체계적 검증 환경’을 선제적으로 갖출 것을 권장

## 세부 요약 - 주제별 정리

### AI 에이전트 시대에는 모두가 ‘코드 생산기’가 될 수 있음을 경험적으로 증명함

- Lauren Tan(별명 Potato)이 SpaceX SI에서 “Grok Bot” 개발에 참여하며, 자동화된 방식으로 3,000개가 넘는 pull request를 실서비스에 적용함
- AI 에이전트/자동 코딩 도구가 등장하기 전에는 상당한 코딩 속도와 정확도를 ‘천재 프로그래머’(예: Bret Taylor가 주말에 Google Maps를 다시 쓴 일화)만이 달성할 수 있었음
- 이제 누구든 수십~수백 명 ‘에이전트’를 사용하는 것만으로 이와 같은 코드 생산량을 달성할 수 있는 시대가 되었음
- 핵심은 생산성(코드량) 증대와 함께 코드 품질을 어떻게 동일하게 높이 유지할 수 있느냐임
- 이 과정에서 “모든 코드는 엉망(슬롭)이지만, 내 코드만은 다르다”라는 편견이 어떻게 바뀌는지 실질 예시와 함께 설명

### 코드 품질 유지는 에이전트 환경에 대한 체계적인 신뢰 구축에서 시작함

- “소프트웨어 공장(software factory)” 개념과 달리, 확실한 신뢰를 주는 환경(신뢰성 높은 검사체계 등)을 구축하는 게 중요함을 강조
- 완전한 맹목적 신뢰가 아니라, 규칙, 제한, 검증 등을 통해 족쇄를 걸어 차후에도 에이전트들이 ‘옳은 행동’을 하도록 만드는 것이 핵심
- 이 시스템을 구축해 6개월 만에 수천 개 PR 자동화를 달성함. 누구나 적절한 방법만 따르면 더 빠르게 도달 가능함을 언급

### 에이전트의 품질 관리는 ‘코드베이스’에서부터 시작하며, 입력의 질이 핵심임을 주장함

- 에이전트가 코드를 짤 때 기존 코드베이스(기존 소스코드)가 가장 강력한 ‘입력’ 데이터가 됨
- 코드베이스에 부적절한 패턴이나 기술적 부채, 나쁜 예제가 남아 있으면 에이전트가 복사해서 확산시킴
- 즉, 코드베이스는 ‘정원’과 같아서, 한두 군데서 발생한 잡초/해충(나쁜 코드)이 곧 전체에 퍼짐
- 그렇기에, 에이전트가 베끼기 쉽도록 ‘훌륭한’ 코드 패턴과 구조, 명확한 아키텍처 기준이 미리 마련되어야 함

### 반복되는 코드 문제의 해결은 규칙 및 구조 설계를 통한 자동 차단이 가장 효과적임

- 예시 1: React의 useEffect 사용은 복잡해서 에이전트가 자주 실수함 → 제품 코드에서 아예 금지, Dune의 한정된 영역에서만 허용하여 문제를 원천차단
- 예시 2: Cursor(Electron 앱)에서는 에이전트가 main/renderer 코드 의존성 혼재로 인한 퍼포먼스 저하를 초래 → 폴더 구조 자체를 electron-main, electron-renderer로 분리, Cross-import를 lint/의존성 검사로 차단
- 예시 3: setTimeout 등 지시형 타이머 남용 → 원인은 아키텍처 미스매치(React declarative vs. VS Code imperative)였고, 임시방편이 전체로 확산됨. 이를 현명하게 lint 규칙으로 원천 봉쇄
- 반복적 오류 및 나쁜 코드 패턴 발생 시, 임시로 주석/매뉴얼만 추가하는 대신 코드・아키텍처 차원에서 구조적으로 해결할 것을 권장

### 불필요한 주석이나 규칙 추가 대신, 자동화된 검사와 코드 개선에 집중해야 함

- 에이전트가 주석(markdown, docstring, 규칙파일, skills 등)을 ‘하지 않은 일’을 정당화하는 수단으로 오용하는 경향 있음
- 주석은 관리도 어렵고, 향후 자동으로 판단이 불가하며 에이전트에게 회피구실만 제공함
- 협업 시 각 PR에 지나치게 미시적인 규칙/준수사항을 추가하는 것이 아니라, 자동화된 lint rule, 구조 개선 등 요청사항을 코드/환경 수준으로 통합해야 악순환을 예방할 수 있음
- Grabot, Dune 등에서는 99%의 주석 작성을 막고, 대신 친절한 에러 메시지를 lint/테스트에서 자동제공하여 근본적 문제 유발 지점을 안내함

### 검증 체계의 강화가 에이전트 신뢰도와 생산성을 동시에 높임

- 코드 리뷰의 방식이 인간의 수동적 확인→자동 검증 체계 점검으로 전환됨
- 런타임 검증(Runtime verification): 에이전트가 사람처럼 코드를 실행·디버깅(Chrome DevTools protocol 활용 등)
- 자체 기능맵(feature map) 제공: 앱 내 가능한 모든 기능을 지도로 시각화해 에이전트가 실수 없이 작업 가능
- 커스텀 CLI(명령줄 인터페이스)로 중복코드, 토큰 소비 줄이고, 테스트 가능성 향상
- 형식적 검증(Formal verification): TLA+로 모델 검사, Lean으로 알고리즘 수학적 증명 적용. 실제 가시적 에러 다수 포착
- UI 속성 기반 테스트: “Pombadil” 라이브러리 도입, UI 버그 탐지에 유용

### ‘검증 체계 구축=신규 비용’이 아닌 자동화로 인한 비용 효율 극대화임을 데이터로 증명함

- 동료 개발자(Sindy) 사례: 6개월 전 ‘에이전트를 신뢰 못하겠다’에서, 최근 ‘일일 토큰의 70%를 검증에 쓴다’로 변화
- Lauren 본인도 “대부분의 토큰이 검증에 쓰인다”고 밝힘
- 이는 검증 활동이 오히려 전체적인 생산성 증가, 품질 향상, 리스크 감소로 이어짐
- 고전적인 소프트웨어 엔지니어링 기법(테스팅, 검증, 정적분석 등)이 과거엔 비용·난이도가 높았으나, 에이전트와 자동화 덕분에 도입 문턱이 크게 낮아짐

### 실시간 대규모 자동화가 가능한 환경에서는 ‘퀄리티 & 스피드’ 모두 달성 가능함

- Grok Bot 팀은 한 달 새 실서비스에 11,000건 PR 투입, 일일 신규 안정 빌드 배포도 가능
- 기여자(Contributor) 숫자 확산: 2023년 10월 한 달간 227명의 개발자가 최소 1건 PR 기여
- PR의 ‘롤백’ 비율은 0.5%로 낮고, 품질 또한 Electron 기반임을 감안해도 서비스 론칭 초기 대비 성능(속도, 반응성) 개선 확인
- 그 결과, 수많은 타사·오픈소스 프로젝트에 비해 훨씬 뛰어난 품질&신뢰성을 유지 중

### 에이전트 자동화 도입 전에 코드베이스와 검증 체계의 정비가 선행돼야 함을 거듭 강조함

- 잘못된 코드 루프/불량 프로세스를 자동화하면 오히려 악화될 뿐만 아니라, 토큰 소모 급증 등 추가적인 비용이 발생
- 기본 단계:
    - 1: Lint rule로 악습관 차단 및 기존 코드 정화
    - 2: 런타임, 정적 검증 프로세스 추가
    - 3: 구조가 잡히면 에이전트용 자동화(예: Graph Bot) 도입
- Graph Bot 등의 에이전트 관리 플랫폼이 이미 다양한 오픈 커넥터와 자동 PR, 자동 테스트, 자동 머지까지 지원
- 깔끔한 코드베이스 위에만 대규모 자동화가 가능하며, 이럴 때 코드 슬롭(엉망)이 ‘금(완성도 높은 산출물)’으로 바뀜

### 최종적으로 정돈된 코드와 체계가 있으면, 에이전트 자동화 환경에서 고품질 소프트웨어를 초고속으로 생산할 수 있음을 시현함

- Grok Bot은 새로운 릴리즈가 나올 때마다 Cursor 프로젝트를 자동 생성, 전체 앱 점검 및 버그 수정 PR 생성·병합도 자동수행
- “코드베이스의 품·질이 곧 PR의 기본 품질이 된다”, “대부분 자동 머지를 허용해도 손실/오류가 없다”는 실증적 결과 확보
- 코드 품질, 아키텍처, 검증/자동화 레이어가 갖춰지면 서비스 속도와 품질에서 타의 추종을 불허하는 경쟁력이 생김
- 결론: 엉성한 코드를 방치하면 자동화가 독이지만, 체계적 준비로 누구나 ‘코드 생산기’가 되고, 인간 검토에 의존치 않는 신뢰성까지 달성할 수 있음
