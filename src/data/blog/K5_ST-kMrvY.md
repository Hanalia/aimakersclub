## *예·아니오 대답에 LLM 요금 그만 내세요* 핵심 요약

- 영상 제목: **예·아니오 대답에 LLM 요금 그만 내세요**
- Glean의 소프트웨어 엔지니어 Chinmay Goyal이 Jev라는 의사결정(분류) 모델을 Glean Assistant에 적용한 사례를 자세히 소개함.
- 디시전(분류) 문제는 기존에 LLM(대형 언어 모델)으로 해결했으나, 비용·지연(latency) 부담이 큼.
- Jev는 범주형(classification) 문제에 적합하며, LLM 대비 저렴하고 빠르며, 텍스트 생성이 필요 없고, taxonomy(분류 체계) 변경에도 별도의 재학습(fine-tune) 필요 없이 prompt만 바꾸면 바로 적용 가능.
- Glean은 기능별로 Jev 도입 전후 성능 및 비용을, 자체 황금 평가 세트·내부 사전 적용·AB 테스트 등 다단계 검증 과정을 거쳐 검토함.
- 실제 적용 사례: 쿼리 분류(90% Llama fine-tuned 대비 품질), 전문가 라우팅(8배 지연 감소), 추천 Ranker(99.2% 시간 제한 충족), LLM 판정자(일관성 및 비용/속도 개선), 보안 버추 클래스파이어(Recall 31.5%→90.2% 및 리소스·인력 비용 50%+ 절감).
- Jev 활용으로 Glean 사용자 경험 개선, 엔지니어 생산성 및 제품 개선 속도 급증, 보안 유지 측면 모두 큰 개선 효과 확인.
- 최종 결론: 결과가 미리 정의될 수 있으면 Jev 등 결정보델을, 그렇지 않으면 LLM을, 두 방식 조합도 유용하다고 제안함.

## 세부 요약 - 주제별 정리

### Jev는 LLM과 파인튜닝 모델 사이의 간극을 메꾸는 결정보델로 비용과 효율성에서 탁월함

- Glean의 Chinmay Goyal은 LLM을 활용한 AI 작업 중 상당 부분이 고도의 생성(generation)보다는 "예/아니오" 등 범주형 결정(classification)에 해당한다고 진단함.
- 기존에는 LLM 혹은 open model(LLaMA 등), 파인튜닝 모델 등 다양한 방식 시도했으나, 모든 방식에 비용, 속도, 운영상의 약점이 존재함.
- Jev는 텍스트 생성 없이 결정만 반환하며, 간단한 prompt 변경만으로 taxonomy 변경에 신속히 대응 가능.
- Jev 도입은 반복적인 모델 파인튜닝 및 배포 비용, 데이터 수집·클리닝, 인프라 관리 부담을 대폭 줄임.
- Jev의 가장 큰 장점은 미리 정의된 결과(label)에 빠르게 반응하며, 필요 인력/리소스를 크게 절감하는 데 있음.

### 기능 변화 시 안전성과 품질 보장을 위한 다단계 평가 및 배포 프로세스를 운영함

- Glean은 수백만 명의 대형 고객 기반을 보유하고 있어, 신규 AI 기능 적용에 대해 체계적인 리스크 관리가 필수임.
- 제품 변경은 항상 황금 평가셋(golden eval set)을 갖고 검증 실시.
- 1,500명 내부에서 수주간 soak(사내 사전 배포) 시행→활발한 피드백 수집 후 개선→외부 고객 대상 AB 테스트를 단계적으로 거침.
- 각 인공지능 기능마다 별도의 평가 체계 구축해, 생성형 AI/의사결정 등 모든 지능 영역에서 제품 품질 저하 가능성을 차단함.

### 쿼리 분류 문제에서 Jev는 파인튜닝 모델 대비 90% 품질을 증명하며 기존 LLM 대비 효율이 뛰어남

- 유저 쿼리 intent 분류는 제품 개선을 위한 중요한 데이터임(예: 세일즈 관련 쿼리↑시 해당 개선 집중).
- Open source LLaMA, Jev, fine-tuned LLaMA 3가지 방식 비교.
- Jev는 LLaMA 원본 대비 아웃풋 품질 약 2배, fine-tuned 대비 90%에 달함.
- 데이터 수집, 클리닝, 파인튜닝, 모델 호스팅, 추론 비용 등 별도 없이 prompt 변경만으로 taxonomy 변경에 즉시 반응 가능.
- 결과적으로 새로운 분류 체계 도입이나 쿼리 유형 변화에 애자일하게 대응이 가능함.

### Jev 도입으로 전문가 라우팅의 정확성과 속도가 크게 향상됨

- 전문가 라우팅은 고객 질의가 어떤 전문가/엔진에 할당될지 결정하는 문제로, 기존에는 general-purpose LLM 사용.
- Jev 통합 시 시스템 아키텍처 및 인프라 복잡성이 증가했지만, 지연(latency) 최대 8배 감소라는 이점을 얻음.
- Jev 도입을 통한 라우팅 정확도(precision)와 빠른 반응속도가 사용성에 직접 기여함.
- 복잡성 증가에도 불구하고 속도-효율 측면에서 도입을 정당화함.

### 추천 Ranker에서 Jev 이용 시 시간 내 응답률 및 결과 품질이 획기적으로 개선됨

- Glean은 다양한 소스(10-15개)로부터 자연어 LLM이 추천 쿼리를 생성, 이를 랭커가 맥락(원 쿼리, Glean 응답, 각 추천 목록)하에 최적 제안을 선택하는 구조임.
- 랭커 시스템은 1~2초 이내 응답(latency)이 필요하며, Jev 사용 시 99.2%가 시간 내 결과 반환(LLM은 90%).
- Jev 활용 시 invalid(유효하지 않은) 응답이 0건 기록(LMM은 다국어 반환, 규칙 미준수 등 오류 발생).
- 각 옵션별(5개 등) 확률값을 반환하므로 고객별 deployment에 따라 임계값을 동적으로 최적화 가능.
- Threshold fine-tune을 셀프러닝화하여, 각 고객별 사용 방식에 따라 사용자 경험 극대화.

### LLM 판정자 평가업무에 Jev를 활용하면 일관성, 재현성, 속도에서 큰 개선이 나타남

- LLM을 품질 평가용 "판정자(Judge)"로 반복 사용 시 응답 일관성·재현성이 중요함.
- Glean은 Jev로 인용 근거(답변이 문서 내용 참조 여부) 판정 업무에 활용 시, 28~30건 중 1건만 결과 불일치, 나머지는 완전 동일.
- 기존 LLM(예: Luna) 대비 속도, 비용, 일관성 모두 우수.
- 단일 입력-출력 쌍에 대해 수회 반복 실험 필요 없이 Jev는 효과적임.
- 결과적으로 엔지니어 생산성 5-6배, 전체 피처(feature) 출시·업데이트 속도 증가, 개발 및 품질개선 파급효과가 선형이 아닌 기하급수적으로 증폭됨.

### Jev는 복잡한 보안 분류 시스템을 단순화하여 50% 이상 리소스, 인력 비용을 절감함

- Glean 고객 모두에게 독립적인 인스턴스/리소스를 제공(싱글 테넌트), 기존엔 가상 클래스파이어(virtue classifier) 및 T4 GPU 필요.
- 수천 고객 대상 인프라 관리, 인력 유지에 많은 엔지니어 자원이 소모됨.
- 보안 절차상 도구 I/O, LLM 결과 모두에 대해 recall 중심의 체크 후, 최종 LLM을 활용한 로딩(respone) 단계가 있음.
- Jev 전환 후 recall이 31.5%→90.2%로 대폭 향상, 리소스·엔지니어링 비용도 50% 이상 절감.
- 단순 리소스 비용 외 인건비, 유지보수 등 총체적으로 더 큰 비용 절감 효과 입증.

### 범주가 미리 정의될 수 있으면 Jev, 자유 생성이 필요하면 LLM, 두 방식 병행도 실전적임을 권장함

- Jev 적용 판단 기준: "결과를 미리 열거할 수 있는가?" → 예: Jev/결정보델 사용 / 아니오: LLM 등 텍스트 생성 활용.
- 라벨이 안정적이고 데이터 볼륨이 많으면(드물긴 하지만), 파인튜닝 모델도 고려.
- 라벨 변화가 빈번하고, 실시간 운영·융통성이 중요하면 Jev 방식을 추천.
- 동적 텍스트 생성도 필요한 경우 Jev와 LLM 병용(하이브리드 솔루션)도 현실적으로 유용함.
- 실제 Jev 실전 활용 결과에 대한 구체 데이터, 블로그 링크를 별도로 공유함.

### Jev 통합으로 Glean의 사용자 경험, 개발 생산성, 보안 수준 등 전방위 혁신 효과가 입증됨

- 최종적으로 Jev의 도입은 단일 기능 최적화가 아니라, 전체적인 제품 경험(사용자, 개발자, 보안 모두)에 혁신을 불러옴.
- 엔지니어당 피처 전개 속도가 5~6배 빨라지며, 전체 조직 생산성, 배포 및 품질 개선 속도가 비선형적으로(기하급수적으로) 증가함.
- 인력 투자 대비 효익이 대폭 커지고, 운영 복잡도/비용 부담은 오히려 감소함.
- Jev의 활용은 Glean 사례에 한정되지 않으며, 대규모 AI서비스, 신속 피봇팅/변경이 필요한 분야에 폭넓게 확장 가능함.
