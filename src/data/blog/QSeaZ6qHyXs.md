- 코드 리뷰 자동화와 대량 PR(풀 리퀘스트) 대응을 위해 CMA와 다중 에이전트가 통합되어 활용됨

- 장시간 세션·에이전트 실행시 이벤트 스트림 및 세션 탭, 커스텀 툴을 통한 상태 추적과 관리 방안 제시
- 멀티플레이어 채팅 및 클라우드 태그 유사 기능 개발을 위한 세션/스레드 운영 방식과 메모리 공유 패턴 제시
- 메인 에이전트와 서브 에이전트로 작업 분리, 서브 에이전트가 작업 수행 중이어도 주 에이전트는 유휴 상태 유지 가능

## 세부 요약 - 주제별 정리

### Ant CLI와 YAML 기반 CI/CD가 코드와 리소스 관리의 핵심 역할을 수행함

- 관리형 에이전트 리소스의 버전 및 상태 유지를 위해 Ant CLI(Antropic 명령줄 도구) 활용
- Ant CLI는 API를 감싼 형태로 Terraform 등 IaC(인프라 관리 도구)와 유사하게 작동
- 장기 운영 리소스(에이전트 등)는 YAML 포맷으로 코드베이스에 저장 가능
- 코드 변경 시, CI/CD 파이프라인에서 YAML 리소스 자동 업데이트·배포 가능
- 내/외부적으로 모두 동일 방식으로 장기 리소스 관리에 적용

### 커스텀 툴 대기 중에는 메시지 수신 차단 및 잘못된 메시지에는 400 에러 반환

- 에이전트가 커스텀 툴의 실행 결과를 기다리는 동안, 외부 메시지 전달이 불가
- 이 대기 중 메시지를 보내면 API에서 400 오류가 발생함(올바른 메시지 순서 보장)
- 커스텀 툴 외 작업 시에는 메시지 큐잉 가능하지만 대기 중에는 메시지 블로킹이 필수

### 워크샵 자료 및 가이드, 클라우드 컨퍼런스 콘텐츠가 실무 적용에 도움을 줌

- "코드 위드 클로드(Code with Claude)" 컨퍼런스를 비롯, 다양한 워크샵 자료와 예제들이 깃허브 저장소 및 유튜브에 공개됨
- 런던 행사(약 한 달 전)를 비롯한 여러 국제 컨퍼런스 발표 및 실습 코드별로 참고 가능
- 각 워크샵, 슬라이드 및 실습 자료는 readme 등을 통해 자가 학습 가능토록 설계

### 대규모 병렬 평가 세션 및 지속적 데이터셋 개선이 모델 품질관리에 핵심적임

- 신모델 공개 전, 광범위하게 병렬 세션(최대 1만 세션 이상) 동시 실행으로 다양한 평가 수행
- 데이터셋, 세션 이력, 프롬프트, 평가기준 등을 반복적으로 튜닝 및 개선
- "고품질 데이터"의 필요성을 강조, 잘못 정의된 평가는 의미 없는 100% 결과 발생 가능성 높음("Garbage In, Garbage Out")
- 기존 세션 결과 및 성능 데이터 등을 수집·분석, 자체 평가 데이터셋 구성 권장

### 조직 내 공유·접근 제어는 워크스페이스와 API 키 단위로 설계 및 세분화 가능

- 리소스(에이전트, 메모리, MCP 채널 등)는 "워크스페이스"에 귀속됨
- 동일 워크스페이스 내 API 키 보유자 모두 리소스 접근·수정 권한을 가질 수 있음
- 엔터프라이즈 환경에선 조직(Org)-워크스페이스-유저 그룹 단위로 접근 권한 설정 가능
- 세부적으로 일부 리소스만 부분 공유할 수는 없으나, 빌더가 통합 설계에서 세밀한 제어 가능

### 코드 리뷰 자동화 및 폭증하는 PR 검토의 주요 bottleneck을 CMA 및 하위 에이전트가 해소함

- PR(풀 리퀘스트)마다 PR별 병렬 세션 및 다중 하위 에이전트가 생성되어, 변경 코드 자동 리뷰 및 버그 탐지 가능
- CMA(Cloud Managed Agents)와의 통합으로 코드 품질을 유지하면서도 처리 시간·버그 발생을 감소시킴
- 내부적으로 자동화 덕분에 PR별 수작업·검토 시간이 크게 단축, 높은 품질 유지
- 무한 병렬화 시대에 새로운 코드 검토 및 배포 방식이 모색되고 있으며, 여전히 최적 솔루션은 발전 중임
- CI/CD 기반 자동 배포 환경, QA(품질보증) 에이전트, 샌드박스 실행 등을 통해 실제 코드 검증 병행 가능

### 다양한 리소스·컴퓨팅 요구 충족 위해 샌드박스 종류 및 외부 프로바이더 연동이 권장됨

- 에이전트별로 메모리, GPU 등 맞춤형 리소스가 필요할 경우 "셀프호스티드 샌드박스" 환경 이용
- Modal 등 GPU 제공 3rd-party 클라우드 프로바이더와 연동해 CI/CD, 에이전트 루프 운영 가능
- 공식 문서와 "cookbook"에 다양한 프로바이더(Modal, EB2, Daytona 등) 연동 가이드 존재
- Anthropic 제공 샌드박스는 스펙이 고정되어 있어, 별도 리소스 필요시 외부 제공자 활용 권장

### 강력한 멀티테넌시와 데이터 분리 기능으로 고객별 개별화·보안 요구 충족

- 엔터프라이즈 고객 지원 시, 고객별로 에이전트/워크스페이스/조직 단위 분리 가능
- 한 에이전트 정의를 여러 워크스페이스에 복제·동기화시키는 자동화 도구 제공
- 하나의 워크스페이스에 여러 고객 데이터를 저장하면 "메타데이터" 또는 세션 맵핑 등으로 구분 가능하나, 법적 데이터 분리가 필요하면 개별 워크스페이스로 운영 필수
- 고객ID, 세션ID 등 메타데이터로 에이전트-고객 간 맵핑 자동화 구축 가능
- 중요한 규제(데이터 분리 요구 등) 준수를 위해 워크스페이스 단위 완전 분리를 공식 권장

### 장시간 세션/에이전트 실행 시 이벤트 스트림과 커스텀 도구로 상태 관리가 용이함

- 수시간 이상 장기 실행 세션도 기본적으로 지속 실행 가능, "탈출 조건(exit criteria)"을 명시적으로 정의
- 체크포인트, 상태 모니터링은 콘솔 내 세션 탭, 이벤트 API 및 세션 이벤트 스트림에서 실시간 확인 지원
- Claude 에이전트가 정기 진행상황 보고를 하는 "업데이트 상태(커스텀 툴)" 등 자동화 기능 활용 가능

### 멀티플레이어 채팅 및 클라우드 태그 유사 기능은 스레드/세션/메모리 매핑으로 손쉽게 구현 가능

- 각 채팅 스레드(예: 슬랙 채널)별로 개별 에이전트 및 세션을 생성
- 사용자 메시지를 각 세션에 유니크하게 주입, 출처별로 맵핑 가능(사용자명 등)
- 에이전트가 각 세션에서 정보/메모리를 공유하게 하거나, 전용 도구(Slack post 등)로 직접 응답 지정 가능
- 각 에이전트는 각기 다른 채널·세션에 한정된 메모리 및 접근 권한 보유

### 메인 및 서브 에이전트 패턴으로 커스텀 툴 대기·비동기 운영의 융통성을 높임

- 메인 에이전트(코디네이터)와 여러 서브 에이전트 구성 가능
- 커스텀 툴이 필요한 작업을 하위 에이전트로 위임, 서브 에이전트가 별도 스레드에서 수행
- 이 구조에서 메인 에이전트가 유휴 때에도 서브 에이전트는 비동기로 계속 작업 가능
- 세션·스레드 매핑 체계가 명확하며, 커스텀 툴 이용 결과 처리도 구조적으로 분리
- 복수의 에이전트/스레드 간 역할 분담 및 데이터 흐름 체계가 명확하게 설계 가능
