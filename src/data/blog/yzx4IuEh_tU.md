## *SKILL.md의 70%는 이미 모델이 알고 있는 내용임* 핵심 요약

- 이 영상은 인텔의 Nikolay Petrov가 에이전트(AI Agent)의 능력 확장을 위한 ‘스킬(skill)’ 제작 및 평가 방법을 상세히 설명함
- 스킬은 모델에 새로운 지식이나 기능을 추가하는 것과 단순 작업 절차(steering, process)를 반복/재현/이식 가능하게 만드는 두 가지 유형으로 구분됨
- 실질적 성능 판단을 위해 ‘이볼브(evolves)’라는 과제를 정의하고, 스킬 미적용(3/5), 적용(5/5) 시의 과제 해결 수 등 주요 결과를 실험적으로 비교함
- 평가는 단순 성공/실패뿐 아니라 토큰 소모, 수행 시간 등의 추가 지표도 활용함
- 스킬이 모델에게 실제로 새로운 능력을 부여하는지 검증하기 위해, 각 스킬의 구성 요소(아이템)별 예상 Q&A를 생성, 판정관(다른 모델군, 패널)이 답변을 평가함
- 모델 스킬 이해도를 ① 스킬 없어도 답을 맞꿈(기존 지식), ② 스킬 추가시 성능 악화(부적절 설계), ③ 스킬로만 답 가능(신규 지식), ④ 둘 다 불가(스킬 불량)로 분류하여 시각화함
- 예시 실험에서 인기 스킬일수록 400개 중 1개 등 오류가 적고, 덜 알려진 스킬은 오류 비율이 높아 유지보수가 필요함
- 모델의 ‘일반 개념 이해’와 ‘구체적 세부사항 이해’(예: Opus에서 70%→22%)의 차이가 크며, 세밀한 정보 제공이 여전히 중요함을 강조함
- 최신, 대규모 모델일수록 더 높은 스킬 이해도를 보이나, 스킬별 이해도 차이도 뚜렷함
- ‘Docume’ 프레임워크를 활용해 스킬 최적화, 효과 검증, 문맥 영향 평가 등 체계적인 반복 실험과 결정을 지원함

## 세부 요약 - 주제별 정리

### 스킬 제작 과정은 반복 실험과 재현 가능한 기능화로 발전함

- 새로운 프롬프트와 에이전트 작업 실험을 반복하며 스킬의 기본 틀을 완성함
- 성공한 프롬프트 시퀀스를 모듈화하여 에이전트에 재사용 가능한 ‘스킬’로 패키징함
- 스킬은 단일 작업이 아닌, 일관성 있게 반복하거나 이식 가능한 기능 집합임
- 일부 스킬은 새로운 지식 또는 능력을 모델에 추가(예: 새 기능, 신규 개념 도입)
- 그 외 스킬은 프로세스 반복, 행동 흐름 유도 등 추가 정보 없이 실행 절차를 설계함
- GitHub 인기 스킬의 사례처럼, 스킬에 따라 확장성과 활용도가 다양함
- 본 세션의 주요 초점은 ‘새로운 지식’ 추가형 스킬 제작과 그 영향 평가임

### 스킬 효과 검증은 이볼브(evolve)라는 실험적 과제 해결로 측정함

- 이볼브는 에이전트가 해결해야 하는 실제 과제로, 스킬 성능을 객관적으로 평가하는 데 활용됨
- 평가 방식: ① 스킬 없이 실행, ② 스킬 적용 후 실행, 두 가지 실험군을 비교
- 예시: 5개의 이볼브 문제 중 스킬 미적용 시 3개 성공, 적용 시 5개 모두 완료
- 토큰 사용량, 처리 시간 등 부가적인 지표도 분석 가능
- 이런 반복 실험을 통해 스킬이 단순 ‘아이디어’ 수준이 아닌, 실제 동작하는 도구임을 증명함

### 스킬 최적화는 시행착오 대신 체계적인 검증 방법으로 발전됨

- 단순히 소스 코드 라인을 바꿔보는 ‘브루트 포스’식 시도가 아니라, 데이터 기반의 분석 필요성 제기
- ‘이용자 피드백’, 모델 버전별 성능 비교 등 다양한 접근법 언급
- 스킬 내 각 명령(아이템)을 질문-답변 쌍으로 쪼갠 뒤, 항목별로 영향력을 평가함
- 평균적으로 스킬 하나당 25~30개 아이템 추출 가능

### 판정관(모델 패널)으로 나온 질문-답변 실험이 스킬 영향력 측정의 핵심임

- 작성된 각 Q&A 항목에 대해, ① 스킬 미적용, ② 스킬 적용의 두 방식을 모델에 입력
- 모델의 답변을 자동 채점하거나, 다른 모델군 및 판정 패널이 평가
- 질문에 답이 노출되지 않게 설계해야 하며, Web Access 등 외부 도구 포함 여부에 따라 실용성 검토
- ‘정답 카운트 행렬’로 모델이 스킬을 통해 무엇을 새로 배웠는지, 이미 알고 있는지, 성능 저하가 발생하는지 등 시각화함

### 스킬별 영향은 ‘신규 지식 부여, 성능 저하 유발, 의미 없음’ 등 네 가지로 분류 가능함

- 1) 스킬 없어도 정답: 이미 모델이 알고 있음(중복)
- 2) 스킬로 성능 저하: 잘못 설계된 스킬로 기존 능력을 저해(드물게 발생)
- 3) 스킬로만 정답 가능: 실제 신규 지식 부여, 스킬 도입 효과 있음
- 4) 둘 다 불가능: 스킬 자체 품질 문제 또는 주제가 부적합
- 인기 스킬(예: Anthropic 관련 400개 아이템 중 1건 이슈)과 비인기 스킬의 오류 빈도 차이도 명시
- 성능 저하 구간은 즉시 수정·제거해야 할 항목임

### 시각적 mapping과 정량 비교(행, 단위별)는 스킬 품질 개선에 도움을 줌

- 각 스킬 아이템 별로 행 또는 문장 단위로 영향성을 색상 등으로 구분해 표시
- 신규 정보와 기존 데이터가 혼재된 부분을 쉽게 추출 및 최적화 가능

### 비용/실험 규모는 상대적으로 저렴하며, 다양한 엄격도 평가 방식이 있다

- 예시: 29개 스킬, 14달러 수준(Sonnet, Haiku 이용)으로 모든 평가 항목 처리
- 평가 방식은 ‘관대(lenient)’, ‘엄격(strict)’으로 나뉘며, 전자는 개념적 이해, 후자는 구체적 값/절차 등 세부사항 일치까지 요구함
- 예시: Opus 모델 기준, 일반적 이해는 70% 달성, 세부사항은 22%로 급감

### 대형/최신 모델일수록 더 높은 스킬 이해도를 보이나, 모든 스킬에 적용되지는 않음

- Sonnet 등 대규모 모델이 소규모 모델보다 전반적으로 스킬 이해도 높음
- 최신 모델일수록 더 많은 ‘기본 내용’을 이미 내장하고 있음
- 그러나 스킬별 이해 수준 차이 존재, 동일 모델 내에서도 신규 지식 추가 효용이 다름
- 스킬 최적화 실험은 다양한 모델, 버전, 스킬 유형에서 반복적으로 수행해야 유의미함

### 불필요한 중복(이미 알고 있는 내용) 제거로 토큰·컨텍스트 효율이 향상됨

- 스킬에서 이미 모델이 잘 아는 부분을 제거하고 실험한 결과, 성능이 유지된다면 스킬 크기를 줄여 효율 극대화 가능
- 단순 감에 의존하지 않고 실측 결과에 따라 스킬 유지·개선 결정

### ‘Docume’ 프레임워크로 반복적, 객관적 스킬 평가 및 최적화가 가능해짐

- Docume는 스킬, 에이전트 문서, MCP 도구 등 관련 맥락에서 성능 비교 및 평가를 지원
- 신규성 평가(노벨티), 이볼브 실험, 문맥 영향, 라우팅, 이름 및 설명 비교 등 다기능 분석 제공
- 이 프레임워크 덕분에 스킬 변경 또는 추가 전후의 영향을 객관적으로 측정, 불필요하거나 유해한 스킬을 배제 가능
- 효과적 스킬 작성과 지속적 개선에 필수적인 자동화 지원 도구임
