## *AI 에이전트를 안전하게 앱에 가입시키는 방법* 핵심 요약

- 영상의 주제는 AI 에이전트가 사용자의 앱에 안전하게 가입하고 작동할 수 있도록 하는 최신 인증 인프라와 개방형 프로토콜 활용법임
- 발표자는 WorkOS의 프로덕트 매니저 이자벨 윌리엄스이며, WorkOS가 인증 인프라를 제공하면서 3,000개 이상의 고객(대표적으로 OpenAI, Propel, Cursor 등)이 신뢰하고 있다고 소개
- 예제 앱 Waypoint(개인/기업 여행 플래너) 실사례와 Cursor 협업 실코드를 통해 논의를 전개하고, Muse, Instinct 등 개인 AI 에이전트의 성장에 따른 구조 변화에 주목함
- 핵심 문제는 '에이전트가 사용자의 앱 사용자로 시도해본 뒤 실제 사용자를 연결하는 방법'과 '에이전트 권한 및 액세스 관리, 감사/취소/제어의 보안성'임
- Off.md라는 오픈 프로토콜(markdown 기반)로 에이전트가 앱에 어떻게 계정 생성 및 인증을 수행할 수 있는지 명시하며, Waypoint 앱에서 엔드-투-엔드 데모 시연
- Off.md 상에서 익명 모드(에이전트가 제한된 기능으로 먼저 사용해보고, 나중에 사용자가 결과물을 청구해 소유권 이전)가 가능함
- 사용자가 수동 가입·코드 입력 없이, 에이전트 프로바이더(예: Claude)에서 인증된 신원 정보(ID Jag 토큰)로 자동 계정 생성 및 권한 부여되는 플로우 강조
- ID Jag(Identity Assertion Joined Authorization Grant)는 IETF 표준 프로토콜로, 에이전트가 앱에 안전하게 신원 증명을 전달하고, 앱은 그 내용을 검증·처리·권한 부여 결정
- 데모에서는 실제로 이메일 인증된 신원으로 Waygo(여행 앱) 계정을 자동 생성, 디너 예약까지 처리하며, 사용자는 별다른 액션 없이 결과물을 공유
- 기업 환경에서는 에이전트의 권한 남용/오용을 방지하기 위해 '에이전트 토큰 발급'과 세밀한 권한(스코프) 제한, 감사 및 철회 기능이 설계 핵심임

## 세부 요약 - 주제별 정리

### 발표자는 WorkOS 인프라와 Waypoint 앱 실예제로 에이전트 통합 문제를 풀고자 함

- 발표자 이자벨 윌리엄스는 WorkOS에서 인증(인증 인프라, Auth Infra) 관련 제품 관리자로 일함
- WorkOS는 3,000여 고객(대표적으로 OpenAI, Propel, Cursor 등)이 쓰고 있으며 앱, 에이전트, API 구축에 집중
- 발표에서 직접 라이브코딩한 'Waypoint'라는 여행 플래너 앱을 실전 사례로 활용
- Waypoint는 개인 및 회사 여행 플래닝 지원 앱임
- 최근 Muse, Instinct, Cursor 등 개인용 AI 에이전트의 부상으로 앱 사용 방식에 구조적 변화가 나타남을 지적

### 에이전트의 앱 사용 흐름과 기존 유저 온보딩의 차이에서 문제의식을 찾음

- 기존에는 인간 사용자가 앱 발견→회원가입→빠른 ‘aha’ 경험까지 직접 주도
- 이제는 사용자가 전체 탐색, 제품 발견, 초기 사용을 에이전트에게 위임
- 이에 따라 제품팀은 "에이전트가 우리 앱을 체험하고 회원 가입을 시도할 수 있도록 지원하는 방식"을 고민해야 함

### 에이전트의 행동을 진짜 유저와 연결하는 문제를 해결하는 플로우 제시함

- 에이전트가 앱에서 초기 탐색 및 일정 작업(예: 여행 계획)을 익명으로 진행
- 이후 실제 사용자가 결과물을 '청구(claim)'해 본인 계정으로 이전
- 이 플로우를 효율적으로 설계하며, 궁극적으로 앱의 실고객 확보와 연결

### Off.md 오픈 프로토콜로 에이전트 온보딩을 표준화함

- Off.md(markdown 파일)는 에이전트가 앱과 상호작용하는 접점(가입/로그인/유저 API 권한 관리 등) 규격을 정의
- 인간이 아니라 에이전트가 접근하는 파일임
- 에이전트가 오프.md를 읽고, 사용 가능 액세스 방식, 계정 생성, 이후 API 호출 방법 등을 파악
- Off.md는 액세스&운영방법만 명시할 뿐, 실제 인증정책/강제는 앱(예시: Waypoint) 단에서 동작

### 익명 액세스 흐름에서 사용자의 행위 소유권 전환 과정을 구체적으로 설명함

- 에이전트는 익명 상태로 앱 API 사용 및 데이터 생성
- 이 때 에이전트는 액세스 토큰(anonymous access)과 사용자 소유권 이전용 claim token을 발급받음
- 실제 사용자가 원할 때, 에이전트가 사용자에게 URL과 1회용 코드 제공
- 사용자는 앱에 로그인(회원가입), 코드 입력→현재까지의 작업(여행 계획 등)이 본인 계정으로 이전
- 그 후 OAuth 플로우를 통해 사용자 대신 에이전트가 앱 API 접근 가능하게 액세스 토큰 발급

### ‘인증된 신원 전달’을 통한 손쉬운 자동 가입 프로세스를 도입함

- 기존 플로우는 사용자 수동 입력·인증 과정이 많아 제품 성장(Product-Led Growth)에서 마찰 요인이 됨
- 예: Muse, Claude 등 최신 서비스는 이미 사용자의 신원을 알고 있음(예: 이메일 인증)
- 따라서, 에이전트 제공자가 이미 인증한 신원을 앱에 안전히 전달하면 사용자가 추가 조치 없이 즉시 온보딩 가능
- 이러한 목적을 위해 Off.md와 더불어 ID Jag라는 표준이 제시됨

### ID Jag(IETF 표준)는 에이전트가 안전하게 신원정보를 앱에 증명하도록 돕는다

- ID Jag: Identity Assertion Joined Authorization Grant
- IETF(국제 인터넷 표준화 기구)에서 규격화 진행 중
- 메커니즘:
    - 에이전트가 오프.md 통해 인증정보 요구사항 확인
    - 사용자의 동의(consent) 획득(예: 이름, 이메일 공유)
    - 에이전트가 에이전트 제공자(Claude, Anthropic 등)에서 신원 Assertions(ID Jag) 획득
    - 이 토큰을 앱의 인증 서버에 제출
    - 인증 서버는 서명/유효성/이메일 인증 여부 등 검증 후, 계정 생성·연동·API 권한 부여 등 결정
- ID Jag 내부 구조:
    - header: ID Jag 타입, 서명 알고리즘, 공개키 정보
    - payload: 발급자(에이전트 제공자), 유저(이름, 이메일, 이메일 인증여부), 대상앱(클라이언트ID), 만료시각
    - 토큰 전체가 발급자의 공개키로 서명됨
- 앱은 토큰 정보와 정책에 따라 계정 생성/연동/권한 부여 등 전적으로 제어 가능

### 실제 데모에서 신원 정보 기반 무인 계정 생성과 예약 처리 과정 시연

- 발표자는 직접 제작한 'Agent Harness'에서 Sam Rivera라는 사용자의 인증된 신원으로 Waygo 앱에 가입 시연
- 에이전트가 여행 일정 생성 도구 탐색(Waygo 등), 필요한 정보(이름, 인증된 이메일) 공유 권한 요청
- 사용자가 동의 시, Waygo에 자동 계정 생성 및 디너 예약 완료까지 전 과정을 무인(Hands-off)으로 처리
- 예약 장소(예: Quality Bistro)까지 자동 선정, 동료와 일정 공유 링크 생성 등 모든 과정이 사용자의 직접 참여 없이 진행됨

### 개방형 표준의 중요성을 강조하며 에이전트-서비스 생태계의 확장성을 강조함

- 신뢰·보안성 확보를 위해서는 Open Standard(개방형 표준) 위에서 에이전트-앱 통신, 결제, 가입 등 전과정 표준화가 필수임을 강조
- Off.md, ID Jag, MCP(Managed Client Protocol), Okta의 cross-app-access 등 실제로 여러 표준 논의가 진척 중

### 기업 환경에서 에이전트 권한 남용을 예방하기 위한 관리·제어 설계가 반드시 필요함

- 예시: Waypoint에서 기업 여행 및 자금 이체를 담당하는 '조던'이라는 페르소나 활용
- 조던은 회사 예산 승인 권한자이며, 앱 내부에 읽기 전용 에이전트와 자금 이동 에이전트 두 종류를 사용
- 읽기 전용 에이전트는 정보 조회만 가능, 자금 에이전트는 승인 범위 내에서 예산 이동 가능, 승인/예산 규칙은 수정 불가
- 조던의 계정/세션은 앱에서 식별되는 별도 '에이전트 토큰'으로 구분 발급

### 에이전트 토큰의 발급과 스코프 적용으로 권한 분리를 구현하고 감사/철회가 가능함을 시연함

- 앱이 발급하는 에이전트 토큰은 사용자 토큰과 분리, 권한/스코프 제한 가능(Blue Print 설계)
- 에이전트 토큰 구조: Subject는 에이전트 ID, acting user 정보, 실제 권한은 사용자 권한과 에이전트 청사진의 교집합
- 감사 가능(누가 무엇을 했는지 추적), 철회(개별 에이전트만 영향), 필요한 권한만 최소화 부여
- 데모에서는 실제 예산 교정 요청 및 예산 한도 내 자금 이동→에이전트의 권한 제한 사례, 승인/예산 변경은 오직 사용자만 가능

### 발표는 실제 적용 가능한 흐름과 오픈소스 표준 자료로 마무리함

- 주요 메시지로 ▲오프.md 기반 에이전트 온보딩 ▲ID Jag를 통한 신원 연결 ▲에이전트 별 권한 제어/감사/철회 설계의 중요성 등 강조
- Off.md와 WorkOS 에이전트 인증 토큰 등 실제 참고 가능한 자료(큐알코드) 제시하며 발표 종료
