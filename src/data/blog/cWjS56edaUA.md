## *대기업은 실제로 이렇게 AI 에이전트 앱을 배포한다: Oracle AI Agent Studio 활용법* 핵심 요약

- 이 영상은 AI 에이전트(Agentic AI)와 챗봇을 단순 적용하는 데 그치지 않고, 실제 기업 환경에 적합하게 “에이전트 기반 앱”(Agentic App)을 구축하는 실무적 방식을 소개함
- Oracle의 공식 정의에 따라, 에이전트 앱이란 AI 에이전트 자체가 아니라 “명확한 비즈니스 성과” 실현이 중심이 되는 방식으로 설계되는 앱임
- 실무적으로는 단일 대화형 AI Agent 서비스에서 벗어나, 다수의 에이전트와 다양한 컴포넌트가 내장된 통합형 앱을 구축하는 게 기업 수요에 적합함
- Oracle AI Agent Studio를 활용하면 이런 에이전트 기반 앱을 쉽고 체계적으로 생성할 수 있으며, 비즈니스 요구에 따라 복수의 워크플로와 보안, 컴포넌트 통합이 가능함
- 영상 예시(매니저 코칭 앱)에서는 팀 매니지먼트, 목표 관리, 추적, 자동화 이메일 발송 등 실제 업무를 위한 다층적 구조가 시연됨
- LLM(대형 언어모델)은 전체 워크플로 내 일부 모듈로 활용되어, 답변 신뢰성과 결정론적(Deterministic) 흐름, 통제권을 확보함
- RAG(Retrieval Augmented Generation)만 사용하는 기존 챗봇과 달리, 테스트된 코드 기반의 정책 적용 및 에이전트별 세분화된 권한 설계가 가능
- Oracle AI Agent Studio는 워크플로 설계, 입출력 포맷 관리, 보안정책 통합, 컴포넌트 시각화 등 엔터프라이즈 실무에 최적화된 기능을 지원함
- 단일 챗 인터페이스가 아닌, 대시보드 중심의 시각적 결과 출력·개입, 다기능 운영, 자동화 관리가 가능하여 생산성과 실무 경험을 크게 향상함
- 전체 메시지는 “AI 에이전트 활용의 핵심은 비즈니스 목적 중심의 앱 아키텍처 설계에 있다”는 점을 반복 강조함

## 세부 요약 - 주제별 정리

### 많은 개발자가 단일 챗봇형 AI 에이전트에만 집중해왔으나, 기업은 더 포괄적인 솔루션을 필요로 함

- 영상 초반, 제작자는 올해 개인용 AI 에이전트(예: ‘세컨드 브레인’, 코딩 어시스턴트, 고객지원) 개발에 집중했다 밝힘
- 대부분 ‘하나의 에이전트’와 간단한 챗 인터페이스, 단방향 응답 구조로 사용됨
- 단일 챗봇이 비즈니스의 많은 부분을 자동화하지만, 대규모 조직에서는 이보다 넓고 체계적인 접근이 필요
- 최근 AI 붐으로 ‘에이전트를 곧 솔루션 자체’로 여기는 경향 많으나, 대부분은 에이전트를 하나의 컴포넌트로 쓰길 원함
- 즉, “에이전트 앱(Agentic App)”이 필요하다며 Oracle의 정의를 인용

### 에이전트 앱은 AI 에이전트가 아니라 명확한 비즈니스 결과 중심으로 설계되어야 함

- Oracle의 정의에 따르면, 에이전트 앱은 “에이전트가 무엇을 자동화하는가”가 아닌 “비즈니스 결과(업무 성과) 창출”에서 출발함
- 실제 비즈니스 문제(예: 팀 관리, 우선순위 결정 등)를 해결하는 데 초점을 맞춘 경험 제공이 핵심
- 그 후에 실제로 도움이 되는 프로세스에 여러 AI 에이전트를 통합
- 이렇게 해야 기업에 실질적 가치를 제공할 확률이 높으며, 단순한 신기술 적용에 그치지 않음
- 에이전트가 전체 앱을 통제하는 구조가 아니라, 에이전트는 목표 중심 워크플로 내에서 ‘도구’로 동작토록 설계

### Oracle AI Agent Studio는 에이전트 앱 개발을 위한 실습적 플랫폼을 제공함

- 영상 전반에서 Oracle AI Agent Studio를 예시로 활용하며, 개발 과정 전체를 시연함
- 사용자는 “내가 만들고 싶은 실제 업무 애플리케이션”을 자연어로 설명하면, Studio가 기본 구조를 자동 생성
- 예시: “매니저 코칭 앱”을 설계한다고 제시(약 12명 팀을 관리하는 관리자를 위한 역량 개발, 현황 대시보드)
- Studio에서는 이런 앱을 바로 생성할 수 있으며, 이 구조 내 다양한 컴포넌트가 워크플로와 에이전트를 호출

### 하나의 에이전트 챗봇이 아닌, 다중 컴포넌트·백엔드 에이전트·워크플로 통합 구조를 지원함

- 생성된 앱에는 ‘전체 구성원 목표 추적’, ‘목표 미달자 자동 이메일 작성/발송’ 등 다양한 컴포넌트가 존재
- 차트, 대시보드 내 위치한 여러 컴포넌트마다 관련 에이전트 및 워크플로가 배치됨
- 예시로, 목표 미달자 대상 맞춤 이메일 초안 자동 생성 → 사용자가 대시보드 내 직접 편집/발송 가능
- 각 컴포넌트 하단에는 챗 응답뿐만 아니라 시각적 결과(표, 제안 등), 다음 액션 제안이 즉시 노출됨
- 백엔드에는 각종 “다음 단계 권고” 기능이 내재해 사용자에게 우선순위 관리를 지원

### LLM의 획기적 성과에도 불구, 워크플로 기반 구조가 기업 환경에선 반드시 필요함

- Oracle AI Agent Studio 내 각 에이전트 컴포넌트는 LLM 호출이 ‘전체 워크플로의 일부’로만 동작하도록 설계
- 대형 언어모델(LLM)은 유연/강력하지만, 신뢰성과 통제력·결정론적 흐름(Determinism)을 희생할 수 있음
- 워크플로(조건문, 코드노드 등) 내 LLM 사용 → 더 많은 컨트롤과 일관된 결과, 예측 가능한 동작 확보
- 특히 기업에서는 “작은 실수도 치명적”이라, 워크플로 내 컨텍스트, 모델 선택, 포맷 제한 등 엄격하게 규정해야 함
- 개인 개발에도 open-source 프레임워크 ‘Arcan’ 등에서 유사한 결정론적 워크플로 설계 사례를 언급

### 앱별 워크플로와 컴포넌트는 맞춤 자동화, 상세 보안 정책, 사용자별 권한 통제가 가능함

- Oracle AI Agent Studio에서는 “정책(Policy)” 개념을 도입, 워크플로에 정밀 권한/기능 부여 가능
- 예시: HR(인사) 매뉴얼 내 정책 PDF 업로드 → 해당 문서를 함수화/코드화하여 API/에이전트 기능 제공
- 각 함수는 소스코드, 테스트케이스, 입력조건 정의 → 인풋에 따라 필요한 정책 변환 자동 생성
- 워크플로에 이런 정책을 삽입, ‘RAG(정보검색+생성)’만 사용하는 것과 달리 100% 신뢰성 확보
- RAG 기반 답변은 “일반적으로는 맞지만, 인사정책 등에서는 충분치 않음” 명시

### 워크플로 설계와 테스트가 쉬우며, 다양한 자동화 트리거 및 컴포넌트 통합을 지원함

- Studio 내에서 워크플로 실행 전 다양한 맥락 추가(분류, 정책 제공 등), JSON 등 다양한 데이터 출력 실시간 확인
- 각 워크플로 실행 권한, 트리거 조건, 자동화 주체의 신원까지 세분화로 통제 가능
- 대시보드 UI 외에도, 이메일 등 실시간 이벤트 발생을 통한 자동화 트리거 설정이 자유
- “앱은 단순 인터페이스에 불과, 핵심은 워크플로·자동화·상태 업데이트 등”을 강조

### UI/UX 측면에서 단순 챗 응답 대신, 시각적 산출물/대시보드가 생산성을 월등히 높임

- 대시보드 기반 다양한 컴포넌트와 결과물이 시각적으로 한눈에 제공
- 예: 학습 리스크 요약 등은 PDF로 정리되어 제공, 복잡한 내용을 빠르게 파악 가능
- 단순 텍스트 챗 응답만 반복시 정신적 부담 상승 → 시각적/구조적 결과물이 실무에 필수적임
- 본인도 발표 때마다 시각/다이어그램 아웃풋을 활용하는 이유를 설명

### Oracle AI Agent Studio는 비개발자도 손쉽게 에이전트 앱을 구축하도록 설계되어 있음

- 프로그래밍 경험이 없어도 Studio 내 워크플로·컴포넌트 설계를 매끄럽게 할 수 있음
- 전문 개발자의 경우, 이후 영상 예고(Visual Studio Code 등에서 코딩 에이전트 활용법)
- Oracle AI Agent Studio는 엔터프라이즈 중심 애플리케이션 생성을 체계적·효율적으로 지원

### 영상 전체의 결론은 “에이전트 기반 앱도 결국 비즈니스 목표 중심 아키텍처와 운영이 핵심”임

- Oracle의 에이전트 앱 정의, 비즈니스 성과 중심 설계, 실무 적용 과정 중심이 반복 강조됨
- AI 에이전트 자체가 목적이 아니라 업무 전반의 문제 해결·성과 향상 수단임을 명확히 함
- 영상은 Oracle AI Agent Studio에서 배울 점 및 AI 자동화의 실무 구조적 혁신에 집중함
