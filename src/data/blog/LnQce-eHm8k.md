## *당신의 AI 에이전트는 당신의 데이터를 원한다 – 데이터를 잠그는 법 (Oracle의 Jeff Smith)* 핵심 요약

- Oracle의 Jeff Smith는 AI 활용 시대에 조직 데이터 보안을 강화하는 방법과, 오라클 데이터베이스의 최신 AI 지원 기능 및 MCP(Managed Control Protocol) 통합에 대해 소개함.
- 오라클 데이터베이스는 기존의 관계형 테이블 외에도, 벡터 검색, 그래프 데이터, 데이터 레이크 등 다양한 데이터 타입과 워크로드를 네이티브로 지원하여 최신 AI 및 RAG(검색-보강 생성) 파이프라인을 구현 가능하게 함.
- 데이터 활용 및 자연어→SQL 변환은 폭발적으로 증가하나, 비전문가가 작성한 쿼리의 위험성(Large Language Model이 잘못된 SQL 생성, 데이터 유출 등)이 꾸준히 제기됨.
- MCP와 오라클의 데이터/리포트 관리 기능을 연동해, 에이전트에게 미리 정의된 보고서, 입력값, 설명 등을 API로 제공함으로써 LLM이 직접 SQL을 생성하지 않고도 안전하게 데이터 결과를 얻는 방안을 제시함.
- 오라클 Data Guard와 같은 읽기 전용 백업 복제 환경에서 LLM이나 에이전트가 안전하게 운영DB 성능분석·튜닝도구를 활용할 수 있도록 지원함(제한된 권한·상황에서만 접근 가능).
- 데이터베이스 수준에서의 레이어 보안 설정(역할, 권한)과 SSO(Azure AD 등) 기반 인증을 연계해, 조직 내 개별 사용자마다 데이터 접근 권한을 엄격히 다르게 통제 가능함(Deep Data Security).
- 기존 BI Publisher나 엑셀, Confluence, SharePoint 등 온갖 사내 데이터/보고서/문서 자산을 MCP로 구조화, 요약, 인덱싱하여 재사용성을 극대화함.
- RAG 파이프라인, 데이터 문서화, 스키마 자동주석, 자연어-쿼리 변환, 추출 요약 등 업무 자동화 도구군이 MCP 기반으로 하나의 API 인터페이스 아래 통합됨.
- 오라클은 AI 시대의 데이터 리스크에 대응해 매달 새로운 기능을 지속적으로 릴리즈하고 있으며, 엔터프라이즈는 신기술 연결 전 “보안에서부터 출발”해야 함을 강조함.
- MCP 기반 오라클 데이터베이스 보안 및 에이전트 도입, 실제 현업 활용 사례, 기술 로드맵, 커뮤니티 지원 등의 최신 정보를 공유함.

## 세부 요약 - 주제별 정리

### 오라클 데이터베이스는 AI 시대 요구에 맞춰 벡터 및 다양한 데이터 워크로드를 네이티브로 지원함

- 오라클의 설립 연도(Star Wars 영화 개봉과 같은 1977년)를 언급하며, 사내외에서 가장 많이 받는 질문이 “오라클의 AI 데이터베이스란 무엇인가?”임을 강조함.
- 오라클 DB는 최근 몇 년 새 전통적 관계형 테이블뿐 아니라 벡터 기반 데이터, 그래프, 데이터 레이크, 바이오, 물류, 제조, 공공/금융/HR/ERP 등 다양한 도메인 데이터를 네이티브하게 지원한다고 설명함.
- 모든 데이터는 SQL API 단일 인터페이스 아래 접근되어, 다중 플랫폼에 데이터를 복제하지 않고도 RAG 파이프라인, 분석 요청 등을 바로 실행할 수 있음.
- 데이터 내장형 벡터 인덱싱을 지원, 데이터베이스 자체에서 AI 검색(예: 벡터 RAG, 그래프 RAG) 처리 가능.
- 데이터 구조(스키마)와 다양한 데이터 타입 지원은 오라클이 “회사가 오래됐다”는 평과 관계없이, 꾸준히 혁신하고 있음을 보여주는 예로 제시됨.

### MCP(Managed Control Protocol)와 오라클 데이터베이스의 통합으로 AI 에이전트의 안전한 데이터 접근을 실현함

- MCP 프로토콜은 2023년 7월에 초기 사양이 공개되었으며, 오라클은 이 사양을 빠르게 반영하여 통합하고 있음.
- MCP를 이용해 AI 에이전트와 데이터베이스를 연결, 실제 업무에 적용할 수 있는 다양한 사례(DevOps, 데이터분석, 자동화 등)를 소개함.
- 에이전트가 데이터베이스와 통신할 때 사용한 명령, 리포트, 입력값, API 인터페이스 등은 모두 통제 가능함.
- LLM의 자연어→SQL 생성의 위험성과 불확실성을 줄이기 위해, 공식적으로 검증된 ‘리포트 리스트/실행’ 인터페이스를 도입함.

### 자연어→SQL자동변환은 혁신적이지만, LLM 기반 쿼리 작성에는 실제적 위험성이 따름

- 자연어 처리와 SQL 쿼리 자동 생성에 대한 업계의 열광 분위기와, 그 이면에 있는 데이터 품질·보안 리스크를 자세히 짚음.
- LLM이 실제로 “원하는 쿼리”가 아니라 “겉보기 그럴듯한 쿼리”를 생성해, 데이터의 잘못된 해석·결정이 이루어질 우려가 큼.
- 예: Codex, Claude, Gemini 등에 쿼리 생성·실행을 일임하는 것은 기업 데이터의 의사결정에 매우 위험할 수 있음을 밝힘.
- 시스템 오용, 데이터 유출의 가능성뿐만 아니라 토큰 소모량, 비용 과다, 느린 속도 문제도 동반됨.

### 사내 존재하던 다양한 BI/문서/엑셀 자산을 리포트-기반 구조로 MCP를 통해 API화하여 재활용함

- 전통적으로 임원, 부서장 등 의사결정자는 “지난달 판매량?” 등 반복성 큰 질문을 여러 비즈니스 인텔리전스(BI) 툴로 파견한 뒤, 대량의 엑셀과 피벗, 요약표로 보고서를 생성해 왔음.
- 이 과정은 비SQL 전문가가 “업무 질문→데이터 추출→결정”까지 직접 해야 하고, 항상 시간과 리소스가 부족함.
- 사내에 이미 방대한 SharePoint, 네트워크 드라이브, Excel, 기존 보고서 등이 축적되어 있는데, MCP를 통해 이 리포트들을 구조화, 카탈로그화하여 API 형태로 에이전트가 직접 질의할 수 있도록 함.
- 각 리포트에는 설명, 입력값, 예시 질문, 권한 정보 등이 포함되기 때문에, LLM이 오작동하여 SQL을 잘못 생성할 위험이 줄어듦.

### MCP 기반 리포트 API는 SQL 기반 대신 안전하고 신뢰할 수 있는 질의 경로를 제공함

- ‘리포트 리스트’/‘리포트 실행’ 등 기본 MCP 도구를 통해 수백 개의 기업 보고서를 한 번에 다루되, 쿼리·코드의 일회성 폭발을 방지함.
- 질문-키워드와 연동한 동적 리포트 탐색, 선택, 실행 절차를 통해 자연어→SQL 변환보다 안전하고 예측 가능한 인풋/아웃풋 관리가 가능함.
- 필요시, 내부적으로 인증된 사람만 리포트의 실제 SQL 쿼리 코드도 볼 수 있게 하여, LLM의 데이터 권한·스키마 이해도를 강화함.
- 이 방식은 다양한 AI Framework이나 언어모델(Claude, Codex 등)과 영향을 받지 않고 MCP와 도구만 구비되면 범용적으로 적용됨.

### DevOps 및 운영팀 대상, 안전한 환경에서 LLM·에이전트 활용으로 운영 효율을 극대화함

- 오라클 Data Guard 등 기술을 활용하여 운영DB와 동일한 읽기 전용 환경에서 LLM이 성능 분석·보고·튜닝을 시도할 수 있도록 함(운영환경이 아닌 복제본/테스트 환경 활용 권고).
- 데이터베이스 보안 정책(역할 기반 접근 등)을 DB Layer 내에 탑재, 에이전트가 읽기 권한만 갖고 접근하더라도 특정 정보는 노출을 제한할 수 있게 설정.
- MCP 커스텀 도구 예시: 6개의 승인 명령만 허락, 그 중 하나가 Cost-Based Optimizer의 통계수집 등 데이터베이스 최적화 패턴 실행.
- 단일 DB 내 여러 업무도구/자동화도구를 MCP 인턴페이스(AWR리포트 생성, 통계수집, 성능분석 등)로 배포 가능.

### 자연어→SQL 과정에서 고민되는 컨텍스트(스키마, 업무용어, 실행 예시) 자동화가 중요해짐

- 새직원이 입사했을 때 낯선 데이터 모델, 명명규칙, 복잡한 업무개념 등에 익숙해지기 어려움. (예: 매출 테이블 이름이 XHR_123 등 직관적이지 않을 수 있음)
- Confluence, 공유폴더 등 각종 문서의 컨텍스트 정보를 오라클 DB의 스키마 주석, 엔티티 관계, 데이터 사전 등과 통합해 쉽게 접근할 수 있도록 ‘스키마 정보’, ‘AI용 컨텍스트 도구’ 등을 제작함.
- LLM 에이전트가 수동으로 무차별 데이터 스캔·조합하지 않고, 관리자·개발자가 직접 제출한 명확한 데이터 컨텍스트를 사용하도록 유도함.
- 이 정보는 자연어 이해에 친화적이고 지속적으로 갱신 가능하여, 인력 이탈·지식 누수도 방지됨.
- ‘스키마 정보’, ‘컨텍스트 검색’, ‘주석 생성’ 등 MCP 기반 도구로 데이터 설명, 예시, 연결관계 등을 JSON 등 명확한 구조로 에이전트에 전달할 수 있음.

### 비정형 문서/외부 데이터까지 자동화 도구(MCP)로 흡수·구조화하여 일관된 데이터 거버넌스를 실현함

- SharePoint, PDF, PowerPoint, Word, Excel 등의 비정형 데이터도 MCP 도구로 일괄 크롤링, 변환·요약·정리하여 데이터베이스에 구조화시킬 수 있음.
- 추출된 데이터와 설명, 주석, 요약문 등도 각 테이블에 함께 저장하여 일관된 검색성과 재활용성 제공.
- Strava API 등 외부 시스템의 데이터도 일단 정형화·주석화해두면 에이전트가 운동 기록 분석, 추천 등 복합적 활용 가능.
- 도메인 불문, 언어모델에 종속되지 않은 장점(MCP 및 오라클DB 기능만 갖추면 RAG, 검색, 요약 등 가능)을 반복 강조함.

### 데이터베이스 레이어에 구축된 보안 및 인증 체계로 사용자별 데이터 접근 권한을 동적으로 엄격히 제어함

- 에이전트·LLM이 데이터베이스에 접근 시, SSO(Azure AD 등)를 통해 실제 직무(Role, Scope)가 반영된 인증을 받고, 데이터베이스가 동적으로 데이터 노출 범위를 컨트롤함.
- 예: HR 매니저는 모든 직원의 급여 데이터 접근 가능, 타직원은 불가능 등 권한별로 데이터 필터링 자동적용.
- 자연어→SQL 변환, 쿼리 실행, 보고서 실행 등 모든 요청에 대해 DB단에서 민감 데이터 자동검열로 Deep Data Security 구현.
- 일회성 프로그램, 신규 툴 도입 모두 안전하지 않으므로 DB Layer(오라클 내부)에서 보안 정책을 적용해야 함을 재차 강조함.

### 최신 MCP/AI 기능 및 보안 강화를 바탕으로 엔터프라이즈 데이터 활용의 생산성 극대화와 리스크 최소화가 가능함

- 오라클은 매월 새로운 기능(도구, 스키마 자동 주석, AI용 컨텍스트, RAG 파이프라인, 문서 자동화 등)을 출시하고 있음.
- MCP API, GUI, 커맨드라인 등 다양한 인터페이스를 통한 RAG 및 데이터 자동화 구현이 가능하고, 전문 커뮤니티 및 공식 문서(oracle.com/mcp)에서 기술 지원을 강화함.
- 향후 GUI 기반 데이터베이스 인터페이스가 MCP 연동 스마트에이전트에서 제공될 예정이며, ‘스킬’ 형태의 자동화도구 배포·적용도 지원 예정임.
- Oracle 부스, LinkedIn 등에서 현장 커뮤니티, 데모, 추가 자료를 상시 제공함.
